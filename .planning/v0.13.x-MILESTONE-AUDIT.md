### Seam 1 — exit-code taxonomy holds across the new command tree

This was the milestone's stated regression risk: #467 exists because cobra's
`MarkFlagsMutuallyExclusive` raises a plain `fmt.Errorf` that bypasses `cliError`/`ExitCode()`,
so a new command tree is exactly where the undocumented exit-code split would reappear. It did
not. Every `spine-review` error path routes through `usageErrorf` /`classifyOperatorErr` /
`classifyOperatorErrConstruction` (`cmd/engram/operror.go:68,174`), all returning `*cliError`
carrying `ExitCode()`. No bare `fmt.Errorf` on any `spine-review` `RunE` path.

### Seam 3 — the `--help` pin is non-vacuous by construction

The goldens are generated by walking the **live** cobra tree
(`cmd/engram/golden_test.go` `TestHelpGolden`/`TestCatalogGolden` via `buildHelpGoldenContent`),
not from a hand-maintained command list. All six `spine-review` subcommands plus `--output` and
the `--fail-on`/exit-code-3 documentation appear in `testdata/help.golden:195-325` and
`testdata/catalog.golden:504-965`. A pin that cannot silently go partial as commands are added
is a real gate, not a false green.

### Seam 5 — the milestone's headline flow traces end to end

`consolidatePairDoc` (`cmd/engram/spine_review_consolidate.go:139-147`) emits `a`, `b`,
`a_short_id`, `b_short_id`, `a_scope`, `b_scope`, `score`; the skill
(`skill/engram/skills/curating-spine/SKILL.md:68-70`) instructs the agent to run
`engram spine-review consolidate --output json` and consumes those exact field names. Both
`same-fact` and `overlapping` verdicts route through `supersede_memory` with `supersedes` naming
every target — matching the real multi-target arg shape at `internal/server/tools.go:613` — and
the skill states there is no `delete_memory` in the merge path, matching
`toolclass.go:139-147`'s `Destructive: false`. Verify's four tiers named in the skill's staleness
section match `spine_review_verify.go:38-42` verbatim.

### Seam 7 — preview-default uniformity is correct-by-classification

`registerDestructive` is used by exactly three commands: `migrate-remap-owner`
(`cmd/engram/migrate.go:257`), `prune-expired` (`prune.go:159`), and `spine-review purge`
(`spine_review_purge.go:425`). `reindex`, `summarize-missing`, and `backfill-short-ids` carry no
`--apply` at all — verified correct, not a gap: `internal/surfaces/toolclass.go:163-199`
classifies all three `Destructive: false` (additive or idempotent-overwrite). The uniformity
property holds at the classification level, which is the property that matters.

### ⚠ Warning — stale rationale comment contradicts the shipped Phase 03.1 contract

`internal/surfaces/toolclass.go:141-142` justifies `supersede_memory`'s `Idempotent: true`

> Idempotent: true — NOT via an idempotency_key (this verb explicitly supports none), but

`internal/server/tools.go:594` states the opposite:

rationale comment is stale, sitting in the registry a future maintainer would treat as ground
truth for why the annotation reads as it does. One-line fix; not a blocker.

## Verdict

The milestone achieved its definition of done. Both classes v0.12.x left to human diligence are
closed: `engram spine-review` plus the `curating-spine` skill make the spine maintainable without
hand-curation, and the conditional-rule registry, conformance gate, MCP annotations, and pinned
`--help` make the interface correct-by-reading. The headline `consolidate → supersede → consent`
flow traces end to end, and the exit-code taxonomy survived contact with a whole new command tree
— the specific regression #467 was unified to prevent.

Status is `tech_debt` rather than `passed` for two reasons, neither an integration blocker:

1. `REQ-consent-adversarial-proof` is genuinely unmet. The honest thing about this milestone is
   that it did not convert a non-result into a green checkbox — the unmet requirement is visible
   in five artifacts and contradicted by none.
2. The planning artifacts have drifted from the work they describe. Three of the four bookkeeping
   defects would make the milestone look *smaller* than it is, and the Progress-row corruption
   would make two completed phases read as never started.
