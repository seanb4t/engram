### B01: AGENTS.md loss after read failure — blocker

At `internal/skills/install.go:152–155`, any index read error becomes empty input.
At `188–193`, a later successful whole-file write replaces the existing guidance
and reports success. A fake filesystem seeded with user guidance, returning
`os.ErrPermission` on read but allowing writes, reproduced
`outside_bytes_lost=true`, `report_error=<nil>`. The success report also hides
that loss from setup's otherwise connected outcome aggregation.

[#559](https://github.com/seanb4t/engram/issues/559) owns the fix: only confirmed
nonexistence starts a new index. Other errors must preserve the file and report
failure while retaining independent skill-file progress. Regressions must verify
no index write on permission/transient errors and propagation through setup's
row/exit classification. No accepted decision waives preservation here.

### W01: timeout error semantics — warning

At `internal/setup/environment.go:94–100`, an `exec.ExitError` from a deadline-killed
process becomes exit -1 and nil error, bypassing the executor's context-error path.
The actual adapter with a 50ms context and `/bin/sleep 5` reproduced that mismatch.
The process is killed; this is not an unbounded-wait defect. A first probe may
still be treated as an ordinary nonzero probe and permit apply to proceed.
[#560](https://github.com/seanb4t/engram/issues/560) tracks context-error precedence
and adapter-to-executor regression coverage.
