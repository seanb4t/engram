never wires it."* It recorded `rg -i 'cross.spine|CrossSpine|searched_scopes' cmd/engram/`
returning **zero** hits.

Re-run 2026-08-02: **113 hits**. Traced end to end rather than grepped:

| Link | Evidence |
|---|---|
| Flag | `client_search.go:84`, `client_list.go:95` — `--cross-spine` on both commands |
| Guard | `client_common.go:234` `validateScopeCrossSpine` — fires pre-dial |

## Tech debt

**1. Two-tier CLI error model, undocumented.** Phase 7's client-side `validateScopeCrossSpine`
returns plain `usageErrorf` text with exit 2 (`client_common.go:216`), not Phase 4's
`field=<name> hint=<code>: <text>` envelope (`internal/server/argerror.go:79`). This is correct
scoping — REQ-validation-error-attribution covers server-side `ArgError` on the wire, and CLI
pre-flight usage errors follow the older exit-code convention — but **no REQ or CONTEXT.md
decision ID records the exemption**. An agent parsing CLI stderr for `hint=` codes to self-correct
will not find one on this path. Worth a short decision note so a future agent does not "fix" it
into false consistency.
