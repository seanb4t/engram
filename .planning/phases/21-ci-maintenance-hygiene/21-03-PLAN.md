<scope_corrections>
Four corrections that override earlier artifacts. Each exists because an executor following the
superseded text would ship a real defect.

### 1. D-03's permission assumption is WRONG — do NOT add `contents: write` (RESEARCH.md Pitfall 2)

D-03 says "write is granted at the `ui-drift` job level only." **Research disproved this.** The
self-heal push must NOT use `GITHUB_TOKEN` at all — that is precisely the token whose pushes fail to
re-trigger checks. It uses a separately-minted GitHub App installation token, whose write capability
comes from the App's own installation permissions and is **completely independent of the workflow's
`permissions:` block**.

Proof in this exact repo: `release.yaml`'s `release` job declares only
`permissions: contents: read, packages: write` — no `contents: write` — yet pushes tags and releases
via its App token. The job `permissions:` block never constrained it.

Therefore: **leave `ci.yaml`'s repo-wide `permissions: contents: read` (lines 9-10) completely
untouched, and add NO job-level `permissions:` block to `ui-drift`.** Adding one would escalate the
ambient `GITHUB_TOKEN` on every run of the job — including every human PR — for a capability the App
token already provides. That violates D-03's least-privilege intent rather than serving it. Do not
"helpfully" re-add it. `commit-lint`'s job-level `permissions:` block (ci.yaml:214) is the in-repo
precedent for a *different* problem (granting `GITHUB_TOKEN` a read capability) — recognize the
pattern and correctly do NOT apply it here.

### 2. RESEARCH.md's sketch has a merge-ref bug — do NOT copy its push line verbatim

RESEARCH.md §"Code Examples" ends its self-heal step with
`git push <url> HEAD:"${{ github.head_ref }}"` from the default checkout. **That is wrong and would
corrupt the Renovate branch.** On a `pull_request` event, `actions/checkout` checks out
`refs/pull/N/merge` — a **merge commit of the PR head into base**, in detached HEAD. Pushing that
`HEAD` to the Renovate branch would push a commit whose parent is the base-merge, silently merging
`main` into the Renovate branch.

You MUST commit against the true branch tip, not the merge ref. Recommended resolution (the
executor may substitute an equivalent that provably commits onto the PR head): inside the guarded
self-heal step, shallow-clone the PR head branch to a scratch directory using the App token, copy
the already-built SPA output into it, and commit + push from there. This reuses the build the job
already did, needs no change to the existing checkout step (so the drift check's semantics stay
identical for every other PR), and is trivially reviewable.

Do NOT solve this by changing the job's checkout `ref` — that would change drift-detection semantics
for every PR in the repo (checking the head instead of the merge result), a scope increase this
phase has no mandate for.

### 3. Never `--amend` (RESEARCH.md Pitfall 3)

Always create a **fresh commit**. Renovate explicitly rebases over an amended commit and would
discard the fix. A new commit instead triggers Renovate's separate, unconditional "a third party
pushed to my branch → stop managing it" rule, which is the behavior this design wants.

### 4. No `renovate.json` change (D-02, RESEARCH.md Pitfall 4)

Keep the inert `postUpgradeTasks` rule (belt-and-suspenders: if the homelab bot is ever fixed it wins
first, CI then finds no drift and does nothing). Do **not** add `rebaseWhen` — the "stop on edit" rule
is a separate unconditional guard that fires before `rebaseWhen` logic is consulted, and
`config:best-practices` does not set it. `.github/renovate.json` is not in this plan's
`files_modified` for exactly this reason.
</scope_corrections>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| fork PR author → `ui-drift` job | **The critical boundary.** A fork PR is authored by an untrusted party, yet its metadata (`github.actor`, `github.head_ref`, branch name) populates the workflow context. If a fork PR reached the App-token mint step, an attacker would obtain a `Contents: write` token for this repo. |
| Renovate bot (self-hosted, homelab) → PR branch | Semi-trusted automation outside this repo's control. Its output (the `ui/` dependency bump) is what the self-heal step rebuilds and commits. |
| `ui/` npm dependency tree → committed `internal/webauth/static/` | The SPA build's output is committed by CI without human review on the self-heal path. |
| GitHub App private key → repo secret store | A leaked key grants whatever the App's installation permits, for as long as the App exists. |
