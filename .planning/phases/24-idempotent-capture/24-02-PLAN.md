<objective>
Wire the Wave-1 primitives into the shared write path: add the optional `idempotency_key` arg,
document the contract on both MCP tool surfaces (D-11), and branch `store_memory`/`schedule_memory`
through a shared `checkIdempotentReplay` that resolves the deterministic ID and does a check-before-
embed Get — returning the original record on a fingerprint match, rejecting on a mismatch, and
falling through to today's embed->persistAndEnqueue tail (with the deterministic ID + stamped
fingerprint) when absent. Prove all five success criteria, including the `-race` no-duplicate
concurrency invariant and the two-owner matrix.

Purpose: This is the behavioral heart of REQ-idempotent-capture — the point at which a repeat
store_memory becomes safely re-runnable. It composes Plan 01's pure primitives; no new derivation
or fingerprint logic is invented here.

Output: `storeArgs.IdempotencyKey`, `checkIdempotentReplay`, the keyed branch in both handlers,
updated tool descriptions, and the SC1-SC5 test matrix.
</objective>
