<objective>
Map `store.ErrResponseTooLarge` once per server lane at each lane's existing chokepoint, with ONE shared
envelope: `field=response hint=too_large: <detail>` (D-04). The Connect lane gains one `connectError` arm
returning `connect.CodeResourceExhausted` — never `CodeInternal` — after logging the raw error server-side
(D-06). The MCP lane gains its first error mapper: a receiving middleware on `tools/call` that reads the
handler's original error through go-sdk v1.8.0's `CallToolResult.GetError()`, rewrites only the
text content for this sentinel, keeps `IsError` true, and logs the raw error exactly once (D-08). Every
other MCP error passes through unchanged (D-09). The vocabulary gains its 11th code, `too_large` (D-05),
and `argError.Error()`'s string-building is extracted into `renderHintEnvelope` so both lanes and
`argError` share one renderer without ever building an `*argError` for this sentinel (D-04, RESEARCH
Pattern 3 and its Anti-Patterns).

D-05 verification (ROADMAP note, checked at planning time): `internal/surfaces` declares conditional-rule
SENTENCES only — `surfaces.ConditionalRule.Hint` is a plain string that references the vocabulary, and no
surfaces type declares the vocabulary itself. The hint vocabulary's single declaration is
`internal/server/argerror.go`'s `HintCode` const block, so the surfaces single-declaration pattern does not
apply unmodified. Plan 02-03 closes the remaining transcription gap (docs-site `reference/errors.md`) with a
mechanical gate instead.

Facts this plan relies on (verified at planning time against the pinned sources, RESEARCH Pattern 4 and
Pitfall 3): go-sdk v1.8.0's typed `AddTool` wrapper turns an ordinary handler error into
`CallToolResult.SetError(err)` and a nil Go error, so `instrumentTools`' own error-log branch never fires
for a tool business error — the new mapper's log line is the FIRST server-side log this error class gets;
`addMiddleware` iterates the variadic list backwards, so the first-listed middleware is outermost.
`Server.Connect(ctx, ...)` hands `ctx` to the jsonrpc2 connection, whose per-request context derives from
it with values preserved — so an in-memory-transport test can carry an authenticated identity by
connecting the server session with `authedContext(t, owner)`.
