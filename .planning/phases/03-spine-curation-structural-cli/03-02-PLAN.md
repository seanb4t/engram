<objective>
Backfill `--output json|text` with TTY auto-detection across every existing operator command
(D-13), so every operator report is machine-readable for the headless CLI lane, without
disturbing the deliberate client-vs-operator `--timeout` divergence.

Purpose: `spine-review` is not the only report an agent needs to parse. Shipping `--output` on one
new command while five shipped ones stay text-only is exactly the two-ways-to-say-one-thing
inconsistency Phase 2 spent itself removing.

Output: a shared operator-tier output helper, `--output` on every operator command, one exported
validation function shared with the client tier, and a documented output contract in the CLI guide.

**Discretion resolved (CONTEXT.md § Claude's Discretion):** the backfill lands AFTER the tracer,
not ahead of it. Plan 03-01 proves the nested tree and the qualified-path catalog first, because a
golden regeneration is cheaper to do once the tree's final shape exists than twice.

**Scope note:** CONTEXT.md D-13 names five existing operator commands. The live cobra tree carries
SIX — `migrate-set-owner` is registered (deprecated, but present in `root.Commands()`, in
`operations`, and in both goldens). This plan backfills all six. Shipping five of six would leave
`engram migrate-set-owner --output json` erroring while its own replacement works, during the very
deprecation window an operator is scripting the migration.
</objective>
