<objective>
Stand up the CSRF token cryptographic primitive: an HKDF-derived sub-key of
`ui.cookie_key` and an HMAC-over-Owner double-submit signer, per D-08. This is
the pure-crypto foundation both the Connect verification interceptor (plan 02)
and the cookie issuance path (plan 03) build on. No wiring, no HTTP, no Connect —
just the `internal/webauth` signer and its unit tests.

Purpose: give the write lane a stable, forgery-resistant token that survives the
Phase-18 session re-seal (Owner-only binding) and introduces no second operator
secret (sub-key derived from the existing cookie key).
Output: `internal/webauth/csrf.go` (signer + key derivation + wire-name consts)
and `internal/webauth/csrf_test.go` (D-08 stability, tamper rejection, key guard).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| ui.cookie_key (operator secret) → k_csrf (derived) | The single session secret is stretched into a second, domain-separated HMAC key; a weakness in derivation would correlate the CSRF key with the AES-GCM session-seal key |
| token bytes → comparison | An attacker-supplied token string is compared against the server-computed HMAC; a non-constant-time compare leaks the valid token |

## STRIDE Threat Register (ASVS L1, blocking threshold: high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-02 | Information Disclosure | CSRFSigner.Verify | medium | mitigate | `hmac.Equal` constant-time comparison, never `==`; asserted by TestCSRFSigner_TamperRejected + acceptance grep for absence of `==` |
| T-16-03 | Spoofing | CSRFSigner.Token/Verify | medium | mitigate | HMAC bound to Owner (D-08) — a token minted for one Owner never validates for another; asserted by the cross-owner subtest |
| T-16-07 | Tampering | DeriveCSRFKey (key material) | medium | mitigate | RFC 5869 HKDF with distinct `engram-csrf-v1` info label gives cryptographic domain separation from the session-seal key derived from the same ui.cookie_key |
| T-16-SC | Tampering | go.mod dependencies | high | accept | Zero new external packages — stdlib crypto/hkdf, crypto/hmac, crypto/sha256 only (RESEARCH § Package Legitimacy Audit: N/A); enforced by `git diff --exit-code go.mod` |
</threat_model>
