<objective>
Let a curated `memory`-category record optionally carry structured provenance, by relaxing exactly
one gate: `payload()` currently writes `kind` and `citations` together under a single
`category == "discovery"` check, and D-01 splits that so `citations` is written whenever the slice is
non-empty, for any category. The existing `store.Citation` shape and `store.Memory.Citations` field
are reused verbatim (D-03).

Purpose: the write gate is only half the work. Three things must be true or the feature ships broken:
the wire field has to be mapped inside `storeArgs.toMemory` (a hand-written allow-list mapper that
today has no citations line — add the field to `storeArgs` without it and citations decode, validate,
and then vanish before `Upsert` ever sees them); the write must go through `payload()` and nowhere
else, or the next `update_memory` erases it; and the Connect compact recall view must be taught to
clear citations, because unlike MCP's hand-written `recallView` it starts from the full proto message
and would otherwise leak the entire citation payload into the token-cheap default response.

Output: the gate split, the arg surface and its mapping, a shared citation validator, the Connect
compact-view fix, and the regression tests that make each of the three failure modes above fail loudly.
</objective>

<planner_assumptions>
Two deliberate choices this plan makes that `26-CONTEXT.md` left open — flagged rather than buried:

1. **Citations are excluded from the idempotency fingerprint.** A keyed replay returns the original
   record with its original citations, and supplying different citations under an existing key is not
   treated as a content mismatch. The alternative (folding citations into `contentFingerprint`) would
   turn an additive provenance edit into a rejected replay. Pinned by a sub-test in Task 2.
2. **`validateCitations` adds a non-empty `ref` check that the shipped discovery validator does not
   have.** D-05 calls for it explicitly, so extracting the validator slightly tightens
   `store_discovery` too: a citation with an empty `ref` that passes today will be rejected after this
   change. An empty `ref` is meaningless under all four citation kinds, so this is judged a desirable
   tightening — but it is a behavior change riding inside a refactor and is called out here rather
   than landing silently.
</planner_assumptions>
