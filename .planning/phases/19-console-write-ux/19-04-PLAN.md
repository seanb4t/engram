<objective>
Provide the write-RPC mutation hooks the form/dialog/row layers consume, following the v6 options-as-thunk `createMutation` pattern with optimistic update + rollback (D-10):

- Memory (D-03): `useCreateMemory` (StoreMemory), `useUpdateMemory` (UpdateMemory — content/tags/summary/shared via update_mask), `useDeleteMemory` (DeleteMemory), `useSetMemoryVisibility` (SetVisibility, Visibility enum), `useScheduleMemory` (ScheduleMemory with not_before/not_after).
- Discovery (D-04): `useCreateDiscovery` (StoreDiscovery), `useDeleteDiscovery` (DeleteMemory by id — discoveries are records addressed by id), `useSetDiscoveryVisibility` (SetVisibility). No discovery edit (D-04 fence).

Each wrapper: options-as-thunk `createMutation(() => ({...}))`, `mutationFn` builds the request via `create(...Schema, {...})` and calls the matching `engramWrite` method, `onMutate` cancels + snapshots + applies the optimistic cache change, `onError` restores the snapshot, `onSettled` invalidates the relevant query keys. Toasts use the lowercase one-word voice.

Purpose: one tested, reusable mutation surface so components never touch the transport or hand-roll cache bookkeeping.
Output: two mutation modules + node tests covering RPC shape and optimistic rollback.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| optimistic client cache → displayed state | Cache is mutated before the server confirms; a failed write must not leave stale state |
| client mutation input → server write RPC | Client field checks are UX-only; server protovalidate is the authoritative validator |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-41 | Tampering | Optimistic cache showing a write that never landed | medium | mitigate | onMutate snapshot + onError rollback restores exact prior cache state (D-10); tests assert rollback equality |
| T-19-42 | Repudiation | onError swallowing the auth error, hiding the terminal failure from the form (D-09) | medium | mitigate | Mutation onError performs rollback + toast but does not consume the error; the caller's onError still fires (drives inline re-auth) |
| T-19-43 | Elevation of Privilege | Client-side validation mistaken for a security boundary | low | mitigate | Requests pass server protovalidate (Phase 15); source comment states client checks are UX-only |
| T-19-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages this phase |
