# Phase 19 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** this is a pure UX-layer contract for a design system that already exists and is fully populated (`ui/src/app.css`, `ui/src/lib/components/ui/*`, `ui/components.json`). ## Spacing Scale

This console runs a **tighter-than-8pt** density scale — it is already shipped and must be matched, not replaced. Declared values in actual use across `MemoryRow`/`MemoryDetail`/`AppShell`:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px (`gap-1`, `p-1`) | Icon-to-label gaps, badge internal padding |
| sm | 8px (`gap-2`, `p-2`, `px-2`) | Row internal spacing, compact button padding |
| md | 12px (`p-3`, `px-3`, `py-2`) | Panel/header padding, row padding (`MemoryRow` uses `px-3 py-2`) |
| lg | 16px (`p-4`) | Sheet/dialog body padding |
| xl | 24px | Empty-state padding (`Empty.Root` uses `p-8` = 32px — treat as the one sanctioned oversized exception, see below) |

Exceptions:
- `Empty.Root` uses `p-8` (32px) for empty-state panels — already established in `MemoryList.svelte`, keep it for any new create-flow empty states (e.g. "no drafts").
- Row action targets (dropdown-menu trigger icon buttons) use the existing `icon-sm` button size (28px / `h-7 w-7`), below the generic 44px touch-target guidance — this is an intentional dense-desktop-console tradeoff already established app-wide (`Button` `icon`/`icon-sm` sizes), not a new deviation. Do not introduce 44px targets in this phase; match the existing `icon-sm`/`sm` button sizing on all new row actions (edit, delete, visibility toggle).

## Typography

This console runs **smaller than default web body text** by design (13px base, not 16px) — a deliberate dense-console choice already live across the app. New write-UX surfaces (sheet forms, dialog copy, inline warnings) must match these existing sizes exactly, not the generic 16px/1.5 recommendation.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / form field text | 13px (`text-[13px]`, Tailwind `text-base` is remapped small in this app — see `Button`/row usage) | 400 (regular) | 1.4 (default browser leading at this size, unmodified) |
| Label / meta / caption | 10–11px (`text-[10px]`–`text-[11px]`, e.g. category labels, timestamps, scope org) | 500–600 (medium/semibold, e.g. `font-medium`, `font-semibold`) | 1.3 |
| Section heading (sheet/dialog title) | 14px (shadcn default `Sheet.Title`/`Dialog.Title` — do not override) | 600 (semibold) | 1.2 |
| Uppercase micro-label (badges, "SUMMARY" tab caption) | 9.5–10px, `uppercase tracking-wide` | 600 (semibold) | 1.2 |

Two weights only, matching existing usage: **400 regular** (body/content) and **600 semibold** (labels, headings, active nav). Do not introduce a third weight.

## Color

Existing 60/30/10 surface split (already implemented in `app.css`, both light and dark):

| Role | Value (light / dark) | Usage |
|------|-------|-------|
| Dominant (60%) | `--background` `#ffffff` / `#0d1117` | Page background, list panel, sheet/dialog surface |
| Secondary (30%) | `--card` `#ffffff` / `#161b22`, `--secondary` `#f6f8fa` / `#161b22`, `--muted` (same) | Cards, side nav, sheet header/footer bars, row hover (`--accent`) |
| Accent (10%) | `--primary` `#6E56CF` / `#8B7BE8` | **Reserved for:** primary CTA buttons ("Save", "Create memory"), active nav rail indicator, the `✦ auto`-summary badge, focus ring (`--ring`), sheet-open trigger emphasis. Do NOT use primary/accent purple for destructive actions, warnings, or secondary buttons — those stay `outline`/`ghost`/`surface` variants. |
| Destructive | **Gap — must be added this phase.** No `--destructive` / `--color-destructive` token exists in `app.css` today, even though shipped shadcn primitives (`badge`, `dropdown-menu-item`, `input`, `textarea`, `input-group`) already reference `bg-destructive`/`text-destructive`/`ring-destructive` classes that currently resolve to nothing. **Required fix:** alias the existing error-semantic color `--cat-gotcha` (`#bc4c00` light / `#ffa657` dark — already used for all error states app-wide, e.g. `text-cat-gotcha` in `MemoryList`/`MemoryDetail`/`+layout.svelte`) as `--destructive` in both `:root`/`.dark` blocks and add `--color-destructive: var(--destructive)` (plus a `--color-destructive-foreground: #ffffff` or existing `--primary-foreground`-equivalent) to the `@theme inline` block in `ui/src/app.css`. This makes the shadcn `dropdown-menu-item variant="destructive"` (delete row action, D-02/D-06) and the delete confirm `dialog` render correctly with zero new color decisions, and keeps one error color for the whole app. |

Accent reserved for: primary CTA buttons only ("Save memory", "Save discovery", "Create"), the active nav-rail indicator bar, the `✦ auto` summary marker, and focus rings. Never for delete/destructive controls, never for the private→shared warning banner (that uses destructive/amber semantics, see Copywriting below), never as a generic "everything clickable is purple" pattern.

## Copywriting Contract

Tone match: existing console copy is **lowercase, terse, no exclamation points** ("copied", "copy failed", "select a scope", "no memories", "failed to load — retry from the toolbar"). All new copy below follows that voice exactly — do not capitalize sentence-style or add punctuation flourish.

| Element | Copy |
|---------|------|
| Primary CTA — new memory | `New memory` (header/toolbar trigger, opens create sheet) |
| Primary CTA — new discovery | `New discovery` (discovery-scope toolbar trigger) |
| Sheet submit button — create | `Create` |
| Sheet submit button — edit | `Save` |
| Sheet cancel button | `Cancel` (shadcn `Sheet.Close`/outline button, left of submit) |
| Row action — edit | `Edit` (dropdown-menu item, pencil icon) |
| Row action — delete | `Delete` (dropdown-menu item, `variant="destructive"`, trash icon) |
| Row action — set visibility | `Share` (when private→shared) / `visibility` shown as current-state badge, not a toggle label, when already shared (irreversible — see warning below) |
| Empty state — no writable records yet (new create flow, e.g. empty schedule list) | Heading: `nothing scheduled` · Body: `set a not-before or not-after window when creating a memory to see it here` |
| Empty state — draft sheet with no content yet | placeholder text in content field: `write the memory…` (lowercase, matches existing placeholder-style copy) |
| Error state — write failed after retry | `write failed — session expired. re-authenticate to continue.` (inline in sheet per D-09, not a toast — toast is reserved for transient/non-blocking feedback like the existing `copy failed`) |
| Error state — generic write failure (non-auth, e.g. validation) | `couldn't save — {server message}` inline near the sheet footer, submit button re-enabled |
| Destructive confirmation — delete memory | Dialog title: `Delete this memory?` · Body: `this can't be undone. the record and its content are removed permanently.` · Confirm button: `Delete` (destructive variant) · Cancel: `Cancel` |
| Destructive confirmation — delete discovery | Dialog title: `Delete this discovery?` · Body: `this can't be undone. the map/fact and its citations are removed permanently.` · Confirm: `Delete` · Cancel: `Cancel` |
| Sharing warning (D-07, private→shared) | Inline banner at the visibility toggle, `text-cat-gotcha`/destructive-toned, not a modal: `sharing makes this readable by every authenticated caller and can't be narrowed back to private once shared.` Confirm action inline: `Share anyway` (destructive-outline styling) / `Cancel` |
| Toast — write succeeded | `saved` / `created` / `deleted` (lowercase, matches existing `toast.success('copied')` convention — no exclamation) |
| Toast — silent retry (D-08) | **None.** Per D-08 the retry-once is invisible — no toast, no flash, on the successful retry path. Only a *failed* retry surfaces the inline re-auth prompt above. |

## Component Specs (write-surface specific)

These extend the existing component inventory; no new shadcn primitives required.

**Create/Edit sheet (D-01):**
- `Sheet` with `side="right"` (the component default — matches existing `data-[side=right]` styling, `sm:max-w-sm` width), header (`Sheet.Title` = "New memory" / "Edit memory" / "New discovery"), body form fields, footer (`Cancel` outline button + `Create`/`Save` primary button, right-aligned per existing dialog/sheet footer convention).
- Field set (memory): content (`textarea`, required), scope (read-only display or `select` defaulting to current scope per Claude's-discretion note in CONTEXT.md), category (`select`, required), tags (chip input built on `input`/`input-group` — no existing chip component, build minimal: comma/enter-to-add tokens rendered as small `badge`s with an inline remove `x`, 10px uppercase style matching existing tag rendering in `MemoryRow` which already shows `bg-muted font-mono text-[10.5px]` pill tags — reuse that exact visual style for chips), visibility (`select` or `checkbox`, default `private`), summary (optional `textarea`, small/secondary), schedule window — `not_before`/`not_after` (two optional datetime inputs, collapsed under a disclosure/`checkbox` "schedule this memory" toggle, only shown for memories not discoveries per D-03).
- Field set (discovery): content/kind/citations are create-only (no edit surface per D-04) — `kind` (`select`: map|fact), citations (structured list, out of deep-edit scope — simple add-URL input for create only), summary (`textarea`), visibility (`select`, default private).
- Inline re-auth prompt (D-09) renders **inside the sheet body**, above the footer, when the retried write hard-fails — same visual treatment as the sharing warning banner (destructive-toned inline alert, not a separate dialog), with a `Re-authenticate` button that triggers `/auth/login` while the sheet's field values remain bound and untouched.

**Delete confirm dialog (D-06):** standard shadcn `Dialog` — `Dialog.Header`/`Dialog.Title`/`Dialog.Description` for the copy above, `Dialog.Footer` with `Cancel` (outline) + `Delete` (destructive-variant button — requires the `--destructive` token fix above to render correctly).

**Inline row/detail actions (D-02):** `DropdownMenu` on `MemoryRow` (trigger: existing `icon-sm` ghost button, kebab icon, appears on row hover matching existing hover-reveal pattern in the app) and explicit action buttons in `MemoryDetail`'s header bar (next to the existing `copy` button, same `Button variant="outline" size="sm"` styling already used there). Delete uses `variant="destructive"` on the `DropdownMenu.Item`.

**Optimistic rollback (D-10):** no new visual state beyond existing loading/error patterns — an optimistic row update renders immediately (no skeleton), and on rollback the row/detail reverts with the existing inline error copy pattern (`text-cat-gotcha`) plus a `toast.error('write failed')` — do not add a distinct "reverting" animation/spinner; keep it instant per the app's terse-feedback convention.
