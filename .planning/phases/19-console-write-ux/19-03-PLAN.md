<objective>
Build the presentational write-action affordances (no mutation wiring yet — that lands in Plan 06):

- `DeleteConfirmDialog.svelte` (D-06): a reusable shadcn `Dialog` confirm, parameterized by kind (memory|discovery), using the exact UI-SPEC copy, with a destructive confirm button. Emits `onconfirm`.
- `ShareWarningInline.svelte` (D-07): an inline, destructive-toned banner stating the irreversibility of private→shared ("readable by every authenticated caller ... can't be narrowed back to private once shared"), with `Share anyway` / `Cancel`. Emits `onconfirm`/`oncancel`.
- `MemoryRow.svelte` + `MemoryList.svelte` (D-02): a hover-revealed `dropdown-menu` (kebab, `icon-sm` ghost) exposing Edit/Delete/Share; delete uses the `variant="destructive"` item. New `onedit`/`ondelete`/`onshare` callback props thread through `MemoryList` exactly like the existing `onselect`.
- `MemoryDetail.svelte` (D-02): Edit/Delete/Share buttons (`Button variant="outline" size="sm"`) in the header bar next to the existing `copy` button.

These components are pure UI: they take callbacks and render; they do not import the write client or mutations. This lets them build in parallel with the transport (Plan 02) and be wired by the route integration (Plan 06). Rules get no affordance (D-05).

Purpose: deliver the destructive/sharing/edit surfaces with correct copy, tone, and density before wiring behavior.
Output: two new reusable components + row/list/detail extensions, each with browser tests.
</objective>
