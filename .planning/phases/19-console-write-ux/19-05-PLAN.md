<objective>
Build the slide-over create/edit forms (D-01) that drive the memory/discovery mutations:

- `MemoryFormSheet.svelte`: a right-side shadcn `Sheet` for both create and edit. Field set (per UI-SPEC): content (textarea, required), scope (defaults to the current route scope, editable), category (select, required), tags (minimal chip input built from input + badge), visibility (default private; toggling to shared surfaces the embedded `ShareWarningInline` acknowledgement — D-07), summary (optional), and an optional schedule window (not_before/not_after) behind a "schedule this memory" checkbox (memory-only — D-03). On a post-retry hard auth failure it keeps the sheet open, renders the inline re-auth prompt with a Re-authenticate button, and preserves all entered values for resubmit (D-09).
- `DiscoveryFormSheet.svelte`: a create-only Sheet (D-04 — no edit) with kind (select map|fact), citations (simple add-URL list), summary, tags, scope, visibility, calling `useCreateDiscovery`.

Purpose: the primary write surface — a slide-over that never loses the operator's input on a rotation/re-auth event.
Output: two Sheet-hosted form components with browser tests covering render, submit, share-warning gate, and the D-09 retain-and-reauth path.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-flight form $state → re-auth event | A hard-fail must not drop the operator's typed input (integrity/UX property) |
| operator visibility choice → shared write | private→shared is one-way; the form must gate it behind acknowledgement |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-51 | Information Disclosure | Accidental private→shared from the form's visibility control | medium | mitigate | Embedded ShareWarningInline requires `Share anyway` acknowledgement before the field is treated as shared (D-07) |
| T-19-52 | Denial of Service (UX) / data loss | Losing typed input on a mid-write session expiry | medium | mitigate | D-09: sheet stays open on post-retry auth failure, `$state` field values preserved, inline re-auth offered; browser test asserts values retained |
| T-19-53 | Information Disclosure | Draft form data leaking beyond what the operator typed | low | accept | No sessionStorage draft persistence this phase (explicitly deferred); form holds only operator-entered values in memory |
| T-19-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages this phase (chip input built from existing input/badge primitives) |
</threat_model>
