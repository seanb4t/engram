<objective>
Build the slide-over create/edit forms (D-01) that drive the memory/discovery mutations:

- `MemoryFormSheet.svelte`: a right-side shadcn `Sheet` for both create and edit. Field set (per UI-SPEC): content (textarea, required), scope (defaults to the current route scope; editable in CREATE, DISABLED in edit), category (select, required in CREATE, DISABLED in edit), tags (minimal chip input built from input + badge), visibility (default private; toggling to shared surfaces the embedded `ShareWarningInline` acknowledgement — D-07 — and sets a `shared` intent the Plan-04 create composite commits via SetVisibility), summary (optional), and an optional schedule window (not_before/not_after) behind a "schedule this memory" checkbox shown in CREATE mode ONLY (memory-only — D-03; ScheduleMemoryRequest has no id so an edit can never schedule). On submit it calls the appropriate Plan-04 hook (create — with `shared` intent, or update in edit mode, or schedule when a window is set in create mode). On a post-retry hard auth failure it keeps the sheet open, renders the inline re-auth prompt with a Re-authenticate button, and preserves all entered values; because clicking Re-authenticate triggers a full `/auth/login` OIDC redirect (which destroys `$state`), the form persists a sessionStorage draft before navigating and restores it on remount so the values genuinely survive re-auth (D-09).
- `DiscoveryFormSheet.svelte`: a create-only Sheet (D-04 — no edit) with content (textarea, required), kind (select map|fact), a citation editor (≥1 citation, each `kind` ∈ file|commit|url|repo + a required `ref`), summary, tags, scope (`discovery:`-prefixed, defaulted only on the discovery route), visibility, calling `useCreateDiscovery`.

**Reconciled with the RPC contracts (Codex+grok HIGH, verified against proto/tools.go):** the memory form's scope/category are immutable in edit mode; schedule is create-only; create-time shared is a two-call composite (not a create-RPC field); the discovery form must send content + typed citations + a discovery-prefixed scope or the server bounces it with InvalidArgument.

Purpose: the primary write surface — a slide-over whose input survives both the in-SPA retry AND a full re-auth redirect.
Output: two Sheet-hosted form components with browser tests covering render, submit, share-warning gate, the create-only schedule gating, the discovery content+citations field set, and the D-09 retain-and-reauth path (including sessionStorage draft round-trip).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| in-flight form $state → re-auth event | A hard-fail must not drop the operator's typed input (integrity/UX property) |
| operator visibility choice → shared write | private→shared is one-way; the form must gate it behind acknowledgement |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-51 | Information Disclosure | Accidental private→shared from the form's visibility control; or create landing PRIVATE while the operator believes it shared | medium | mitigate | Embedded ShareWarningInline requires `Share anyway` before the `shared` intent is set (D-07); the intent drives the Plan-04 create→SetVisibility composite (not a create-RPC field), whose partial-failure toast never falsely reports shared |
| T-19-52 | Denial of Service (UX) / data loss | Losing typed input on a mid-write session expiry or a full re-auth redirect | medium | mitigate | D-09 two-tier: (1) sheet stays open on a post-retry auth failure with `$state` preserved (no navigation); (2) a sessionStorage draft is persisted before the `/auth/login` OIDC redirect and restored on remount so input survives the round-trip; browser tests assert both |
| T-19-53 | Information Disclosure | sessionStorage draft data persisting beyond the operator's session / leaking beyond typed input | low | mitigate | The draft holds ONLY operator-entered form values (never server data or tokens), is keyed per kind/mode/record, is cleared on successful submit AND consumed-then-deleted on restore, and lives in sessionStorage (per-tab, cleared on tab close).
