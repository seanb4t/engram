<objective>
Wire the write surfaces into the three list/detail routes so the operator can actually create/edit/delete/re-share/schedule end-to-end — the payoff plan that connects Plans 03/04/05.

Introduce `WriteSurfaces.svelte`, a route-level host component that owns the write UI state (which sheet is open, edit target, delete target, share target) and orchestrates: the `New memory`/`New discovery` toolbar entry point, `MemoryFormSheet`/`DiscoveryFormSheet` (create + edit), `DeleteConfirmDialog` (triggered by a delete callback), and `ShareWarningInline` (triggered by a share callback → `useSetMemoryVisibility`/`useSetDiscoveryVisibility`). Then wire each route (`observe`, `search`, `discovery`) to render `WriteSurfaces` and to pass `onedit`/`ondelete`/`onshare` down through `MemoryList` (and `MemoryDetail`) to the rows.

Entry points (Claude's discretion, per CONTEXT): `New memory` on the memory routes (observe/search) and `New discovery` on the discovery route, each as a least-intrusive toolbar button that opens the matching form sheet defaulted to the current scope (a `discovery:`-prefixed scope on the discovery route).

WriteSurfaces exposes an EXACT host API — `export function` instance methods (`openCreate`/`openEdit`/`requestDelete`/`requestShare`) reached via `bind:this` — no vague "or equivalent". The discovery route wires only delete/share (no edit — D-04).

Finally, this plan ships the phase: after `pnpm test`/`pnpm check` are green, Task 3 runs `task ui:build`, commits the rebuilt `internal/webauth/static/` (the go:embed'd production console), and gates on the full `task` run — otherwise the shipped binary would not contain the write UX and CI ui-drift would reject (Codex HIGH).

Purpose: deliver SC1 as a working console flow AND ship it in the embedded binary, honoring D-02/D-06/D-07/D-10 and the D-04/D-05 fences.
Output: one host component + three wired routes + the rebuilt embedded SPA, with a browser test for the host's open/confirm orchestration.
</objective>
