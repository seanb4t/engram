<objective>
Wire the write surfaces into the three list/detail routes so the operator can actually create/edit/delete/re-share/schedule end-to-end — the payoff plan that connects Plans 03/04/05.

Introduce `WriteSurfaces.svelte`, a route-level host component that owns the write UI state (which sheet is open, edit target, delete target, share target) and orchestrates: the `New memory`/`New discovery` toolbar entry point, `MemoryFormSheet`/`DiscoveryFormSheet` (create + edit), `DeleteConfirmDialog` (triggered by a delete callback), and `ShareWarningInline` (triggered by a share callback → `useSetMemoryVisibility`/`useSetDiscoveryVisibility`). Then wire each route (`observe`, `search`, `discovery`) to render `WriteSurfaces` and to pass `onedit`/`ondelete`/`onshare` down through `MemoryList` (and `MemoryDetail`) to the rows.

Entry points (Claude's discretion, per CONTEXT): `New memory` on the memory routes (observe/search) and `New discovery` on the discovery route, each as a least-intrusive toolbar button that opens the matching form sheet defaulted to the current scope.

Purpose: deliver SC1 as a working console flow, honoring D-02/D-06/D-07/D-10 and the D-05 fence.
Output: one host component + three wired routes, with a browser test for the host's open/confirm orchestration.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator action → destructive/one-way write | Delete + private→shared reach the server only after their confirm/warning gates |
| console UI → server authz | The console can only invoke the write RPCs; all authz/rule-immutability enforced server-side (Phase 17) |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-19-61 | Tampering | Accidental delete via row/detail action | medium | mitigate | delete callback routes through DeleteConfirmDialog (D-06) before any delete hook fires |
| T-19-62 | Information Disclosure | Accidental private→shared via row/detail share action | medium | mitigate | share callback routes through ShareWarningInline acknowledgement (D-07) before set-visibility fires |
| T-19-63 | Elevation of Privilege | A rule write entry point slipping into the console | low | mitigate | WriteSurfaces + routes render no rule affordance (D-05); server also rejects rule set_visibility |
| T-19-64 | Tampering | Stale optimistic state after a failed write | medium | mitigate | Plan-04 hooks roll back on error (D-10); routes add no bypassing refetch |
| T-19-SC | Tampering | npm/pip/cargo installs | low | accept | No new packages this phase |
</threat_model>
