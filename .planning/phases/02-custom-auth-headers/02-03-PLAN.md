## Prohibition probe (spec-less fallback, in-prompt recall)

Stage 1 raw candidates for the CLI boundary: must not echo a pasted secret in an error; must not read
the header var's value; must not let `Authorization` have two owners; must not treat `--header ""` as
absent; must not sort or dedupe silently (a duplicate is an error, not a merge — unlike `--runtime`'s
WR-02 dedup, because two different ENVVARs for one NAME is a real conflict); must not add a koanf row;
must not turn a usage error into a per-runtime failed row; must not widen the row JSON with an array;
must not change the `Accepted --auth modes` block; must not run a real runtime CLI in tests. Stage 2
keeps three (authored above, descriptor-less): the **never-echo-the-right-hand-side** safety
prohibition, the **never-read-the-value** safety prohibition, and the **usage-error-not-runtime-row**
transparency prohibition. The rest are pinned as truths (D-01/D-07/D-08) or are canon: argv/shell
injection through a header NAME is canon (RFC 7230 token grammar excludes whitespace and shell
metacharacters; `apply.go` execs with no shell) — covered by `/gsd-secure-phase`, not minted here.
