<objective>
Extend plan 02-01's header vocabulary to the two remaining runtimes that CAN express a header:
opencode renders one `--header NAME={env:ENVVAR}` pair per header on its single `opencode mcp add`
action in every mode it supports (D-01, D-04, D-08), and `generic` carries the extras in its EXISTING
`headers` JSON object beside any bearer `Authorization` entry, valued `${ENVVAR}` (D-04, D-05), with the
marshaled object ordered `Authorization` first then extras sorted case-insensitively so generic JSON
shows the SAME order argv does (D-08). `TestNoSecretInArgs` gains the positive control that every
successful header-carrying Plan actually names the variable.

Purpose: REQ-header-name-parameter names opencode and `generic` alongside Claude Code, each in its own
syntax; REQ-header-value-env-ref-only needs both files to stay free of any environment read;
REQ-header-bearer-unchanged needs generic's zero-header Config and opencode's zero-header Args to stay
byte-identical — which is why generic's ordering is done with a `MarshalJSON` that reuses
`json.Marshal` for every key and value (so `<` escaping and every other byte stays as it is), not
a hand-rolled encoder.

Output: `openCodeHeaderArgs`, `genericHeaders` (named map type + `MarshalJSON`), extended
`Generic.Plan`, `TestOpenCodeHeaders`, `TestGenericHeaders`, and the positive control in
`TestNoSecretInArgs`. Depends on 02-01's `HeaderSpec`/`sortedHeaders`.
</objective>
