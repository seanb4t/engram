<objective>
Give `internal/setup` the vocabulary for an ADDITIONAL, secret-valued HTTP header that rides alongside
whatever `--auth` produces (the user's framing correction in 02-CONTEXT.md: orthogonal to `--auth`,
never an `Authorization` rename, never "bearer generalized"). This plan lands the shared types and the
two runtimes at the ends of the capability spectrum: `Options.Headers []HeaderSpec`, the new
`ErrHeaderUnsupported` sentinel and the `sortedHeaders` ordering helper in `runtime.go` (D-06, D-08,
D-10); claude-code rendering one `--header "NAME: ${ENVVAR}"` pair per header on the SAME `claude mcp
add` action in every auth arm (D-01, D-04, D-08); and codex declining any header before its auth switch
with a `failed`-row reason naming the header(s), the capability gap, and the remedy (D-09, D-10).

Purpose: REQ-header-name-parameter needs a per-runtime rendering with no shared cross-runtime
formatter; REQ-header-value-env-ref-only needs the structural guarantee that this package never sees a
header value; REQ-header-codex-declined needs a distinct sentinel so `codex mcp add`'s missing header
flag is reported as exactly what it is. Plan 02-02 extends the same vocabulary to opencode and
generic; plan 02-03 wires the `--header` flag; plan 02-04 documents it.

Output: `HeaderSpec`, `Options.Headers`, `ErrHeaderUnsupported`, `sortedHeaders`,
`claudeCodeHeaderArgs`, the codex guard, and three tests (`TestNoSecretInArgs` extended,
`TestClaudeCodeHeaders`, `TestCodexDeclinesHeaders`). No new files; zero new dependencies.
</objective>
