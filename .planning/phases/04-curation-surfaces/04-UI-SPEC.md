### Deltas the sketch's `curation.md` does not yet reflect (04-CONTEXT.md revisions)

The sketch document is the primary design source, but four `04-CONTEXT.md` decisions **override**

| Sketch says | `04-CONTEXT.md` says instead |
|---|---|
| Re-auth: "Re-authenticate & retry" auto-resubmits the draft | **D-15**: the dialog reopens and **waits**. Nothing is resent automatically; copy becomes "Signed in again — review and resend" with a manual resend action, not an auto-retry. |

| Archive/Restore ships with a single undo (the result body) | **D-09**: undo is offered **twice** — the result body's "Undo — restore N" (durable record) **and** a separate svelte-sonner toast on Done (satisfies CUR-02's "one-click undo toast" literally). |

## Typography

Inherits Phase 2's four sizes / two weights (`--text-2xs`/`--text-xs`/`--ui-font` body/`calc(16 *
var(--u))` heading, 400/600) unchanged. No new sizes or weights this phase. Dialog-specific
notes:

- Dialog titles ("Supersede 2 records into one", "Archive 2 records?") use the Heading role
  (600, `calc(16 * var(--u))`), matching the detail-pane section-label precedent.
- The byte counter (`86/512 B`) and target/gate counts (`Supersede N → 1`) are monospace,
  Micro-label size, 400 weight — danger-tone (`--color-danger`) only when over the limit, per
  `curation.md`'s `.cnt` styling.
- The "No undo." success-state sentence is body text at 600 weight (the one deliberate emphasis
  exception) — it is the single most safety-critical sentence this phase renders and must not
  read as decoration-equal to the rest of the success body.

## UI Considerations

Probe: `ui-consideration-probe` over 6 authored elements (E1–E6), `--auto`. Empty/error copy
lives in the Copywriting Contract above; rows here reference it rather than restating it.

Elements: E1 Supersede dialog · E2 Archive/Restore confirm dialog · E3 Chain dialog · E4 Bulk
selection bar and row action buttons · E5 Rules route · E6 Scheduled route

| Element | Category | Status | Truth |
|---------|----------|--------|-------|
| E1 | empty | resolved (explicit) | A supersede dialog opened with zero targets shows the gate `Add at least one target` and a disabled primary button — it never opens with an empty predecessors column with no explanation. |
| E1 | loading | resolved (explicit) | The validate_only preview call shows `supersede_memory · {N} targets…` with a spinner; existing chip/form content stays visible and interactive (not blanked) while it resolves. |
| E1 | error | resolved (explicit) | Validation, server-rejection, and re-auth each render their own named status block (Copywriting Contract); a client-side per-target issue is computed instantly, the server's own validate_only answer is trusted over it when they could differ. |
| E1 | populated | resolved (explicit) | Two-column layout (targets left, correcting record right) collapses to one column under `@container frame (max-width: 700px)`; the chain preview strip re-renders on every keystroke/target change without remounting the input fields (no focus loss while typing). |
| E1 | partial | resolved (explicit) | A mix of valid and invalid targets renders each independently — valid chips show their subline, invalid chips show their issue line — the gate blocks submit until every target is valid, never a partial/best-effort submit. |
| E1 | overflow | resolved (explicit) | More predecessors than fit the left column scroll within that column (the column, not the dialog, scrolls); the chain-preview column strip scrolls horizontally past 4-5 nodes (`.chain-cols { overflow-x: auto }`, already in the sketch CSS). |
| E1 | zero-one-many | resolved (explicit) | Header and button copy agree in number: `Supersede N records into one` / `Supersede N → 1` for any N ≥ 1, including N = 1 (no singular-form special case — "1 records" is avoided by phrasing the count before the noun consistently, matching the sketch's own N-agnostic template). |
| E1 | long-text | resolved (explicit) | Target chip summaries and the correcting-record's content field do not overflow the dialog — chip summaries ellipsize, content is a scrollable textarea. |
| E2 | empty | resolved (backstop) | `{ statement: "Archive/Restore confirm dialog: undefined", verification: backstop }` — an empty target set cannot occur (the dialog is only ever opened with ids already resolved from a row action or a non-empty selection). |
| E2 | loading | resolved (explicit) | Same shared status-block pattern as supersede (loading/validation/rejection/re-auth), reused rather than re-invented. |
| E2 | error | resolved (explicit) | A not-owned record in the set shows its issue inline and can be removed via `×`; the gate blocks submit while any remains, matching supersede's per-target validation pattern. |
| E2 | populated | resolved (explicit) | One chip per record with its current state chips; Archive and Restore render as the SAME dialog component with a `mode` prop swapping header/subline/button copy and style (danger-outline vs primary), not two components. |
| E2 | partial | resolved (explicit) | An idempotent outcome (`already_archived`, `not_archived`) renders in the result body as information text, never with error styling — `04-CONTEXT.md` D-09 is explicit that idempotent cases are not errors. |
| E2 | overflow | resolved (default) | A bulk archive of many records lists every chip in a scrollable body region (the dialog itself does not grow unbounded) — consistent with the supersede dialog's own left-column scroll pattern. |
| E2 | zero-one-many | resolved (explicit) | `Archive N records?` / `✓ N archived` / `Undo — restore N` all use the same N-agnostic phrasing for N = 1 through many. |
| E2 | long-text | resolved (backstop) | `{ statement: "Archive/Restore confirm dialog: undefined", verification: backstop }` |
| E3 | empty | resolved (backstop) | `{ statement: "Chain dialog: undefined", verification: backstop }` — a chain dialog is only reachable from a row already known to be chained (D-06), so an empty chain cannot occur. |
| E3 | loading | resolved (explicit) | Each node's fetch-by-id peek shows its own inline loading state (not a dialog-wide spinner) since nodes are fetched independently on click, not all at once. |
| E3 | error | resolved (default) | A peeked node that fails to fetch (e.g. a transient error) shows `No memory with id {id} that you can read` inline on that node, reusing the detail-pane's existing not-found copy rather than inventing a new string. |
| E3 | populated | resolved (explicit) | Columns run oldest-left to head-right per `curation.md`; the active/opening row is highlighted (`.cnode.hl`) among the chain. |
| E3 | overflow | resolved (explicit) | The column strip scrolls horizontally (`scroll-area` wraps it on narrow viewports) rather than wrapping to a second line, which would break the left-to-right reading order the legend promises. |
| E3 | zero-one-many | resolved (default) | A chain of depth 1 (one predecessor, one head) still renders as two columns, never collapsed to a single-node special case — the same layout scales from depth 1 to many. |
| E3 | long-text | resolved (backstop) | `{ statement: "Chain dialog: undefined", verification: backstop }` |
| E4 | empty | resolved (explicit) | With zero rows selected, the bulk bar does not render at all — `ResultsHeader` shows its normal honest-feedback content (Phase 2 contract, unchanged). |
| E4 | populated | resolved (explicit) | With one or more rows selected, the header swaps entirely to the violet bulk bar copy (D-03) — it does not append to the existing header text. |
| E4 | overflow | resolved (default) | On a narrow viewport the bulk bar's action list wraps to a second line before truncating any action label — matches the existing header's own narrow-viewport wrap behavior (Phase 2 "below 620px" precedent) rather than hiding an action. |
| E4 | zero-one-many | resolved (explicit) | `{N} selected` agrees in number and the action verbs stay plural-agnostic (`Supersede N into one…` reads correctly at N=1 through many, same template as E1). |

`aria-multiselectable="true"` is added to the listbox root when Phase 4 ships; `aria-selected` is
set per option, kept independent of `aria-activedescendant` (D-02) — a selected row and the

artifact.

### Selection lifecycle (D-04)

Selection clears on a query or facet change. It persists across "Show more" (a bigger `k`) and
across in-place updates after a write (D-10's flash-in-place rows stay selected through their own
state change, if they were selected). It is never written to the URL — a shared/bookmarked
`/search?...` link never carries someone else's selection.

### Row-in-place update after a write (D-10)

After a successful archive/restore/supersede, affected rows are **patched locally from the
response** — not refetched — and:

1. Render the new state word immediately, with the existing dim treatment (`isPastState`).
2. Flash `--color-primary-soft` for **exactly 1.6s** (`foundations.md`'s `@keyframes flash`,
   already defined — reuse it, do not re-tune the duration).
3. Stay in the list until the next query actually excludes them (recall queries are invalidated
   in the background per `engram-connect-client`'s invalidation table, but the **visible** list
   does not jump or reorder mid-flash).

This is a strict UX requirement, not a suggestion: a naive "invalidate then let TanStack Query
refetch and re-render" implementation will make rows disappear or jump immediately, which is the
exact behavior D-10 exists to prevent.

### Re-auth resume — dialogs wait, they do not retry (D-15)

Every curation dialog reopens after the OIDC round trip **already populated** (targets/ids/
correcting-record fields/`idempotency_key` intact) but takes **no automatic network action**. The
supersede dialog additionally **re-runs its `validate_only` preview** on reopen (not the commit)
so the chain reflects anything that changed server-side during the detour. The operator must
explicitly click Resend/Supersede/Archive again. This directly contradicts `curation.md`'s
"Re-authenticate & retry" auto-resubmit line — apply the Deltas-table override, not the sketch's
literal button behavior.

### Resume envelope v2 (D-16)

`ui/src/lib/resume.ts` gains, in the same file, no new module:

- `RESUME_VERSION` → `2`. A stored v1 envelope (from a build predating this phase) still
  round-trips through the existing memory/discovery restore path — v2 is additive, not a breaking
  rewrite of the schema the peek/consume functions accept.
- New envelope `kind` values: `'supersede'` (`{ targets, fields, idempotencyKey }`), `'archive'`
  (`{ mode: 'archive' | 'restore', ids }` — the Scheduled view's archive action reuses this exact
  kind with `returnPath: '/scheduled'`), `'delete'` (Rules view's delete confirm; distinct from
  the existing memory/discovery delete since it carries no `kind: 'memory' | 'discovery'`
  ambiguity to resolve).
- New `ALLOWED_DESTINATIONS` entries: `'/rules'`, `'/scheduled'`. `'/observe'` is **removed**
  from this list in the same change that deletes the route (D-14) — a stale envelope pointing at
  it now fails `isAllowedDestination` and is discarded, landing the operator on `/` through the
  existing rejection path, not a broken redirect.
- The ownership rule is unchanged: **a dialog calls only `persistResume`**; the route host
  (mirroring `WriteSurfaces.svelte`'s exact pattern — see Component Composition below) remains
  the sole owner of `peekResume`/`consumeResume`.
- Each new kind gets its own resume round-trip test (CUR-05 success criterion 4) — this is a
  test-plan requirement the planner must schedule, not implementation detail left implicit.

### Component composition (resolves 04-CONTEXT.md's first Discretion item)

**Decision:** mirror `WriteSurfaces.svelte`'s existing architecture exactly, rather than
inventing a global singleton host. A new sibling component, `CurationSurfaces.svelte`, is
instantiated once **per route** that needs it (`/search`, `/rules`, `/scheduled` — mirroring
where `WriteSurfaces` is instantiated today), exposing an explicit bind:this method contract
(`openSupersede(ids)`, `openArchive(ids)`, `openRestore(ids)`, `openChain(id)`) the same way
`WriteSurfaces` exposes `openCreate()`/`openEdit(id)`/`requestDelete(id, kind)`. Each instance
owns its own dialog `open` state, its own `idempotency_key` per draft, and — critically — its own
`returnPath` for the resume envelope, so `/rules`'s delete-confirm resume and `/search`'s
supersede resume can never cross-contaminate. This keeps the resume-host rule (route/host is the
sole owner of peek/consume) mechanically true without a new architectural pattern to learn.

The Rules view's delete confirm is the **one exception**: it reuses `DeleteConfirmDialog.svelte`
directly (adding a third `kind: 'rule'` to its existing copy table) rather than routing through
`CurationSurfaces`, since it is a plain delete with no supersede/archive-shaped state to carry.

### Navigation additions

`AppShell.svelte`'s `nav` array and `CommandMenu.svelte`'s `navItems` array both: **remove** the
`Observe` entry (D-14) and **add** `Rules` (`${base}/rules`) and `Scheduled` (`${base}/scheduled`)
entries, in that position order (replacing Observe's slot, Search and Discovery keep their
existing positions). `ui/src/routes/+page.svelte`'s scope tiles and any `DetailPane`/
`HeaderSearch`/discovery links currently pointing at `/observe?scope=...` are repointed to
`/search?q=scope:{x}` (D-14) — this is a mechanical find-and-retarget, not a new interaction.
