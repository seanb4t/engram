<objective>
Author the D-09 conversion layer (`protoconv.go`): proto write requests -> internal
`*Args`, and write results (the `mutationResult` from 17-02) -> proto response
messages, with exact-mapping unit tests. This is the seam that keeps every write
handler a thin adapter (SC2).

Two review fixes are load-bearing here:
- **RFC3339Nano (HIGH):** the original plan formatted `not_before`/`not_after`
  timestamps with `time.RFC3339`, truncating fractional seconds — which can
  collapse two valid sub-second bounds into equal strings that `parseWindow`
  rejects (tools.go:469) and can turn a slightly-future `not_after` into the
  current second, failing the future check (tools.go:464). Use `time.RFC3339Nano`;
  `time.Parse(time.RFC3339, ...)` still accepts fractional input, so `parseWindow`
  needs no change.
- **By-id result mapping (HIGH):** `UpdateMemoryResponse`/`SetVisibilityResponse`
  expose `id`+`short_id`; protoconv maps 17-02's `mutationResult` into them (the
  handler does NOT re-fetch).

The mask-driven `content` mapping is the second half of landmine 2: `content`
absent from `update_mask.paths` -> nil `updateArgs.Content` (now `*string`), never
the proto zero value. Test framing is EXACT MAPPING, not round-trip (proto ->
internal optional fields is intentionally lossy — review LOW).

Addresses review concerns: RFC3339Nano timestamp truncation (HIGH), response
conversion for update/visibility (MEDIUM), round-trip->exact-mapping framing (LOW).
</objective>
