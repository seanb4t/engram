<objective>
Author the D-09 conversion layer (`protoconv.go`): proto write requests -> internal
`*Args`, and write results (the `mutationResult` from 17-02) -> proto response
messages, with exact-mapping unit tests. This is the seam that keeps every write
handler a thin adapter (SC2).

Two review fixes are load-bearing here:
- **RFC3339Nano (HIGH):** the original plan formatted `not_before`/`not_after`
  timestamps with `time.RFC3339`, truncating fractional seconds — which can
  collapse two valid sub-second bounds into equal strings that `parseWindow`
  rejects (tools.go:469) and can turn a slightly-future `not_after` into the
  current second, failing the future check (tools.go:464). Use `time.RFC3339Nano`;
  `time.Parse(time.RFC3339, ...)` still accepts fractional input, so `parseWindow`
  needs no change.
- **By-id result mapping (HIGH):** `UpdateMemoryResponse`/`SetVisibilityResponse`
  expose `id`+`short_id`; protoconv maps 17-02's `mutationResult` into them (the
  handler does NOT re-fetch).

The mask-driven `content` mapping is the second half of landmine 2: `content`
absent from `update_mask.paths` -> nil `updateArgs.Content` (now `*string`), never
the proto zero value. Test framing is EXACT MAPPING, not round-trip (proto ->
internal optional fields is intentionally lossy — review LOW).

Addresses review concerns: RFC3339Nano timestamp truncation (HIGH), response
conversion for update/visibility (MEDIUM), round-trip->exact-mapping framing (LOW).

feeds parseWindow, so no 17-03 change is required. This plan is unchanged for round 2.

**Round-5 review (this revision):** a documentation/framing fix, no code change. (MED,
Codex) The RFC3339Nano precision guarantee is now explicitly SCOPED to the adapter/
validation boundary (it stops parseWindow from spuriously rejecting a valid sub-second
window) and this plan makes NO claim of end-to-end sub-second SCHEDULING: the store floors
both window bounds to integer Unix seconds on encode (store.go:320/:323) and decode
(:406/:410), so persisted scheduling is SECOND-GRANULAR — a `not_after` 500ms in the future
persists as start-of-second and is immediately expired. The `<1s future` test case is
reframed to assert ONLY parseWindow's acceptance of the formatted string, not end-to-end
persistence. 17-CONTEXT.md D-09 requires no sub-second scheduling persistence, so a
nanosecond store representation is deliberately OUT OF SCOPE (per the reviewer's recommended
resolution — document the second-granular limitation rather than add a nanosecond format).
No round-1/2 fix is regressed.

**Round-8 review (this revision):** two correctness fixes, no structural change. (MED, Codex —
orchestrator-CONFIRMED) BOOL/ENUM MISMATCH: the round-1..7 plan reused ONE `Visibility` enum<->bool
mapping for BOTH the SetVisibility and the UpdateMemory-`shared` paths, but `UpdateMemoryRequest.shared`
is a proto `bool` (`bool shared = 3`, engram.proto:168) — only `SetVisibilityRequest.visibility` is the
`Visibility` enum (engram.proto:185). An executor reusing the enum mapper for UpdateMemory-`shared`

`Visibility` enum mapping is reserved to the SetVisibility path only. A new exact-mapping case pins
`update_mask=["shared"]` with `shared=false` to a NON-NIL `*bool` whose value is false (the
presence-sensitive case most likely to regress). (MED, Codex) SUB-SECOND EXPIRY: the round-5 framing
merely DOCUMENTED that a sub-second `not_after` persists as immediately-expired (the store floors both
bounds via `.Unix()`, store.go:320/:323/:406/:410). Round-8 RESOLVES it explicitly (reviewer option b):
protoconv rounds the bounds OUTWARD to whole seconds — `not_before` down (`.Truncate(time.Second)`),
`not_after` up (ceil) — before RFC3339Nano formatting, so the store's second-flooring is a no-op and a
sub-second window is WIDENED to the containing whole-second window rather than silently collapsed to
immediate-expiry. No round-1..7 fix is regressed.
