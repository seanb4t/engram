  same subject — a test-only error mapper that reuses connectError's rules only

  MEDIUM):** the spy records STORE calls below `deps`, and `storeMemory`/`scheduleMemory`
  both call `MintShortID`+`Upsert` (tools.go:634-694), so a handler calling the WRONG
  deps method could forge an identical store trace. Add a source/AST-level assertion
  that each of the six Connect write handler bodies invokes its NAMED `deps.*` method
  (e.g. a test that scans connectapi.go and asserts `StoreMemory` contains
  `a.d.storeMemory(`, `ScheduleMemory` contains `a.d.scheduleMemory(`, etc.).
- **Per-lane independent fixtures (finding 4, HIGH):** a per-ROW reset is NOT enough —
  within a single row the direct `deps.*` lane runs first and MUTATES state (a Delete
  removes the record, an update changes the stale-summary precondition, a replace
  changes the second call's result) BEFORE the Connect lane runs, causing
  order-dependent false failures. Give EACH lane its own independently seeded fixture
  (or fully reset the spy/store between the two lane calls within the row).

  contradictory (it required the message to both echo the supplied UUID and exclude
  the resolved UUID). Split: short_id input -> message contains the short_id and
  excludes the resolved UUID; direct-UUID input -> message contains exactly the
  UUID the caller supplied (the caller already knows it).
