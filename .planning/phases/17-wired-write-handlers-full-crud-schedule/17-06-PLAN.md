<objective>
Realize D-07's single-path intent for READS with a transport-neutral, strongly-
typed SUPERSET convergence point — the locked review resolution, NOT a least-
common-denominator rewire and NOT `[]any`.

The reviewers proved the naive rewire (pointing Connect reads at today's
`deps.listMemory`/`searchMemory`) is a REGRESSION: those drop offset pagination,
categories, visibility, exact `total`, and cursor/next-token (tools.go:485,
tools.go:809 vs proto engram.proto:51 / connectapi.go:124), silently change the
search `k` default 20->8 (connectapi.go:162 vs tools.go:854), and return MCP-shaped
`[]any` instead of `[]store.Memory`.

This plan defines a typed core list/search request+result that is a superset of
both lanes, refactors `deps.listMemory`/`searchMemory` to return typed store data
on that contract (threading `caller` through all five read methods), moves the
MCP-specific `shapeRecall -> []any` presentation into the MCP tool closures, and
moves the per-lane `k` default to the adapter boundary (MCP 8, Connect 20). The
Connect read handlers are rewired onto this core in 17-04 — this plan makes that
possible without dropping a single Connect field.

Wave note: this plan is split from 17-02 (write-lane single-path) because both edit
tools.go and cannot run in parallel; the read convergence is a genuinely large new
piece the review escalated from a rewire to a real neutral-typed contract. It is
W2 (depends on 17-02's caller seam + memStore interface) and runs in parallel with
17-03 (protoconv.go — disjoint files).

Addresses review concerns: read-lane rewire regression / transport-neutral typed
core (HIGH, D-07 locked resolution); **round-2: searchDiscovery k-default
coordination (finding 7) — this plan keeps deps.searchDiscovery's internal MCP k=8
so the Connect adapter override in 17-04 governs the Connect lane's k=20 without a
regression.**

**Round-3 review (this revision):** the MCP list_memory closure must set
`CursorMode: true` when building the core request (HIGH-2) — the neutral core defaults
it to false and offset mode leaves next_cursor empty (store.go:817/:865), so without
the explicit true the tokenless first page silently stops cursoring, breaking the
byte-for-byte MCP pagination contract; a tokenless-first-page MCP test guards it.

**Round-4 review (this revision):** three narrow test/type corrections, no design
change. (1) HIGH-2 — the superset pagination assertion is SPLIT to match the store's
mutually-exclusive offset/cursor semantics: an offset-mode (`Offset>0`) request asserts
exact `Total` + EMPTY `NextToken` (store.go:817), and a cursor-mode first-page request
asserts a NON-EMPTY `NextToken` (store.go:865) — the prior single `Offset>0` + NextToken
assertion was impossible against live Qdrant and passed only against a token-fabricating
fake. This is distinct from and does NOT touch the round-3 MCP-closure `CursorMode: true`
+ tokenless-first-page test (correct, endorsed). (2) MED-6 — core `CreatedAfter/Before`
are `time.Time`, not `string|time.Time`; each transport parses its own wire form at the
boundary so a parse error never enters the core to be misclassified as CodeInternal.
(3) finding-7 — the shared `Limit==0 -> 20` default is REMOVED from the list core (MCP
closure applies 20, Connect leaves 0 as 'all'), the same per-lane discipline as the k
default. No round-1/2/3 fix is regressed.

**Round-5 review (this revision):** one mechanical fix, no design change. (HIGH, Codex)
The searchMemory `(ctx, caller, coreSearchRequest)` signature change omitted its compiling
call site in `internal/server/embed_wiring_test.go` (`TestSearchMemoryUsesEmbedQuery:38`
calls `d.searchMemory(ctx, searchArgs{...})` via a store-less `&deps{em: rec}`); it is now
in `files_modified` and Task 2 updates the SEARCH-path line with an explicit anonymous
caller + `coreSearchRequest`, preserving the stop-before-store intent — the STORE-path
sibling (`d.storeMemory`) is owned by 17-02 (Wave 1), so the file compiles after 17-02 and
again after 17-06. A repo-wide `rg` enumeration of every direct read-method call site backs
the compile gate. No round-1/2/3/4 fix is regressed.

**Round-6 review (this revision):** one test-intent fix, no design change. (MED, grok)
Task 2's generic "update any direct call sites" would make two EXISTING tests
compile-but-meaningless once the core takes `time.Time` and carries `CursorMode` from the
request. Task 2 now NAMES both explicitly: (i) `TestListMemoryRejectsBadWindow`
(tools_test.go:1619-1623) today passes `CreatedAfter: "nope"` (a string) expecting the core's
internal `parseRFC3339` to reject it — but after round-4 MED-6 moved parsing to the transport
boundary, a `time.Time` core field CANNOT carry an invalid string, so the bad-window rejection
is RELOCATED to the MCP tool-closure/parse boundary where `parseRFC3339` now lives (asserted at
the closure, not the core); (ii) any existing deps-level list test that asserts a non-empty
`next` must now set `CursorMode: true` explicitly on its `coreListRequest` — the core no longer
hard-codes cursor mode (store.go:817/:865), so without the flag those tests go red or silently
return an empty `next`. No round-1..5 fix is regressed.
