<objective>
Realize D-07's single-path intent for READS with a transport-neutral, strongly-
typed SUPERSET convergence point — the locked review resolution, NOT a least-
common-denominator rewire and NOT `[]any`.

The reviewers proved the naive rewire (pointing Connect reads at today's
`deps.listMemory`/`searchMemory`) is a REGRESSION: those drop offset pagination,
categories, visibility, exact `total`, and cursor/next-token (tools.go:485,
tools.go:809 vs proto engram.proto:51 / connectapi.go:124), silently change the
search `k` default 20->8 (connectapi.go:162 vs tools.go:854), and return MCP-shaped
`[]any` instead of `[]store.Memory`.

This plan defines a typed core list/search request+result that is a superset of
both lanes, refactors `deps.listMemory`/`searchMemory` to return typed store data
on that contract (threading `caller` through all five read methods), moves the
MCP-specific `shapeRecall -> []any` presentation into the MCP tool closures, and
moves the per-lane `k` default to the adapter boundary (MCP 8, Connect 20). The
Connect read handlers are rewired onto this core in 17-04 — this plan makes that
possible without dropping a single Connect field.

Wave note: this plan is split from 17-02 (write-lane single-path) because both edit
tools.go and cannot run in parallel; the read convergence is a genuinely large new
piece the review escalated from a rewire to a real neutral-typed contract. It is
W2 (depends on 17-02's caller seam + memStore interface) and runs in parallel with
17-03 (protoconv.go — disjoint files).

Addresses review concerns: read-lane rewire regression / transport-neutral typed
core (HIGH, D-07 locked resolution); **round-2: searchDiscovery k-default
coordination (finding 7) — this plan keeps deps.searchDiscovery's internal MCP k=8
so the Connect adapter override in 17-04 governs the Connect lane's k=20 without a
regression.**
</objective>
