<objective>
The foundations wave for the write lane. Four coupled deliverables the review
proved are prerequisites for any handler wiring:

1. A narrow `memStore` interface — NOW INCLUDING `DeleteAll` and `ListScopes`
   (their omission was the reviewers' consensus BLOCKER: `deps.st` retyped to the
   interface while `d.st.DeleteAll(...)` at tools.go:1143 and `a.d.st.ListScopes(...)`
   at connectapi.go:93 still compile only if the interface carries them).
2. A payload-only, vector-preserving store update method — because `store.Update`
   always requires a vector and always Upserts, and a fetched `store.Memory` carries
   no vector, "skip re-embed on shared/summary-only update" was unimplementable as
   originally written (review HIGH).
3. The `caller` seam (D-01/D-02/D-03) + a typed `mutationResult` (canonical UUID +
   short_id) returned by the by-id mutations, so `UpdateMemory`/`SetVisibility` can
   populate their proto responses without re-fetching (review HIGH).
4. The write-lane single-path rewire: caller threading through the six write
   methods + storeRule/listRules, `updateArgs.Content` → `*string` with vector-vs-
   payload routing, typed rule/stale-summary sentinels, and the proto tags-only
   doc reconciliation.

Read-lane convergence (D-07 typed core) is 17-06; protoconv is 17-03; handlers are
17-04. This plan makes those buildable.
