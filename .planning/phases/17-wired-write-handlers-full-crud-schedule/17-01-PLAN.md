<objective>
Evolve the shared `auth.ClaimIdentity` owner resolver from a single claim to an
ordered claim list so authenticated service/machine tokens without an `email`
claim resolve to a stable, namespaced owner instead of failing closed — while
keeping every existing single-value `email` deployment byte-for-byte unchanged.

This is an authorization-key change (owner is the authz key) and is hard-flagged
for `/gsd-secure-phase`. Two invariants are load-bearing: the `email_verified`
gate (D-05) and namespace disjointness between claim sources (D-06).

Purpose: closes the "service token has no email → fails closed" gap and lays the
owner-space foundation the six write RPCs (Plans 02–05) attribute records under.
Output: an ordered-list `ClaimIdentity`, list-valued config plumbing, and
dedicated D-05/D-06 security unit tests.
</objective>
