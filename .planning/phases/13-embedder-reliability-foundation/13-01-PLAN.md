<objective>
Harden the embed HTTP client construction with two isolated, provider-facing reliability fixes on the `embed.New` seam: (1) an operator-tunable request timeout replacing the hardcoded 30s (REQ-embed-timeout / GH #333, D-07/D-08/D-09), and (2) a shape-aware base-URL → `/embeddings` join with an explicit operator override, replacing the naive concat that 404s on OpenRouter/Gemini shapes (REQ-embed-baseurl-join / GH #332, D-10/D-11/D-12).

Both fixes share the same files (`internal/embed/embed.go`, the koanf config trio, and the `embedderFromConfig` wiring in `internal/server/tools.go`), so they are planned together as one embed-client-hardening unit to avoid redundant cross-wave file reloads.

Purpose: a provider 529 brownout no longer hangs the calling MCP tool indefinitely, and every documented OpenAI-compatible provider shape resolves to a working embeddings endpoint.
Output: `ENGRAM_EMBED_TIMEOUT` (default 30s, validated), `ENGRAM_OPENAI_EMBEDDINGS_URL` override, `joinEmbeddingsURL`, `embed.WithTimeout`/`embed.WithEmbeddingsURL`, and their tests; plus the D-09 assert-only regression proving no embed↔summary-queue coupling.
</objective>
