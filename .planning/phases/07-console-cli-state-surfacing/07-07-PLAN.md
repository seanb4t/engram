current schema version are routine maintenance, records AHEAD of it mean the running binary cannot
fully read its own collection. Silent at zero, silent while loading, and silent when the lookup
itself fails.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `MigrateStatus` response → every console route | A whole-collection aggregate is rendered on every page for every authenticated console user |
| query failure → user-visible UI | A diagnostic's own failure must not become a user-facing message |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-05 | Information Disclosure | `MigrationBanner` on every route | low | accept | The banner renders exactly the aggregate counts the RPC already returns to any authenticated caller — no record content, no scopes, no owners. This is the same disclosure accepted at T-07-03 under the developer's locked D-06, rendered rather than newly obtained; the console adds no data it did not already have access to. |
| T-07-20 | Denial of Service | `MigrationBanner` fetch scheduling | low | mitigate | One fetch per root `QueryClient` lifetime (NOT per browser session — the client is recreated on a full page load): `staleTime: Infinity`, `refetchOnMount: false`, `refetchOnWindowFocus: false`, `retry: false`. Because `AppShell` wraps every route, a per-route or polling fetch would multiply RPC volume against a server-side facet-plus-two-counts operation for a number that changes on operator timescales. |
| T-07-21 | Tampering | banner copy interpolation | low | mitigate | Both strings interpolate only two integers from the response; no record-derived string reaches the DOM, and Svelte escapes text interpolation by default. This plan introduces no `{@html}`. |
| T-07-22 | Repudiation | silent failure of the migration lookup | medium | mitigate | Silent to the USER is not silent to the operator debugging it: the failure is logged through `logError` from the layout's centralized `QueryCache.onError` — the SINGLE logging owner, with no component-level `$effect` duplicating it — and `meta.silent` suppresses only the global error banner, never the console diagnostic. An acceptance criterion asserts exactly one `console.error` for a rejected migration query, so the diagnostic is neither lost nor doubled. The auth-redirect branch stays first, so an unauthenticated console still redirects rather than silently showing nothing. |
| T-07-SC | Tampering | npm/pip/cargo installs | low | accept | This plan installs no packages. The UI-SPEC's Registry Safety section confirms the banner is deliberately hand-rolled rather than built from shadcn's uninstalled `alert`, so no `shadcn add` run is needed; `git diff --exit-code ui/package.json ui/package-lock.json` is expected to exit 0. |
</threat_model>
