<objective>
Add `engram get <id>` over the existing, ungated `GetMemory` RPC (D-09), rendered through Phase 6's
typed operator view via the one-line `json.RawMessage` adapter (D-10) — and close the headline
sanitization hole first, because this is the plan that creates the exploit condition for it.

`renderOperatorView` sanitizes every FIELD value through `sanitizeViewValue` but writes the HEADLINE
raw. That has been safe only because all 15 existing headline producers interpolate CLI flag values
and counts, never stored record content — an invariant written down nowhere and enforced by nothing
(issue #505, threat lineage T-06-03). `engram get`'s headline is the first to be built from a live
record's state, so the fix is a precondition of shipping this verb, not smuggled hardening.

Purpose: SC2 names `engram get` and it does not exist; `GetMemory` is the only place a hidden record
is reachable by id with no flag at all.
Output: one verb, one structural one-line fix, and a regression test that stops the invariant from
being conventional.
</objective>

Define `getCmd` with `Use: "get <id>"`, `Args: cobra.ExactArgs(1)`, and a `Short` that states it
fetches one memory by id or short id and renders its full state. **One id only** — multi-id was

record, so `engram get` always returns full content, matching the `get_memory` MCP tool.

`RunE` follows `client_list.go`'s skeleton exactly: `clientFromFlags(cmd)` for the client, format and
timeout; `context.WithTimeout(cmd.Context(), timeout)` for the deadline — the single resolution
point, never a second one; `client.GetMemory(ctx, connect.NewRequest(&engramv1.GetMemoryRequest{Id: args[0]}))`;
`wrapRPCError(err)` on failure with no retry. There is no `--scope` precondition — `GetMemory` is
addressed by id — so skip `requireScopeUnlessCrossSpine` entirely.

followed by the canonical-order state words in parentheses, comma-SPACE-joined, when

comma-NO-space join: the table cell is optimised for `cut`/`awk`-style piping, the headline is
prose. Both draw from the same `memoryStateWords`, which is what makes the two CLI views agree.

In the `format == formatText` branch, marshal `resp.Msg.GetMemory()` with

`schema_version` and `summary_model` `optional`, and protojson omits an unset `optional` field even
under `EmitDefaultValues`.

In the json branch call `renderJSON(cmd.OutOrStdout(), resp.Msg.GetMemory())` — the MEMORY, not the
response wrapper. Both lanes must serialize the same value with the same options or the text/json

every operator-tier gate — including the view-fixture coverage gate, which would then demand a
fixture entry this command should never have.
