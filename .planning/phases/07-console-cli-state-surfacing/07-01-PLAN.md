## Codegen re-vendor is destructive — the DAG serializes UI compilation around it

`ui/src/lib/gen/engram/v1/engram_pb.ts` is briefly ABSENT while `task proto:gen` runs. Any plan

(**07-02**, **07-04**, **07-07**). The phase DAG is arranged so no re-vendoring plan and no
UI-compiling plan ever share a wave: `07-01` (w1) → `07-03` (w2) → `07-02`, `07-05` (w3) →
`07-06` (w4) → `07-04` (w5) → `07-07` (w6). The edges `07-02 → 07-03` and `07-04 → 07-06` exist
for this reason and no other; they are tooling-ordering edges, not semantic dependencies, and each
is labelled as such in the depending plan. Do not "optimise" them away by moving a console plan
back into a re-vendoring wave.

## Flagged assumptions (unresolved — carried, not dropped)

- **A-01 (UI-SPEC `partial` / E1+E5, unresolved).** The UI-SPEC leaves open whether a record surfaced
  by one include-flag should render a *different* state's marker, or be filtered out. This plan
  implements **reveal semantics**: each flag removes one `Must` condition, which widens the result
  set and never narrows it, so every state word a returned record carries is rendered regardless of
  which flag revealed it. That reading is grounded in D-02 ("false meaning today's behavior") and is
  structural in the Qdrant filter, but the UI-SPEC did not lock it, so it is recorded here as an
  assumption rather than authored as a resolved criterion.
- **A-02 (edge probe row 7, `unclassified`).** The edge probe could not classify
  `REQ-migration-state-visible`. No edge truth is minted for it. The planner's reading is that its
  edge surface is the zero/absent/future bucket cases plus banner-and-footer silence at zero, which
  07-06 and 07-07 cover as ordinary acceptance criteria — but that is a planner inference, not a
  probe-derived classification.
