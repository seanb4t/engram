Give the operator the switch. Three include-state toggles in `ScopesSidebar` (D-16), round-tripped

uses, and threaded into `listMemories` so the console can reach the records 07-01 made reachable.

already see — which excludes the archive tier entirely, since nothing links to an archived record.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| URL query string → console filter state | An operator-supplied (or shared/bookmarked) URL controls which include flags are set |
| browser → `ListMemories` RPC | The three flags travel as request fields to the recall gate |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-13 | Tampering | `parseObserveParams` `inc` parameter | low | mitigate | The parse filters `inc` values against the exported `INCLUDE_STATES` list, mirroring how `cat` is filtered against `CATEGORIES` today, so a crafted URL cannot inject an unrecognised value into the request. A test asserts the unrecognised value is dropped. |
| T-07-08 | Information Disclosure | include flags on the console lane | medium | accept | A crafted URL can set all three flags, but the flags relax only state conditions — the server's owner/shared authz filter is unconditional (D-04), so no URL reaches a record the caller could not otherwise read. Enforcement lives in `internal/store`, never in the browser; the console cannot widen its own authorization. |
| T-07-14 | Spoofing | shared/bookmarked console URLs | low | accept | A shared URL carries filter state only — no credential, no scope grant. The recipient sees whatever their own session is authorized to see under those filters. This is the existing property of every `scope`/`cat`/`vis` parameter and is unchanged here. |
