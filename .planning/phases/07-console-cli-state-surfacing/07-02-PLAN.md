<objective>
Make a record's archived / superseded / expired / scheduled state legible in the operator console:
state marker badges plus a dim-iff-past row treatment in `MemoryRow`, and an always-present
`schema` chip plus a dedicated State section in `MemoryDetail` (D-13, D-14, D-15).

This plan is independent of every proto change in this phase. Phase 5 already landed all eight
record-state fields on `engramv1.Memory` and the console's vendored TypeScript types already carry
them — the console work here is purely rendering fields that are already on the wire and already
fetched.

Purpose: close the half of `REQ-console-record-state` that needs no new transport.
Output: a mixed list where an operator can tell at a glance which records are history, and a detail
pane that answers "superseded by what?" in one click.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server response → browser DOM | Record-derived values (ids, timestamps, short handles) are rendered into the detail pane and list rows |
| console user → `GetMemory` | Activating a successor link issues a fetch for a record the caller may not be authorized to read |

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-07-07 | Information Disclosure | `MemoryDetail` successor/predecessor links | medium | mitigate | The link renders unconditionally from the id the record already carries; the caller learns nothing new from its presence. An unreadable target fails on activation through the existing 404-indistinguishable envelope (`DEC-xa6`). Conditionally suppressing the link would convert link presence into a readability oracle — the acceptance criteria forbid that path. |
| T-07-09 | Tampering | `MemoryRow` / `MemoryDetail` state rendering | low | mitigate | Every state word is drawn from a four-member fixed vocabulary in `memorystate.ts`; no record-controlled string reaches a badge or a State-section label.
