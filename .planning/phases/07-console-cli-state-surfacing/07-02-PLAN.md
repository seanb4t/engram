<objective>
Make a record's archived / superseded / expired / scheduled state legible in the operator console:
state marker badges plus a dim-iff-past row treatment in `MemoryRow`, and an always-present
`schema` chip plus a dedicated State section in `MemoryDetail` (D-13, D-14, D-15).

This plan is SEMANTICALLY independent of every proto change in this phase. Phase 5 already landed all
eight record-state fields on `engramv1.Memory` and the console's vendored TypeScript types already
carry them — the console work here is purely rendering fields that are already on the wire and
already fetched. The `depends_on: ["07-03"]` edge is a tooling-ordering edge only; see "Why this plan
depends on 07-03" below.

Purpose: close the half of `REQ-console-record-state` that needs no new transport.
Output: a mixed list where an operator can tell at a glance which records are history, and a detail
pane that answers "superseded by what?" in one click.
</objective>

readability-probe hazard the next paragraph forbids. A truncated UUID prefix is not a valid

characters. Give the link `break-all` (or the wrapping utility already used on the Meta tab's scope
line at `MemoryDetail.svelte:121`) so a long id wraps inside the pane instead of overflowing.

orthogonal to state (D-04), a target the caller cannot read fails on activation through the existing

readability probe.
