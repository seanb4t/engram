4. Set-difference eligibility for the manifest path — **the derivation, stated as three set operations over ids, exactly mirroring `Store.ApplyPurge`'s (spine.go) `Deleted`/`Spared`/`Appeared`** (REVIEWS.md C4-H5, C4-L6):
   - `manifestIDs` := `maps.Keys(opts.Manifest)` — the previewed set.
   - `observed` := the ids the fresh full-backlog scroll actually yields. **Every id in `observed` is below-target by construction**, because the scroll runs `backlogFilter(target)` (migratebacklog.go:58-70), whose only arms are `Lt(schema_version, target)` and `IsEmpty(schema_version)`.
   - `Migrated` (written) := `observed ∩ manifestIDs`.
   - `Appeared` := `observed \ manifestIDs` — accumulated INSIDE the loop (these records are present in the scroll, so the loop can see them). Not written.
   - `Spared` := `manifestIDs \ observed` — computed ONCE, AFTER the scroll is exhausted. **It CANNOT be accumulated in the loop**: a manifest member that was stamped current between preview and apply no longer matches `backlogFilter`, so Qdrant never returns it and no loop body ever runs for it. A loop-local `if inManifest && !belowTarget { … }` branch is unreachable dead code and the test that requires observing it cannot pass — this is exactly the defect REVIEWS.md C4-H5 names.
   - Sort `Spared` and `Appeared` before returning, so two runs over the same state produce byte-identical results (`PurgeResult`'s determinism convention).
   - **Documented semantic, copied verbatim from `PurgeResult.Spared`'s own doc comment:** a manifest member absent from the fresh backlog is "eligible at preview, ineligible **(or already gone)** now". This apply pass deliberately does NOT distinguish "stamped current by a concurrent writer" from "deleted" — both mean *not migrated by this apply*, which is the whole fact `Spared` reports, and distinguishing them would cost one id-addressed probe per spared record for no operator-visible gain. Write this sentence into the field's doc comment, and pin the semantic with a test (step 12b below) rather than leaving it accidental.
   - `opts.Manifest` values (`migrate.Version`) are the previewed FROM-version and are informational only; eligibility is decided by the fresh scroll, never by the recorded version. Say so in the field doc, so nobody re-derives eligibility from the manifest's stale versions.
5. Implement the MANIFEST-LIMITED APPLY path as a SINGLE PASS (REVIEWS.md H7 resolution — the PA-3 guard must not fire on Appeared records):
   - When `opts.Manifest != nil`, do NOT enter the re-derivation loop (`for {}`). Instead:
     a) Perform one exact Count (backlogFilter) to capture the pre-migration backlog for telemetry.
     b) Page through the ENTIRE backlog (like DryRun — full-backlog Scroll via next_page_offset until exhausted). For each point: record its id into `observed`; if the id is in the manifest, run the chain and migrate it via SetPayload (counting `res.Migrated`); if it is NOT in the manifest, append it to `res.Appeared` and skip it without writing.
     c) After the full scroll, compute `res.Spared = sort(manifestIDs \ observed)` and `sort(res.Appeared)` (step 4).
     d) Perform ONE MORE exact Count to get the true post-apply backlog. Set `res.Backlog = postApplyCount` — the TRUE count, which includes Appeared records that were intentionally not processed. Do NOT subtract Appeared from Backlog.
     e) Return — there is no second pass, so PA-3 never fires. The single-pass approach is explicitly chosen because manifest-limited apply is a deliberately bounded operation (process exactly the previewed set), not a convergence-driven sweep.
   - Add a doc comment to the manifest branch explaining why it diverges from the re-derivation loop (H7 resolution) AND why `Spared` is a post-scroll set difference rather than a loop classification (C4-H5).
