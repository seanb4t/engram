## Phase-wide gate invariants (apply to ALL FOUR plans, stated once here)

These four rules bind every task in every plan of this phase. A violation is a defect even where no
reviewer has named the specific site.

**INV-1 — Every task's `<verify>` runs its package UNFILTERED, and no task's gate may reference an
artifact a LATER task produces.**
Every task's `<automated>` block contains a bare `go test ./<pkg>/ -count=1` for each package it
edits, so a task that registers a command without the registry rows keyed on it cannot pass its own
gate. Consequently a gate measuring a symbol, toolclass row, flag, or command declared in a later
task is unsatisfiable, and the artifact and the gate on it land in the SAME task. This covers
`-run` selectors (a name that does not exist yet silently matches nothing and reports PASS, which is
worse than RED) and bidirectional set-equality registries (a registry entry naming a command not yet
in the live tree fails the *other* direction).

**INV-2 — Every negative gate matches the PROPERTY, not the NAME, and no comment can fail it.**
Permitted shapes only: declaration-shaped (`^\s*Field\s+Type`, `^var name`, `func name(`),
call-shaped (`\.Method\(`, `&varName`), composite-literal / row-shaped (`Field: value,`,
`enclosingFunc: "X"`), import-shaped (`"os/signal"`), or a section-scoped Go assertion.
**The comment-stripping idiom `rg -v '^\s*//' FILE | rg PAT` is FORBIDDEN phase-wide**: it strips
only FULL-LINE comments, so a trailing comment on a code line survives it and fails the gate — and
trailing comments are exactly what these plans instruct the executor to write. Bare-name and
bare-phrase negative greps are likewise forbidden; if a property cannot be expressed in a permitted
shape, assert it with a Go test instead of a grep, or drop the gate and rely on the behavioural
assertion that already proves it.

**INV-3 — A `-run` name resolves, and a count is not a proxy.**
Every test name in a `-run` selector resolves to a shipped `func Test…` or to a test the same task
creates, AND the creating step mandates that exact function name. Counts use `rg -o … | wc -l`,
never `rg -c` (which counts LINES). A selector must be able to go RED for the reason it was written:
in `cmd/engram`, `-run TestMigrate…` also matches five shipped owner-migration tests
(`cmd/engram/migrate_test.go:71,86,104,133,145`), so this phase's new CLI tests use the
**`TestMigrateFamily…`** prefix and selectors name that prefix.

**INV-4 — A plan does not describe itself.**
No plan states a count of its own gates, files, or tasks; restates what an adjacent table already
says; or cites a line number inside a PLAN document. Line anchors into SHIPPED SOURCE are
load-bearing for the executor and are kept (and re-verified); anchors into `.planning/**` are not.
