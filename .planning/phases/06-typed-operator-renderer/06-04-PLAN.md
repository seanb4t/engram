<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Qdrant payload -> operator CLI process | Version histogram counts and revert refusal text originate from the store layer. |
| `store` package types -> operator serialization | Until this plan, `migrate status` serialized a store type directly, so any field added to `store.MigrateStatusResult` would have been disclosed automatically. |
| operator CLI process -> terminal / pipe / log | Rendered bytes reach a device that interprets control sequences. |

| T-06-01 | Information Disclosure | `migrateOutputDoc`, `revertOutputDoc` | high | mitigate | Both remain hand-declared structs carrying counts, a version integer, and the refusal string only — no record content. Task 1 changes no field, verified by the `git diff` criterion. |
| T-06-08 | Information Disclosure | `revertOutputDoc.Refusal` | medium | accept | The refusal string is `store.RevertRefusalError(plan).Error()`, which names version numbers and candidate counts — operator-tier facts the plan itself already computed. It carried the same string in the json lane before this phase. |
| T-06-03 | Tampering | rendered values in this group | medium | mitigate | Inherited from plan 06-01: `sanitizeViewValue` strips C0 controls and DEL from every rendered value, including the multi-clause refusal string. |
| T-06-SC | Tampering | package-manager installs | low | accept | No installs — Go source edits and one new test file. |
