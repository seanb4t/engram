## Conversion Rules

**This section is the single normative statement of the per-report conversion recipe. Plans 06-03,
06-04, 06-05 and 06-06 cite it as `06-01-PLAN.md §Conversion Rules` and MUST NOT restate its body.**

- **R1 — Headline trim.** A report's existing `xxxSummary(...) string` becomes a *headline producer*:
  keep the function, its signature, its purity, and its FIRST line only. Delete the loops and the
  appended blocks that emitted per-row lines, notice lines, and re-run lines — the view renders those
  from the document now. The function must return a single line with no trailing newline. Per D-04
  the headline is additive prose over a complete table and is explicitly non-exhaustive.
- **R2 — Gap closure, never gap dropping.** If the pre-conversion sentence stated a fact that is
  neither present as a key in the report's doc struct nor derivable from one that is (a rendered
  list's own length is derivable; a re-run command string is not), ADD that fact to the doc struct as
  a new JSON key. Never delete the fact from the headline to make it fit. This is an additive JSON
  key: no existing key, tag, or value changes. 06-CONTEXT.md `<specifics>` blesses exactly this for
  `spineScanReportDoc` gaining `scope`.
- **R3 — Fixtures.** Each conversion plan adds its OWN `cmd/engram/operator_view_<group>_test.go`
  declaring `<group>ViewFixtures() map[string][]any` keyed by `commandKey` (for example
  `"spine-review scan"`), with one or more sample documents per key, and a
  `Test<Group>ViewIdentity` that calls `assertViewIdentity` for every fixture. Conversion plans do
  NOT edit `cmd/engram/operator_output_test.go`; plan 06-07 merges the group functions and adds the
  both-directions enumeration gate.
- **R4 — Structural pinning only.** Per D-08, no test asserts an exact rendered text string or byte
  sequence for a report, and no `testdata/*.golden` file is created for text output. Assert line
  counts, line prefixes, ordering, and presence of a substring the headline is documented to carry.
  The JSON lane keeps its existing assertions unchanged.
- **R5 — Call sites keep their shape.** `renderOperator(cmd, format, <headline>, <doc>)` stays a
  four-argument call at every site. No call site is deleted, added, or reordered by a conversion.

## Planner decisions recorded here (Claude's Discretion, 06-CONTEXT.md)

- **Walk the marshaled bytes, not the Go struct.** `viewFields` calls `json.Marshal(doc)` once and
  walks the resulting bytes with `encoding/json`'s streaming decoder. Reflecting over the Go struct
  instead would require reimplementing `encoding/json`'s tag semantics (`omitempty`, `-`, embedded
  promotion, custom `MarshalJSON` on types such as `time.Time`) and would drift from them. Walking the
  marshaled bytes makes D-02's "identity by construction" literally true rather than nearly true.
- **Manual rune-counted column padding, not `text/tabwriter`.** tabwriter was the obvious candidate
  and was rejected: its column blocks terminate at any line that does not carry the same cell count,
  and D-07's nested row lines are exactly such lines, so a report's label column would silently
  re-align around each nested block. A label column width computed once per report is simpler and
  stable. Padding counts runes with `utf8.RuneCountInString` — the same measure tabwriter itself uses
  — so this inherits tabwriter's wide-character limitation rather than a worse one.
- **No initialism table in the humanizer.** `humanizeKey` is underscore-to-space plus a capitalized
  first letter and nothing else. No top-level key in the operator tier is an initialism, and nested
  row keys render raw per D-05, so an acronym table would be untested dead code. `top_k` renders as
  `Top k`; that is accepted on an explicitly-unstable lane.

Declare `func viewFields(doc any) ([]viewField, error)`.
