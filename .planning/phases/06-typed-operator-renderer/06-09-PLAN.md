  <action>
**The gate's unit is a `(command, variant)` pair, not a command.** This is the correction
`06-REVIEWS.md` HIGH-3 demands. The first-cycle design mapped each command to "the variant exercising
the most fields", which left every other shape structurally ungated — `revertSummary`'s refusal,
preview and applied shapes (`cmd/engram/migrate_family.go:386`) and purge's preview-versus-applied
templates (`cmd/engram/spine_review_purge.go:276` and `:294`) among them — while the plan claimed
tier-wide D-03 coverage. The claim must not be broader than the gate.

**Both halves of the pair are derived from production source.** This is `06-REVIEWS.md` cycle-2
HIGH-2's option (a), chosen over its option (b) (an AST gate over builder branches, which this
subsumes) and its option (c) (accept the residual and prove its boundary, which would have left the
hand-listed-universe failure family intact one level above the comparisons). The reason it is now
reachable: 06-01 moved each variant's identity into production code, so `operatorReport("prune-expired",
"preview", ...)` is a source-level fact a parser can enumerate — exactly as `operatorCommands()`
enumerates the cobra tree. The first-cycle design reconciled three hand-written test-side
representations against each other and could stay green under a synchronized omission; there is now
only one representation, and it is the code that runs.

Create `cmd/engram/fieldset_registry_test.go` with
`derivedReportVariants(t *testing.T) map[string][]string`: parse every non-`_test.go` `.go` file in
`cmd/engram` with `go/parser` (`parser.ParseDir` or a `parser.ParseFile` loop, `parser.SkipObjectResolution`
is fine — no type checking is needed), walk each file with `ast.Inspect`, and for every `*ast.CallExpr`
whose function is the identifier `operatorReport`, read arguments 0 and 1. Each must be an
`*ast.BasicLit` of `token.STRING` or a constant concatenation of them; anything else fails the test
naming `fset.Position(call.Pos())`. Argument 2 — the template — carries the same constant requirement,
which is what stops one call site from serving two shapes behind a computed string. Collect the results
as `(key, variant)` pairs, failing on any duplicate pair with both positions named, and failing if the
collected set is EMPTY — a parse that matches nothing must be loud, since a silent zero is this repo's
recorded fail-open shape (record `bqpfcnrnjs`). In the same walk, fail on any selector expression
naming `fieldset.New`, `fieldset.NewLabeled`, `fieldset.MustNew`, or `fieldset.MustNewLabeled` from a
function other than `operatorReport` or `operatorRow`: that rule is what makes the enumeration
exhaustive rather than merely broad, because it removes every other route to a constructed report.

Put the reasoning in the file's doc comment so a reviewer reads it rather than inferring it, including
the two residuals from this plan's `must_haves`: the walk reads source text rather than the compiled
call graph (over-inclusive, fails closed), and constant-argument enforcement is what closes the
one-call-site-two-templates hole.

Write `TestFieldSetRegistryCoversEveryOperatorCommandAndVariant` asserting the rules above plus THREE
exact set equalities, each with `slices.Equal` over sorted, dedup-checked slices, each reporting every
mismatched element by name — never a count, never a partition identity, never a one-directional
containment check, because this project has a recorded case where a partition identity stayed invariant
under the very mutation it appeared to guard and only exact set equality survived:

1. **Command universe.** `commandKeySet(operatorCommands())` — the live cobra-tree walk — set-equal to
   the key projection of the derived pair set.
2. **Variant universe.** The derived `(key, variant)` pairs, set-equal to the `(Key, Variant)` pairs
   `operatorReportFixtures()` carries. `TestOperatorReportGoldenSetIsComplete` already holds that
   fixture set equal to the checked-in golden files in both directions, so this equality joins two
   independently derived universes to the complete golden set — and unlike the first-cycle version,
   neither side of this equality is hand-maintained test metadata.
3. **Construction.** In a subtest per `(key, variant)` pair — not per command — invoke that fixture's
   `Report()` and assert it is a validated `fieldset.Set` whose `Label()` is exactly
   `<key>/<variant>`, and that it renders both lanes without error. Since after 06-01 the only way to
   obtain a `Set` is a validating constructor, a builder that would widen cannot return; the subtest's
   job is to prove every pair's builder is actually EXERCISED and that the label the AST read matches
   the label the runtime carries, which is what turns the tier-wide coverage claim from prose into a
   gate.
