Create `cmd/engram/fieldset_registry_test.go` declaring `fieldSetReports() map[string]func() FieldSet`,

builder with representative deterministic inputs. Where a command has several sentence variants, map it

so this registry's job is command coverage, not variant coverage.

The table is hand-authored deliberately. RESEARCH.md's third open question asks whether that is a
legitimate continuation of D-07, and the answer recorded here is yes: it lists which CONSTRUCTOR to
call and never a fact string. D-07's objection was to hand-listed facts, which under-list silently. A
command-to-constructor mapping cannot under-list silently, because the gate below holds it set-equal to
a universe derived from the live cobra tree — hand-written, but derived-CHECKED. Put that rationale in
the file's doc comment so a reviewer reads the reasoning rather than inferring it.

Write `TestFieldSetRegistryCoversEveryOperatorCommand`: build the want set with
`commandKeySet(operatorCommands())`, build the got set from the registry keys, sort both, reject
duplicates, and assert exact `slices.Equal` set equality, reporting every mismatched key by name. Never
a count, never a partition identity, never a one-directional containment check — this project has a
recorded case where a partition identity stayed invariant under the very mutation it appeared to guard,
and only exact set equality survived. Then, in a subtest per key, invoke the builder and assert
`validateFieldSet` returns nil, so tier-wide coverage is asserted from the derived universe.

Then retire the superseded gate: delete the parity test function, its row type, its row-building
function, and the scalar-value and containment helpers that exist only to serve it, all from
`cmd/engram/operator_output_test.go`. The compiler is the completeness check — a helper still used
elsewhere refuses to disappear, and a leftover reference fails the build.

Record in `06-09-SUMMARY.md`, per D-07, the two properties of the retired gate that must not be lost:
its fact strings were hand-listed, precisely the test-over-hand-built-rows Success Criterion 1 rejects;
and it was one-directional, asserting only that every declared text fact appeared somewhere in the
json, never that the json failed to widen past the text. State explicitly that the new mechanism closes
the second direction and that the deleted gate is recoverable from git history.
