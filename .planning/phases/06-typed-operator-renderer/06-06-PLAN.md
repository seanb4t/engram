<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Qdrant payload -> operator CLI process | Record ids, short ids, scopes, categories and citation refs in scan, consolidate and verify rows originate from callers. |
| filesystem -> `verifyReport` | Verify reads cited files and computes a `Reason`; the report type deliberately excludes the `Excerpt` it read. |
| operator CLI process -> terminal / pipe / log | Rendered bytes reach a device that interprets control sequences. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-01 | Information Disclosure | `spineScanReportDoc`, `consolidateReportDoc`, `verifyReportDoc` | high | mitigate | All three remain hand-declared structs. `verifyReportDoc` in particular carries counts, ids, refs and reasons only and NEVER the `Excerpt` — Task 2 strengthens that comment to state that under D-01 the exclusion now bounds the text lane too. Verified by the `git diff` criteria showing no field change in any of the three. |
| T-06-10 | Information Disclosure | `spineScanReportDoc.Scope` (new key) | medium | mitigate | The value is the operator's own `--scope` flag, a scope identifier and never record content. It was already printed verbatim in text mode; adding it as a key closes a text/json gap rather than opening a disclosure. The field is a plain `string`, not a store type. |
| T-06-11 | Information Disclosure | `verifyEntryDoc.Reason` rendered inline in a row | medium | mitigate | `Reason` is a diagnostic sentence computed by verify (for example "excerpt found at byte offset 12, not at the cited locator"), never the excerpt itself. Rendered through `sanitizeViewValue`, so a reason containing a newline cannot forge an additional entry row that appears to name a record verify never examined. |
| T-06-03 | Tampering | rendered scope, category and ref values in this group | medium | mitigate | Inherited from plan 06-01: `sanitizeViewValue` strips C0 controls and DEL from every rendered value. Scan's breakdown rows carry caller-supplied scope and category strings, which is the tier's largest free-form surface. |
| T-06-SC | Tampering | package-manager installs | low | accept | No installs — Go source edits and one new test file. |
</threat_model>
