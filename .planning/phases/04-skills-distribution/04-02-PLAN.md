<objective>
Build the second of this phase's two genuinely new mechanisms: splicing a delimited, re-detectable
block into a file engram does not own, without disturbing one byte outside it — and give that block
its content by adding one authored index line to each shipped `SKILL.md` at the Agent Skills
specification's own extension point.

The AGENTS.md splice is where "content outside the block is left byte-for-byte untouched" is hard to
honor, and it is the one place in this phase where engram writes into a file a dotfiles manager may
own. Both halves of that risk are already locked: hard-fail on any ambiguous state (D-15), and an
in-place write that follows a symlink rather than replacing it (D-16).

Purpose: the mechanism must be complete and proven before plan 04-03 decides which runtime routes to
it, so the routing decision is about product shape rather than about whether the machinery works.

Output: `internal/skills/frontmatter.go`, `internal/skills/agentsmd.go`, the `metadata` index entry
in all five shipped skills, a re-vendored `internal/skills/data`, and one promoted direct dependency.
</objective>

`internal/skills/agentsmd.go` — new file.

Declare the fixed, parameterless marker pair as exported constants, following the repo's existing
HTML-comment convention `engram:<domain>:start` and `engram:<domain>:end` with the domain `skills`.
There is exactly one skills block per file, so no per-identifier parameterization is needed — state
that in the constants' doc comment, and state that the literals are a published on-disk surface
because they persist in a user's own file.

Declare a three-value state enum for the scan result — absent, well-formed, malformed — as explicit
values, never modeled as an absence or the zero value, following `plan.go`'s `Outcome` doc-comment
discipline.

Write an unexported `scanBlock(content []byte)` returning the state, the byte offset and length of
the start marker line, the byte offset and length of the end marker line, and the byte offsets of
every marker occurrence found. Imitate `scanAnchors`' pending-pair state machine — track whether a
start has been seen and whether an end has been seen, so "neither seen" is distinguishable from
"seen but ill-paired" — but scan by byte offset rather than by line index alone, because D-15
requires the offending marker OFFSETS in the failure text and the existing scanner surfaces only a
file path and an identifier. A marker is recognized when a line, after trimming leading and trailing
whitespace, equals the marker literal exactly. Classify: neither marker seen is absent; exactly one
start then exactly one end with nothing else is well-formed; every other shape is malformed —
including a second start before the first end, an end with no open start, and a start never closed
before the end of the content.

Write `RenderBlock(skills []Skill, skillsDir string) string` producing the block, deterministic and
newline-terminated: the start marker line; one line naming this block as managed by `engram setup`
and stating that edits inside it are overwritten; one line per skill in inventory order carrying the
skill's name, its authored index entry, and the absolute path formed by joining `skillsDir`, the
skill name, and the skill's own `SKILL.md`; then the end marker line. The full text of a skill is
never inlined — the whole point of the index is that the agent fetches a procedure on demand, and
inlining the five would add roughly fifteen thousand tokens to every session on that runtime,
permanently (D-13).

Write `Splice(content []byte, block string) ([]byte, error)`. On the absent state, append: when
`content` is empty, the result is exactly `block`; otherwise the result is `content`, then a newline
if `content` does not already end with one, then a blank line if `content` does not already end with
a blank line, then `block`. On the well-formed state, replace only the bytes strictly between the end
of the start marker line and the beginning of the end marker line with the block's own interior
lines, preserving both marker lines verbatim. On the malformed state, return a nil slice and an error
whose text names the state and every offending byte offset; a caller must be structurally unable to
obtain content to write from a malformed input. Never collapse duplicates and never treat an
unmatched marker as absent — engram must not silently rewrite a region of a file it did not author,
which is the exact promise the requirement exists to make.

Do NOT import `internal/surfaces` and do NOT call its region writer. Its documented behavior rewrites
the body inside every matched pair, which is the opposite of D-15's hard failure on two or more
pairs. Record that in this file's package-level comment so a future contributor does not "unify" the
two implementations and silently inherit the wrong invariant.
