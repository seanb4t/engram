prefixed directive over `data`, and carry a rationale comment in the same style as the webauth

`internal/skills/inventory.go` — new file. Define `File` with `Path string` (the slash-separated
path RELATIVE to the skill's own directory, e.g. `SKILL.md`) and `Content []byte`. Define `Skill`
with `Name string` and `Files []File`. Export `Inventory() ([]Skill, error)`: walk the embedded FS
under `data` with the stdlib directory walker, treat each immediate child directory of `data` as
one skill, and collect every regular file beneath it. Sort skills by `Name` and each skill's
`Files` by `Path` so the result is deterministic. Nothing in this file, or its tests, may name a
count or a fixed list of skill names — the inventory is structural (D-04). Return an error when the
walk yields zero skills: an empty inventory means the embed broke, and it must fail loudly rather
than install nothing successfully.

Also in `inventory.go`: export `Digest(s Skill) string` returning the first 12 lowercase hex
characters of a SHA-256 over that skill's own files, computed by writing, for each file in sorted
`Path` order, the path bytes, a NUL byte, the content length in decimal, a NUL byte, the content,
and a NUL byte — length-prefixed and NUL-separated so no path/content boundary is ambiguous.
Document that the truncation is deliberate and that this digest is a display and cross-machine
comparison aid, never a security boundary. Export `TotalBytes(skills []Skill) int` summing every
file's content length, and `ContentJSON(skills []Skill) (string, error)` returning a MINIFIED
single-line JSON object keyed by `<skill-name>/<file-path>` with the verbatim file content as the
string value — a Go string, never a map or a raw-message type, so the value can never bypass the
operator renderer's scalar-only sanitizing branch, exactly as `Plan.Config` already does.

`internal/skills/install.go` — new file. Define `Format` as a string enum with three explicit
values: a "no filesystem destination" case, a "native" case, and an "agents-md" case. Every value
is REAL and explicit — never modeled as an absence or the zero value, per `plan.go`'s own `Outcome`
doc comment. Define `Target` with `Format Format`, `Dir string` (absolute), and `IndexFile string`
(absolute; meaningful only for the agents-md case, which Wave 2 implements). Define `Report` with
`Wrote []string`, `AlreadyCorrect []string`, and `Err error`.

Export `Install(env Environment, target Target, skills []Skill) Report`. This task implements the
native case only; the agents-md case returns a Report whose `Err` states it is not wired yet, and
the no-destination case returns an empty Report with a nil `Err` (it has nothing to write). For the
native case, for each skill in inventory order and each file within it: join `target.Dir`, the
skill name, and the file's relative path; create the parent directory; read the existing file; when
the read succeeds and the bytes are equal to the embedded content, append the path to
`AlreadyCorrect` and write nothing; otherwise write the embedded content unconditionally and append
the path to `Wrote`. Accumulate every error into a slice and join them once at the end, so a failure
on one skill never skips a later skill and never discards an earlier skill's success (D-07). A read
error that means "the file does not exist" is NOT an error — it is the write case.

`internal/setup/aggregate.go` — new file, a pure classification with no I/O, mirroring `exit.go`'s
posture so the whole table is unit-testable with no fake. Export `SkillsOutcome(format SkillFormat,
mutate bool, wrote int, alreadyCorrect int, failed bool) Outcome` encoding, in this precedence: the
no-destination format always yields the would-write value in BOTH lanes (it never writes and never
converges — the same reasoning the executor already applies to a zero-Actions plan); a failure

wrote value; otherwise any already-correct files yield the already-correct value; and a call

empty inventory is a broken embed and must never be laundered into success. Export

documented precedence `failed > wrote > already-correct > would-write > not-present`, and treating
the zero value or any unrecognized value as the failed value so an unset outcome can never become
an exit 0. State the generalized invariant in the doc comment: mixed state resolves UP to wrote,
never down to already-correct. Do not touch `exit.go`.

<assumption_delta_decision>
The `assumption-delta scan` detector fired on this phase (`detected: true`, two `pluralization`
signals: `fallback` and `second`). One core assumption genuinely lost its monopoly.

**The noun that is now primary:** a runtime row's `outcome` is now **the per-runtime SETUP
outcome**, not the per-runtime REGISTRATION outcome. Until this phase, `Result.Outcome` had exactly
one producer — registration — so "the outcome" and "the registration outcome" were the same value
and nothing distinguished them.

**Decision: `promote`.** D-06 already encodes it and this plan implements it as stated: the row's
single `outcome` is promoted to the general per-runtime setup outcome, aggregated from facets by an
authored precedence, and registration is demoted to one facet among two, reported as an ordinary
`registration=` row field alongside `skills=`. It is deliberately NOT an add-alongside: a second
`Result.SkillsOutcome` field consumed by `Classify` was considered and rejected in D-06 because it
reopens the pinned pure function and its exhaustive table, and because a row that carries two
top-level outcomes has no answer for "did this runtime succeed".

**Companion invariant test (accepted, and it is Task 2):** `TestAggregateOutcomeExhaustive` plus
`TestAggregatePrecedenceIsAuthoredNotDerived` encode the generalized intent over the whole input
space. They go red the instant a future phase reintroduces the singular assumption — for example by
letting a third facet bypass aggregation and write `outcome` directly, or by resolving mixed state
down to `already-correct`.

**What is explicitly NOT promoted:** the five-value `Outcome` vocabulary itself, `Classify`, and
`exit.go`. D-06 and D-16 of Phase 3 both pin them, and this plan's acceptance criteria assert they
are byte-identical afterwards.
</assumption_delta_decision>
