<objective>
Build the retrieval-quality eval harness (REQ-retrieval-eval) — the measurement
instrument the rest of the phase depends on. It is a straight structural copy of
the established `eval:summary` pattern: an env-gated (`ENGRAM_RETRIEVAL_EVAL=1`)
Go test in a new `internal/retrievaleval/` package that boots a Qdrant
testcontainer (reusing `internal/store/store_test.go`'s proven `TestMain`
provisioning), seeds a labeled query→expected-record dataset, embeds queries
through `EmbedQuery` for prod parity (D-05a), and reports `recall@k` / MRR.

The GitHub #261 scenario (Query A/B → Record T + sticky topical-neighbor
distractors) is encoded as a permanent regression fixture. The eval also asserts
the always-on similarity score is meaningful (populated, descending) — the
machine-checkable half of REQ-search-similarity-scores (feeds D-03).

Per D-05, this harness IS the decision mechanism for REQ-ranking-precision:
Plan 03's ranking approach is chosen by these numbers, not assumed. This plan
captures the post-#262 baseline; it does not hard-fail on the #261 quality bar
(that becomes Plan 03's acceptance gate).

Purpose: make recall measurable so ranking and embedding changes are measured,
not guessed (D-05).
Output: `internal/retrievaleval/` package + `task eval:retrieval` target.
</objective>
