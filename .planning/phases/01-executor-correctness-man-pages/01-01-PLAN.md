<objective>
Fix GitHub #560: `internal/setup/environment.go`'s `osRun` misclassifies a subprocess killed by its
command-context deadline (or a cancelled parent context) as a clean nonzero exit — `cmd.Run()` returns
`*exec.ExitError{ExitCode: -1}` for a SIGKILLed child, `errors.As` matches it, and the seam returns
`RunResult{ExitCode: -1}` with a **nil** error while `ctx.Err()` is simultaneously non-nil
(01-RESEARCH.md reproduced this live). The fix is a new first `case ctx.Err() != nil:` in `osRun`'s
switch returning `RunResult{}, ctx.Err()` (D-10, D-12), plus a `runSeam` wrap in
`internal/setup/apply.go` that turns `context.DeadlineExceeded` into
`timed out after 20s: context deadline exceeded` so the operator's row names the timeout (D-11).

Purpose: `Environment.Run`'s doc comment (`environment.go:44-49`) already promises "a non-nil error
means the process never produced an exit status at all — it failed to start, or ctx's deadline expired
before it exited". Production violates that contract today, so a hung runtime CLI is reported as
`exited -1` (blaming the third-party tool) and — worse — a timed-out *probe* read can be misread as a
legitimate "not registered" answer that `--apply` then acts on. REQ-osrun-deadline-error.

Output: the three-line `osRun` fix, the `runSeam` wrap (+ `errors` import), a new
`internal/setup/environment_test.go` proving the fix against a REAL child process (the test binary
re-exec'd via `os.Args[0]` — never a third-party CLI, never `$HOME`), and two new fake-`Environment`
subtests in `internal/setup/apply_test.go` pinning the row wording. Independent of plan 01-02; no
shared files.
</objective>

## Prohibition probe (spec-less fallback, in-prompt recall)

Stage 1 raw candidates for REQ-osrun-deadline-error (over-produced on purpose): must not swallow partial
output silently; must not surface partial stdout on the error path; must not retry the child; must not
lengthen or disable `execTimeout` to make the symptom disappear; must not diagnose third-party stderr;
must not report a cancel as a timeout; must not report a timeout as `exited -1`; must not block past
the deadline waiting for pipes; must not leak the killed child (zombie); must not change `RunResult`'s
meaning alongside a nil error. Stage 2 keeps two (authored above in `must_haves.prohibitions`, both
descriptor-less): the **no-retry** safety prohibition and the **never blame the third party for our own
timeout** transparency prohibition. The rest are routine correctness owned by the edge probe / the
tests themselves. Canon breadcrumb: none applies (no injection, traversal, or PII surface here).
