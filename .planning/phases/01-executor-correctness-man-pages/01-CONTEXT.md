# Phase 1: Executor Correctness & Man Pages - Context

**Gathered:** 2026-09-13
**Status:** Ready for planning

<domain>
## Phase Boundary

Two independent, individually shippable fixes, nothing else:

1. **`osRun` deadline classification (#560, REQ-osrun-deadline-error).** `internal/setup/environment.go`'s `osRun` consults `ctx.Err()` before the `errors.As(*exec.ExitError)` branch, so a subprocess killed by its command-context deadline (or a cancelled parent context) surfaces as the seam's own error — never as a clean nonzero exit with a nil error — and `engram setup`'s result row for that runtime names the timeout.
2. **Man pages (REQ-manpages-generated, REQ-manpages-cask-installed).** A new hidden `engram man <dir>` command wraps `cobra/doc.GenManTree` to write one byte-stable roff page per visible command from the live cobra tree; `.goreleaser.yaml`'s existing hand-rolled cask `post_install`/`post_uninstall` hook pair grows a man-page step symmetric with the shipped completions step; `cmd/engram/releaseconfig_test.go` pins ordering and absence the way it already does for completions. `cobra/doc` is promoted from indirect to direct — zero new Go dependencies.

Shell completions are **already shipped** (2026-08-23.01 Phase 1, PR #515) and require no work. Nothing in this phase touches the other Setup v2 features (headers, plugins, drift).

</domain>

<decisions>
## Implementation Decisions

### Man-page determinism & header
- **D-01:** `GenManHeader.Date` is pinned to a **fixed constant** in code (a release-independent date such as the Unix epoch), never left nil. cobra/doc renders `.TH`'s date as `"Jan 2006"` from `time.Now()` when `Date` is nil (honouring `SOURCE_DATE_EPOCH` only as a fallback), so the default is byte-stable merely within a calendar month. No env-var dependency: the cask hook runs on an end user's machine with nothing exported.
- **D-02:** `GenManHeader.Source = "engram <version>"` (the ldflags-injected `main.version`, the same value `rootCmd.Version` and `engram version` already report — a dev build reads `engram dev`) and `Manual = "Engram Manual"`. Re-running the same binary is byte-identical; the version changes only when the binary does.
- **D-03:** `rootCmd.DisableAutoGenTag = true` — set once on the root, propagated to every child by cobra/doc's `VisitParents` walk — so the `# HISTORY … Auto generated by spf13/cobra` footer (the last date-bearing surface besides `.TH`) is dropped from every page.
- **D-04:** Byte-stability is proven by a Go test that runs the generator twice into two temp dirs and requires identical bytes per file, plus asserts the `.TH` line carries the pinned date/Source and that no `HISTORY` footer appears. **No golden files** — a help-text edit must not force a regen across N pages. `cmd/engram/golden_test.go`'s harness is not extended for this.

### Man-page command coverage
- **D-05:** The page set is **cobra/doc's default walk**, unfiltered: every command for which `IsAvailableCommand()` holds and that is not the help command. That means the visible `engram --help` tree **plus the `completion` subtree** (`engram-completion.1`, `engram-completion-zsh.1`, …), and automatically excludes the hidden `man` command itself, `help`, and the `Deprecated`-marked aliases (`backfill-short-ids`, `migrate-set-owner`). No filtering code; `cmdwalk.go` and `internal/surfaces` are untouched.
- **D-06:** A Go test derives the expected set from the live tree — walk `rootCmd` with cobra's own `IsAvailableCommand()` / not-help predicate, expect exactly `<dashed command path>.1` per command — and asserts `engram-man.1` and the deprecated aliases' pages are **absent**. It must not reuse `surfaces_test.go`'s `nonHiddenCommands()` helper, which deliberately skips `completion` and would disagree with D-05.

### Cask install/uninstall shape
- **D-07:** `post_install` generates **straight into** `#{HOMEBREW_PREFIX}/share/man/man1`: `FileUtils.mkdir_p` the directory, then `system_command binary, args: ["man", man1_dir]`. No tmpdir, no copy loop. `system_command`'s default `must_succeed: true` raises on failure exactly as the completions step does — fail-closed, never Homebrew's rescuing helper and never the declarative cask `manpage:` stanza (same `write_completion`-style `rescue` subsystem; research STACK.md).
- **D-08:** `post_uninstall` removes exactly the pages the binary wrote by globbing `engram.1` and `engram-*.1` under `share/man/man1` and calling `FileUtils.rm_f` on each match — the file-scoped remover, never the directory, never `rm_rf`. No install-time manifest. (The binary symlink is already gone at `post_uninstall`, so the set cannot be regenerated there.)
- **D-09:** The man step is **appended after completions** as the hook's fourth exercise of the installed binary: `xattr` strip → `version --output json` gate → completions → `man`. `TestReleaseConfigCaskInstallGate` extends its `checkOrdering` chain by one link (`args: ["completion"` → `args: ["man"`), counts exactly one non-comment `args: ["man"` occurrence, requires the uninstall glob string to appear exactly once, and adds `manpage:` to the forbidden-strings list alongside `generate_completions_from_executable`, `brews:`, `rm_rf`. Because those gates are literal occurrence counts, the hook's **comments must not spell `manpage:`** or name the helper either (same rule the completions comment already follows). — **Reversibility:** reversible — a config + test edit.

### Timeout row wording (osRun)
- **D-10:** `osRun` adds `case ctx.Err() != nil:` as the **first** switch case and returns `RunResult{}, ctx.Err()` — the bare sentinel, covering **both** `context.DeadlineExceeded` and `context.Canceled` (Ctrl-C / parent cancel). Any context termination is "never got an answer" per `Environment.Run`'s documented contract; the narrow deadline-only check was rejected as leaving half the contract violation in place.
- **D-11:** The `timed out` wording lives in `runSeam` (`internal/setup/apply.go`), the sole owner of `execTimeout` (20s): when `errors.Is(err, context.DeadlineExceeded)`, wrap as `fmt.Errorf("timed out after %s: %w", execTimeout, err)`. The row then reads `<runtime>: <argv>: timed out after 20s: context deadline exceeded` via the existing `describeSeamError`. `errors.Is` still resolves for callers; `Canceled` passes through unwrapped.
- **D-12:** The `RunResult` returned alongside a ctx error is the **zero value** — no partial stdout/stderr — matching `RunResult`'s doc ("only ever meaningful alongside a nil error"). Nothing on the error path reads it (`describeSeamError` takes only `err`).

### Claude's Discretion
- How the `osRun` test spawns a real child that outlives a short deadline without invoking any third-party CLI (rule `m45p2b4bp7`): e.g. the test binary re-exec'd as a helper via `os.Args[0]`, or a POSIX `sleep`. Must never touch the operator's `$HOME` or a real runtime CLI (`ryr82bf2s2`).
- Exact `engram man` usage/arg validation (single required `<dir>` arg via `cobra.ExactArgs(1)`; whether the dir is created or must pre-exist — the cask hook `mkdir_p`s first either way), its `Short`/`Long` text, and its file placement (`cmd/engram/man.go` + `man_test.go` per research).
- Where the pinned date constant and header construction live (unexported in `man.go`).
- Whether `engram man` mirrors `completion`'s hidden-ness via `Hidden: true` only (it is excluded from the catalog by `commandWalkSkip` automatically — no `surfaces` classification row, no `help.golden` regen expected; confirm with `task test`).
- Order of the two independent fixes across plans/waves; both are independently shippable.

</decisions>

- `cmd/engram/releaseconfig_test.go` — `readNonCommentLines`-style comment stripping (skips `#{…}` interpolation), `countMatches`, `checkOrdering` (with `TestCheckOrderingCatchesTransposedLines` proving it goes RED), `TestReleaseConfigCaskInstallGate` (`:133-160`: xattr count, ordering chain, forbidden strings, completion paths). Extend, don't fork.
- `.goreleaser.yaml:146-210` — `hooks.post.install` / `hooks.post.uninstall` bodies; the completions loop (`:193-200`) and the three `rm_f` lines (`:208-210`) are the shape to mirror.
- `go.mod:22` — `github.com/spf13/cobra v1.10.2` (main); `go-md2man/v2 v2.0.7` and `mousetrap v1.1.0` already `// indirect` — `go mod tidy` after the `cobra/doc` import should be a no-op beyond promotion.

### Established Patterns
- Hidden/scaffolding commands are excluded from the classified catalog by `cmd/engram/cmdwalk.go:23`'s `commandWalkSkip` (`Hidden || help || completion`) at every depth — a `Hidden: true` `man` command needs no `surfaces` row and no `help.golden` change.
- Deprecation is expressed via cobra's `Deprecated` field (`backfill.go:58`, `migrate.go:270`), which `GenManTree` already skips.
- Cask hooks exercise the **installed** binary (`#{HOMEBREW_PREFIX}/bin/engram`) after the version gate; each added step is another fail-closed proof the shipped binary works.
- Tests fake `Environment` (`withFakeSetupEnv`-style seams) and never invoke a real runtime CLI.

### Integration Points
- `cmd/engram/man.go` (new): `manCmd` with `Hidden: true`, `RunE` → `doc.GenManTree(rootCmd, &doc.GenManHeader{...}, dir)`; registered via `rootCmd.AddCommand` in `init()` like every sibling.
- `.goreleaser.yaml` `hooks.post.install` gains a `man` step after the completions loop; `hooks.post.uninstall` gains the glob + `rm_f` sweep after the three completion `rm_f`s.
- `internal/setup/apply.go:runSeam` gains the DeadlineExceeded wrap; `environment.go:osRun` gains the `ctx.Err()` case.
