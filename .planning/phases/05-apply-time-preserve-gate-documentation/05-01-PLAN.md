Purpose: REQ-apply-preserve-gate closes the 2026-09-10 overwrite incident (gotcha `ryr82bf2s2`)
at its root — the executor never branches on probe content today, so `--apply` still
remove-then-adds over a registration it cannot reproduce. REQ-apply-rewrite-consequence makes

say upfront that an OAuth login will be lost.

Decisions recorded by this plan (Claude's discretion, per 05-CONTEXT.md):
- **RESEARCH Open Question 1 — mechanism for the OAuth note:** a NEW `Observation.RewriteConsequence`
  field (option b), not an extension of `WholeEntryNote` (option a). Rationale: `WholeEntryNote`
  is rendered only on a `preserved` row's `Reason`; the consequence must reach a `would-write`
  row's `Notes` — a different outcome and a different field — so reusing the constant would force
  the executor to slice one sentence per outcome. A dedicated field keeps `apply.go` to one
  generic rule ("would-write + non-empty consequence -> Notes"), keeps `codex.go` free of any
  OAuth text (it leaves the field empty), and is individually testable.
- **D-05 remediation mechanism:** likewise a NEW `Observation.ManualRemediation` field with one
  constant per runtime (`claudeCodeManualRemediation`, `codexManualRemediation`), appended by the
  executor after `WholeEntryNote` when non-empty — the same idiom as `RewriteConsequence`, rather
  than extending the whole-entry constants (RESEARCH A2's minimal-churn option): each sentence
  stays a separately named, separately pinned clause.
- **Sharing the prefix:** one `classification` value computed once from probe1, consumed by both
  lanes; `renderClassification` writes the five classified fields the same way in both lanes.
  The byte-compare tail survives only for the not-compared path.
- **Apply-lane `Facets`/`Drift` on a classified row:** carried (they describe what differed
  pre-write); `Registered` on a `wrote` row is the post-write re-observe (D-02); on
  `already-correct`/`preserved` all four fields are exactly preview's. The not-compared apply
  path leaves `Facets`/`Drift` empty exactly as today (no output change on that path).
- **RESEARCH Open Question 2:** `internal/setupgen`'s generated `/engram-setup` prose is NOT
  touched — it renders argv only and contains no outcome text (grep-confirmed: zero occurrences
  of `already-correct`/`preserved` under `internal/setupgen/` and the slash-command file), so
  nothing there goes stale under D-01; `go run ./internal/surfacesgen --check-setup` must stay
  green with zero drift.

new/retargeted tests across `internal/setup` and `cmd/engram`, and rewritten doc comments in
`plan.go`/`apply.go` that no longer describe the mutate branch as unrewired.
