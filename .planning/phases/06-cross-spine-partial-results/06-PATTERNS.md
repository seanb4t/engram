## Pattern Assignments

### `internal/server/tools.go` — `(*deps).searchedScopes` (`:1840-1855`)

**Analog:** itself (structural amendment) + `connecterror.go`'s `store.ErrResponseTooLarge` arm for the "log server-side, never leak raw text" shape.

**Current shape** (`tools.go:1840-1855`):
```go
func (d *deps) searchedScopes(ctx context.Context, c caller, crossSpine bool) ([]string, bool, error) {
	if !crossSpine {
		return nil, false, nil
	}
	counts, more, err := d.st.ListScopes(ctx, c.Subj)
	if err != nil {
		return nil, false, err
	}
	scopes := make([]string, len(counts))
	for i, sc := range counts {
		scopes[i] = sc.Scope
	}
	return scopes, more, nil
}
```

**D-01/D-02/D-03 requires:** on `d.st.ListScopes` error, do NOT `return nil, false, err` (that is exactly today's discard-on-error path the four callers propagate). Instead: log the cause server-side and return a value the caller cannot silently ignore — a third boolean, a small struct, or a typed sentinel (Claude's Discretion; the four call sites just need to stop treating a non-nil `error` as "abort with an error").

**Server-side logging pattern to copy** (`internal/server/connecterror.go:103-105`, the D-02-equivalent "log cause, keep wire generic" precedent from Phase 2):
```go
case errors.Is(err, store.ErrResponseTooLarge):
	slog.ErrorContext(ctx, "connect handler: response too large", "error", err)
	return connect.NewError(connect.CodeResourceExhausted, errors.New(responseTooLargeEnvelope()))
```
And the MCP-lane sibling (`internal/server/responsetoolarge.go:70-78`):
```go
slog.ErrorContext(ctx, "mcp tool call: response too large", "tool", tool, "error", toolErr)
```
`searchedScopes` is helper-shared by both lanes, so ONE `slog.ErrorContext(ctx, "searchedScopes: ListScopes failed", "error", err)`-shaped call inside the helper itself (not duplicated per lane) is the natural home — mirrors the file's own existing `slog.InfoContext` calls at `tools.go:1890`, `:2632`, `:2679` for level/field style (`slog.XContext(ctx, "<verb-ish message>", "key", value)`).

**Existing doc-comment discipline to preserve** (`tools.go:1822-1839`): keep the "An error from ListScopes fails the CLAIM" reasoning intact in the updated comment — D-01 changes what happens to the *hits*, not the *coverage claim's* honesty.

### `internal/server/tools.go` — `recallResultMap` (`:1864-1870`)

**Analog:** itself — extend the existing on/off-by-`crossSpine` key-add discipline (D-14) with a third key, gated the same way.

**Current shape:**
```go
// recallResultMap assembles a search_memory/list_memory MCP result map: base
// (the transport-specific entries, e.g. "memories" and, for list_memory,
// "next_cursor") plus, ONLY when crossSpine is true, "searched_scopes" and
// "scopes_truncated". On a non-cross-spine call neither key is added at all
// (D-14) ...
func recallResultMap(base map[string]any, crossSpine bool, scopes []string, truncated bool) map[string]any {
	if crossSpine {
		base["searched_scopes"] = scopes
		base["scopes_truncated"] = truncated
	}
	return base
}
```

**D-03/D-04 requires:** on the coverage-unknown path, `"searched_scopes"` must be ABSENT (never an empty slice) and `"scopes_truncated"` absent/false, while `"scopes_unknown": true` is added. Since this function currently only receives `scopes`/`truncated` as plain values (no way to distinguish "coverage known, zero scopes" from "coverage unknown"), its signature necessarily grows a parameter carrying the new state — follow whatever shape `searchedScopes` itself returns (Claude's Discretion), and keep the `if crossSpine` gate as the OUTER condition so a non-cross-spine call still gains zero new keys (byte-identical guarantee, same as today).

### `proto/engram/v1/engram.proto` — `ListMemoriesResponse` / `SearchMemoriesResponse`

**Analog:** the existing `scopes_truncated` field in each message — the new field is its sibling, same style of doc comment, same "present only alongside X on a cross-spine response" phrasing pattern, inverted for D-03(c).

**`ListMemoriesResponse`** (`:111-125`), add after `scopes_truncated = 6`:
```protobuf
message ListMemoriesResponse {
  repeated Memory memories = 1;
  uint64 total = 2;
  bool approximate = 3 [deprecated = true]; // always false since totals are now exact (Count)
  string next_page_token = 4;               // empty when no further pages (cursor paging)
  repeated string searched_scopes = 5;
  bool scopes_truncated = 6;
  // scopes_unknown is true when a cross-spine query's coverage-enumeration
  // (ListScopes) itself failed after hits were already produced: the RPC
  // still succeeds and memories are still returned, but searched_scopes is
  // ABSENT (not an empty list, which would read as "searched nothing") and
  // scopes_truncated is absent/false. Present only on a cross-spine
  // response; never true alongside a populated searched_scopes.
  bool scopes_unknown = 7;
}
```

**`SearchMemoriesResponse`** (`:160-171`), add after `scopes_truncated = 3`:
```protobuf
message SearchMemoriesResponse {
  repeated Memory memories = 1;
  repeated string searched_scopes = 2;
  bool scopes_truncated = 3;
  // scopes_unknown — see ListMemoriesResponse.scopes_unknown; identical
  // semantics, sibling field number scheme (next free number in THIS
  // message, not shared with ListMemoriesResponse's field 7).
  bool scopes_unknown = 4;
}
```

**Convention to note:** field numbers 5/6 and 2/3 above are ALREADY occupied (`searched_scopes`/`scopes_truncated`); 7 and 4 are each message's own next free number — do not renumber existing fields, and do not reuse a number from a `[deprecated = true]` field (`approximate = 3` on `ListMemoriesResponse` occupies 3 permanently — memory `s780vae1vr`).

```go
type lostRaceStore struct {
	*spyStore
	winnerID, winnerFP string
}

func (l *lostRaceStore) Supersede(_ context.Context, _ store.Memory, _ []float32, targets []string, subj store.Subject) error {
	owner := ownerOfSubject(subj)
	l.mu.Lock()
	l.record("Supersede", owner, targets[0])
	l.records[l.winnerID] = store.Memory{ID: l.winnerID, Owner: owner, IdempotencyFingerprint: l.winnerFP}
	l.mu.Unlock()
	return fmt.Errorf("%w: %s", store.ErrAlreadySuperseded, targets[0])
}
```
```go
sp := newSpyStore()
```

## Shared Patterns

### Single-helper discipline (extend, don't duplicate)
**Source:** `internal/server/tools.go:1840-1855` (`searchedScopes`)
**Apply to:** both MCP closures, both Connect handlers — the fix lives ONCE, inside the helper; none of the four call sites gets its own inline error-handling logic (mirrors this phase's own D-06 and Phase 2's single-mapper discipline).

### Log-the-cause-not-the-wire (D-02)
**Source:** `internal/server/connecterror.go:103-105` (Connect lane) and `internal/server/responsetoolarge.go:70-78` (MCP lane)
**Apply to:** `searchedScopes`' new error-handling branch — `slog.ErrorContext(ctx, "<message>", "error", err)`, never a scrubbed string reaching the proto/MCP-result-map wire.
```go
case errors.Is(err, store.ErrResponseTooLarge):
	slog.ErrorContext(ctx, "connect handler: response too large", "error", err)
	return connect.NewError(connect.CodeResourceExhausted, errors.New(responseTooLargeEnvelope()))
```

### crossSpine-gated key/field addition (D-14, extended)
**Source:** `internal/server/tools.go:1864-1870` (`recallResultMap`) and `proto/engram/v1/engram.proto` `scopes_truncated` fields
**Apply to:** the new `scopes_unknown` MCP key and the two new proto fields — added ONLY when `crossSpine`/`cross_spine` is true, so a non-cross-spine response/result-map stays byte-identical to today's.

### Additive-proto / committed-codegen discipline
**Source:** `proto/engram/v1/engram.proto` (existing `scopes_truncated` fields) + CLAUDE.md "Protobuf/buf" convention
**Apply to:** both new proto fields — new field numbers only (7 and 4, the next free numbers in each message), never renumbering; regenerate all three `gen/`/`ui/src/lib/gen/` trees via `task proto:gen`; `buf breaking` (FILE mode) is satisfied by an additive field.

### Store-failure injection via embedding `*spyStore`
**Source:** `internal/server/tools_test.go:4202-4216` (`lostRaceStore`)
**Apply to:** the new `ListScopes`-failure test double — embed `*spyStore`, override exactly one method, wire via `&deps{st: wrapper, em: fakeEmbedder{}}` (MCP path) or `&engramAPI{d: d}` (Connect path) — no live Qdrant needed for this failure-injection proof, unlike the existing `testDeps(t)`-backed cross-spine isolation tests which DO require live Qdrant and are NOT the right base for this specific failure scenario.

### CLI renderer stays the ONE place text output is decided
**Source:** `cmd/engram/client_common.go:333-343` (`renderCoverageFooter`)
**Apply to:** the new third footer form — grow the existing function's signature, do not add a second renderer or inline the new branch at either call site (`client_list.go:94`, `client_search.go:82`).
