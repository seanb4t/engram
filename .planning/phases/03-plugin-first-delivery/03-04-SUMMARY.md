## Accomplishments

- `skill/engram/.codex-plugin/plugin.json` ships as the minimal four-key twin of `.claude-plugin/plugin.json` — `$schema`, `name`, `version`, `description` — with the last three byte-equal to the Claude manifest's, no `interface`/`hooks`/`mcpServers` key.
- `release-please-config.json`'s `extra-files` now syncs the codex manifest's `$.version` in the same release as the Claude manifest's, so both bump together forever.
- `TestPluginManifestIdentityMatches` is the permanent drift gate: it re-reads both manifests and the release-please config from disk, asserts the codex manifest's exact key set, byte-equal identity fields, a bare `X.Y.Z` version core, and exactly one `extra-files` entry for each manifest — plus a non-literal substring check that the description stays vendor-neutral.
- `internal/setupgen.Render` now takes a second `PluginActionsFunc` parameter and appends `### Claude Code plugin delivery (--apply)` — a four-row table (`absent` × 2 marketplace states, `outdated`, `current`) sourced from `setup.ClaudeCode.(setup.PluginRuntime).PluginActions` through `Plan{Actions: actions}.Display()`, never a re-typed literal. The renderer validates its own shape: a row whose action count contradicts its state, or any action whose argv doesn't start `claude plugin`, fails generation with a named error before any partial body is returned.
- `skill/engram/commands/engram-setup.md`'s anchored region was regenerated via `go run ./internal/surfacesgen` in the same commit as the `Render` change — the five delegation rows and five fallback rows stayed byte-identical, only the new plugin table was appended. The hand-authored prose outside the anchors now explains plugin-first delivery's mutual exclusion with the native copy, the third table's four states plus what `unavailable` means, and that an existing native skills copy is reported but never removed by setup.
- Full repo gate (`task`, `task license:check`, empty `go.mod`/`go.sum` diff, `internal/keylinks`, `surfacesgen --check-setup`, the pytest privacy guard) is green, including the full `task` run across every package (`internal/store`'s red-evidence harness included).
