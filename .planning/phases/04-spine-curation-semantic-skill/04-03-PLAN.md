## Decisions this plan settles (RESEARCH.md's two open questions, plus proseTargets)

### Open Question 1 — the reactive trigger is prose-only, not a hook. DECIDED.

Not a preference; the hook mechanism cannot express the decision.

- D-03 fires the reactive path **only** when staleness is visible from what the agent already has
  open — "the recalled record cites a file or commit the agent already has open or just read, and
  plainly contradicts it." That is a judgment over the agent's own live context.
- A `PostToolUse` hook is an external process. It has no access to the agent's open context, so it
  cannot evaluate that condition. The most it can do is inject a blanket nudge after **every**
  matching tool call — which is precisely the nag D-03 exists to prevent and the failure mode
  CONTEXT.md spends a paragraph guarding against.
- Supporting evidence, not the reason: `skill/engram/hooks/hooks.json`'s only `PostToolUse` matcher
  is `Edit|Write|NotebookEdit`, so the existing capture-nudge precedent does not even fire on recall
  tools. A recall-matching hook would be new surface, not a reuse.
- Consequence: no file is added under `skill/engram/hooks/`, `hooks.json` is unchanged, and no new
  pytest file appears in `skill/engram/hooks/tests/`. RESEARCH.md's Wave 0 item for this resolves to
  "no new test surface needed."
- Reversibility: `reversible`. A hook can be added later; nothing published depends on its absence.

### Open Question 2 — `distinct` is recorded as an `update_memory` tag. DECIDED, with a stated limit.

- CONTEXT.md deferred this only "if it needs a store change." It does not: `update_memory` already
  accepts `tags`, so the convention is achievable in pure prose with zero server change.
- **The `rule-declined` precedent is not directly reusable here.** `curating-memory` records a
  decline by storing a *new* `category: decision` memory — which requires `store_memory`, a tool
  outside the six this phase is allowed to call. So the analogous shape is a tag on an existing
  record, not a new record.
- Convention: tag the record whose `short_id` sorts lexicographically first with
  `spine-distinct-<other short_id>`. One tag write per `distinct` verdict, deterministic, and it
  names the specific counterpart so it cannot over-suppress unrelated future pairs. The character
  class matches the existing `rule-declined` convention (lowercase, hyphens) plus a Crockford base32
  short id — no tag grammar is invented.
- Gotcha the prose must carry: `update_memory`'s `tags` **replaces** the whole set. The current tags
  must be read via `get_memory` and re-sent as a union, or every existing tag is silently cleared.
- Consent: the tag write is a mutation, so it is a batch item like any other, with its own yes. One
  `distinct` judgment about one pair produces exactly one write, so this is not the batch-approve
  shortcut D-10 forbids.
- **Stated limit, not papered over:** a *declined* proposal has no durable record here, because that
  would need `store_memory`. Within a session, step 3's "ask once, then stop" covers it; across
  sessions it does not persist. The skill must say so plainly. This is the residual part of
  CONTEXT.md's deferred "recording a `distinct` judgment durably" item and stays deferred.

## Flagged Assumptions (no-silent-drop ledger)

The phase-level ledger is closed in plan 04-01 (3 authored + 2 flagged = 5 probe items). This plan
adds no probe items. Plan-local assumptions recorded rather than dropped:

1. **The `distinct` tag is written to one record of the pair, not both.** Chosen for determinism and
