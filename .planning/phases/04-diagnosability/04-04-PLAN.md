<objective>
Convert every remaining single-field rejection in `internal/server/tools.go` to the envelope plan
04-01 built, and prove the conversion with a matrix rather than a spot-check.

D-06 is explicit that this is a sweep, not a sample: a partial conversion leaves a surface where an
agent can branch on the field for some tools and not others, which is worse than not having field
attribution at all. RESEARCH enumerated every row; this plan works that list.

Two things make this plan more than mechanical.

**The relational checks do not fit a single-field envelope.** `parseWindow`'s
"requires not_before and/or not_after" and its ordering check name two fields. 04-01's envelope
already carries `Fields []string` for exactly this, so they get both names — not an arbitrary pick,
which would defeat the matrix's whole point.

**D-08's scope fence is load-bearing and is verified BEFORE anything is reformatted.** Reformatting
argument-validation message text is approved. Changing the MCP 401 auth body is not: engram
`e9yv53pmnv` records it as a wire contract, and it is produced by the go-sdk's `RequireBearerToken`,
not by `tools.go`. Task 1 proves the separation by reading, then pins it, and only then does Task 2
touch a message.

Purpose: make field attribution total across the MCP tool surface, so an agent can rely on it.
Output: sixteen converted Category A sites, three converted Category B sites, the matrix, the
no-value-echo negative gate, and the 401 byte-identity pin.
</objective>
