<objective>
Fix the bug that made this requirement exist.

Research established that issue #360's misleading `missing properties: ["content"]` is emitted by the
go-sdk's `applySchema` BEFORE any `tools.go` code runs, because `storeArgs.Content`/`Scope`/`Source`/
`Category` carry no `omitempty` and are therefore marked required in the auto-inferred JSON schema. A
phase that converted only the `tools.go` sites would have satisfied criterion 2's matrix in full while
leaving its own motivating bug exactly reproducible. Sean extended scope for that reason.

The fix moves required-ness out of the wire schema and into engram's own validation, where the
envelope built in plan 04-01 can name the right field. It applies to EVERY arg struct carrying
schema-required fields, not only the two names in #360 — a partial application would recreate D-06's
own inconsistency objection one layer up.

Two things here are sharper than they look.

**`updateArgs.Content` is not a symmetric relaxation.** Its comment says in as many words that the
MCP tool requires content on every call *because* the schema requires it, while the Connect
field-mask lane legitimately supplies nil. Relax the tag without putting the replacement check in the
right place and MCP's full-replace semantics change silently.

**Criterion 2's matrix does not prove #360 is fixed.** D-06a says so explicitly. The regression test
is separate, names the issue, and reproduces its exact call.

Purpose: close #360 at its actual cause, not one layer above it.
Output: the schema delta, a Go-level presence check per relaxed field, the memory-summary bound, the
named regression with its positive control, and plan 04-03's dimension-derived embeddings bound.
</objective>
