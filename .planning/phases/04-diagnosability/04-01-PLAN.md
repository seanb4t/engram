<objective>
Build the one envelope this phase's two validation requirements share, and prove it end-to-end on a
single real rejection before any sweep touches thirty more.

D-09 is explicit that the field attribution (D-05) and the remediation hint are one envelope, not
two mechanisms. That makes the type a one-time design decision with two published wire consequences —
the MCP error string and the Connect error code — and both are one-way doors. This plan defines the
type, wires ONE rejection site through both transports, and stops. The sweep is plans 04-04 and
04-05; they author classes and codes at rejection sites and never touch `argerror.go` or
`connecterror.go` again.

`validateStoreDiscovery` is the tracer's rejection site because it is the smallest complete
validator that is simultaneously (a) a Category-A single-field site, (b) currently unwrapped and
therefore a live D-11a `CodeInternal` misclassification, and (c) reachable from BOTH the MCP
`store_discovery` tool and the Connect `StoreDiscovery` RPC. One function proves the whole path.

Purpose: make the envelope's shape a decision taken once with full context, not an accretion.
Output: `internal/server/argerror.go`, the `connectError` class dispatch, and a converted
`validateStoreDiscovery` whose rejections are field-attributed, hint-carrying, and correctly coded
on both lanes.
</objective>

**(1) The envelope grammar (D-09, Claude's Discretion).** `go-sdk@v1.6.1/mcp/server.go:340-354`

Chosen over a JSON-object `Error()` because these errors are wrapped by callers
(`fmt.Errorf("...: %w", err)`), which would corrupt a bare JSON string but leaves a prefix grammar
