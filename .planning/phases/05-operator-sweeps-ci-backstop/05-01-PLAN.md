<objective>
Turn `Store.scrollAllPoints` into the one iterator every operator sweep in this phase can use, then
move `spine-review`'s four read-only sweeps onto it with a per-sweep payload projection, each proven
against a scope whose 256-record page would have overflowed the named receive limit.

D-03 (one real-Qdrant regression per migrated sweep, both fixture shapes), D-04 (per-sweep
projection, never one shared full-payload sweep view), D-00 (choose by idiom, not effort).

Purpose: four of the ten Phase 5 inventory rows stop requesting a full payload at 256 records per
RPC, and the iterator gains the one parameter plan 05-04's `Store.Reindex` needs.

Output: three new view constructors and their ceilings, four migrated call sites, and one new
real-Qdrant regression file covering all four sweeps on both fixture shapes.
</objective>

<fixture_sizing>
Read this before writing any assertion about which shape overflows.

At `storetest.RecvLimit` (4 MiB) the two shapes are NOT symmetric for a 256-record sweep page:

- `FewLarge` is 40 records of 131072 content bytes. One 256-record page returns all 40 at once —
  about 5.24 MiB — so it is the shape that overflows a 256-record full-payload sweep page and the
  shape that carries every RED direction in this phase.
- `ManySmall` is 1000 records of about 5243 content bytes. A 256-record page is about 1.34 MiB and
  does NOT overflow; this shape exercises multi-page pagination and per-page assembly at the same
  named limit.

Both shapes must run and pass. Do not write an assertion claiming `ManySmall` overflows a sweep page.
</fixture_sizing>

<performance_note>
After the migration a full-payload sweep requests `min(spineScrollBatch, rpcByteBudget/ceiling)`
records per RPC. At `DefaultRecordCaps()` `fullRecordCeiling` is 970240, so a full view drops to 2
records per RPC and a 1000-record scope costs about 500 round trips. This is the same trade Phase 4
already accepted for `Store.List`, and it is why D-04 exists: `summaryRecordCeiling` (34304) yields
about 61 records per RPC, and the two tiny projections in this plan stay capped at `spineScrollBatch`.
A regression run that takes a few minutes longer is expected; a run that hangs is not.
</performance_note>
