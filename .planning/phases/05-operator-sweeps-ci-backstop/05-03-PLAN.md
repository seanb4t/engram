<objective>
Delete the four hand-rolled `ScrollAndOffset` cursor loops inside `engram migrate` and
`engram migrate revert`, replacing each with the shared byte-budget iterator, and express each
mutating pass's batch boundary as its own sentinel error rather than a page size.

Decisions covered: D-01 (the own-loop sweeps migrate onto the established primitive; the stateful
bits become closure state and early termination rides the callback's error, verified against the
iterator's own contract), D-02 (no new characterization test — the 23 in-place tests are it),
D-03 (a real-Qdrant regression per sweep), D-04 (the full view is genuinely required here, because
both write paths decode the whole payload).

Purpose: the two most safety-critical operator commands in the repo stop requesting 256 full
payloads per RPC, without changing a single thing they report or write.

Output: four deleted loops, two sentinels, two corrected recall-gate justifications, and one new
real-Qdrant regression file covering both commands on both fixture shapes.
</objective>

`func (s *Store) scrollAllPoints(ctx context.Context, collection string, filter *qdrant.Filter, view readView, fn func(*qdrant.RetrievedPoint) error) error`.
Contract: it advances a forward id cursor across RPCs, sizes each RPC's `Limit` from the view's byte

- Dry-run backlog projection, inside `case opts.DryRun:`. One exhaustive `ScrollAndOffset` walk of

<design_note>
Read before writing the sweep-mode callback.

Today a mutating pass reads all `batch` records in ONE RPC and then writes them. After the migration
the iterator interleaves: read two records, write them, read the next two. Those writes advance
`schema_version`, which removes the written records from the pass's own filter.

This is safe, and the reason is specific: the iterator advances a FORWARD id cursor derived from the
previous response's next-page offset. Removing an already-passed record from the filter cannot move
the cursor backwards, so no record is skipped and none is visited twice within a pass. A record whose
write FAILS stays in the filter and is picked up by the next pass's fresh count, exactly as today.

State this reasoning in a comment at each migrated write loop. It is the one genuine behavioural
difference between the old and new shape, and `TestMigrateV0ToV1MintEndToEnd`,
`TestMigrateWritesOnlyAddedKeys` and `TestMigrateTracerLegacyRecordEndToEnd` are the in-place tests
that would catch it being wrong.
</design_note>

<fixture_sizing>
At `storetest.RecvLimit` (4 MiB) the two shapes are NOT symmetric for a 256-record sweep page:
`FewLarge` is 40 records of 131072 content bytes, so one 256-record page returns about 5.24 MiB and
overflows; `ManySmall` is 1000 records of about 5243 bytes, so a 256-record page is about 1.34 MiB
and does not. `FewLarge` carries the RED direction; `ManySmall` exercises multi-page pagination and,
for a mutating sweep, multi-PASS draining (1000 records at a 256 batch is four passes). Both must
run and pass. Do not write an assertion claiming `ManySmall` overflows a sweep page.
</fixture_sizing>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator intent → destructive write | `engram migrate` and `engram migrate revert` are the only commands in the product that rewrite every record in a collection; their preview/apply split is the operator's whole safety margin. |
| iterator cursor → concurrently mutated filter | Writes now interleave with reads, so the pass's own writes change the set the cursor is walking. |
| sentinel error → real failure | An early-stop marker that reaches a caller as a failure, or a failure swallowed as an early stop, both misreport what a sweep did. |
| classification list → derived emission set | A name-keyed AST gate is only true while the code it names emits what it claims. |
