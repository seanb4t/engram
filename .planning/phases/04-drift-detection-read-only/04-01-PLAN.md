compared against the already-known intent (`Options`), not against a second read — the basis
`apply.go`'s doc comment currently rules out (04-RESEARCH.md Pitfall 1); REQ-drift-redaction needs
redaction by construction, which only a parse-then-rebuild path gives; REQ-drift-facet-naming
needs a typed facet set rendered in a fixed order; REQ-drift-preserved-outcome needs the value to
survive `Classify`/`AggregateOutcome` without being laundered into `failed`.

Why the tracer is Codex, not Claude Code: the full `codex mcp get --json` shape is captured
verbatim (03-RESEARCH.md, codex-cli 0.153.4 — 04-RESEARCH.md Code Examples), so a scanner built
against it is built from observed reality, while Claude Code's full `mcp get` framing (name line,
`Scope:`/`Status:`/`Type:` chrome, any trailing hint) was never captured verbatim — only its
`Headers:` block was. D-06 therefore gates Claude Code's scanner on `04-OBSERVATIONS.md` (plan
04-05, wave 3); Codex's only observation-gated piece is the literal-header fixture, also 04-05.

Decision (Open Question 1, planner): `OutcomePreserved` sits BETWEEN `OutcomeWrote` and
`OutcomeAlreadyCorrect` in `precedenceOrder` — `failed > wrote > preserved > already-correct >
would-write > not-present`. Rationale: the aggregate's standing invariant is "mixed state resolves
UP, never down to already-correct"; a `preserved` registration beside a `current` plugin
(`already-correct`) must surface as `preserved` at the row's headline Outcome, or an operator
scanning outcomes would read a declined write as convergence — while a facet that actually wrote
is the more consequential event and still outranks it. 04-RESEARCH.md's earlier suggestion
(between already-correct and would-write) would hide preserved beneath already-correct and is
rejected for that reason. Reversibility: costly (a published `--output json` row-outcome contract).

Assumption-delta (advisory, orchestrator contribution): the `Outcome` enum was already plural —
`no-change`. `Result.Registered`'s meaning shifts from raw capture to normalized redacted rendering
— decision `promote` (the rendering REPLACES the raw capture in the same scalar field; keeping a raw
field alongside would keep the leak D-03 closes), rated costly per 04-CONTEXT.md D-03.
