<objective>
Wire one path end-to-end: a shell-only caller runs `engram search`, the command resolves a server
URL and a bearer credential without either touching `argv`, builds one Connect client over a
TLS-verifying transport, calls `SearchMemories`, writes a single JSON document to stdout, and — on
failure — exits with a code that tells the caller *what kind* of failure it was.

This is the phase's tracer slice. It touches every layer the phase will ever touch: flag parsing,
credential resolution, TLS policy, Connect client construction, the bearer interceptor, RPC
dispatch, output rendering, error classification, and the process exit code. `list` and `store`
(Plan 02) are horizontal expansion over a shape this plan proves.

Purpose: a Connect *client* is genuinely net-new in a repo that has only ever been a Connect
*server* (`02-PATTERNS.md` found 8 role-level analogs and 0 exact). Proving the whole column works
on one command before writing three is what keeps an architectural dead-end cheap.
Output: the shared client foundation, `engram search`, the reusable in-process Connect test
harness, and the one change to `Execute` that makes the D-09 exit taxonomy real for the whole
binary.
</objective>

  <action>
Create `cmd/engram/client_common.go` holding everything the three subcommands share, so the server
URL, credential resolution, TLS policy, output-format selection, and error classification exist
exactly once (D-03/D-10).

Declare the four shared flag vars and `addClientFlags(cmd *cobra.Command)` binding them:

  - `--server` (string, default `""`) — help text names `ENGRAM_SERVER_URL` as the fallback.
    **Bind the default as the empty string, not as `os.Getenv(...)` inline.** `reindex.go:102-104`
    uses the inline-getenv idiom, but that bakes the environment in at `init()` time, which makes
    the D-02 precedence untestable with `t.Setenv` and hides the env value inside `--help` output.
    Resolve at run time instead, in `resolveServerURL`. Note the deliberate divergence in the
    comment so a later reader does not "restore" the repo idiom and silently break the test.
  - `--token-file` (string, default `""`) — a path to a file containing the bearer credential.
  - `--insecure` (bool, default `false`) — **no environment fallback of any kind** (D-14: an
    env-settable escape hatch is precisely the silent disable the decision forbids).
  - `--output` (string, default `""`) — `json` or `text`; empty means detect from stdout (D-05/D-06).

Declare `resolveServerURL(flagVal string) (string, error)`: return `flagVal` when non-empty; else
`os.Getenv("ENGRAM_SERVER_URL")` when non-empty; else a `usageErrorf` naming both the flag and the
variable (D-02 — no localhost default, ever; a CI job that silently queries nothing is the exact
failure the decision exists to prevent).

Declare `resolveToken(tokenFilePath string) (string, error)`: return `os.Getenv("ENGRAM_TOKEN")`
when non-empty; else, when `tokenFilePath` is non-empty, read the file and return
`strings.TrimSpace` of its contents (a trailing newline is the default state of a file written by
a shell redirect and would otherwise produce a three-field credential the server rejects); else
return the empty string with a nil error — an anonymous call against a no-issuer server is legal.
There is **no** flag that accepts a credential value; a credential must never be able to reach
`argv` (D-13).

Declare `bearerInterceptor(token string) connect.UnaryInterceptorFunc` returning a unary
interceptor that, when `token` is non-empty, calls `req.Header().Set` to set the credential header
to `"Bearer "+token` — one space, exactly two whitespace-separated fields, which is what the
server's extractor requires. When `token` is empty it sets nothing at all. This mirrors the
server-side `connect.UnaryInterceptorFunc` idiom already used in `internal/server`, and it composes
with any transport, so TLS policy and credential attachment never touch the same object.

Declare `newHTTPClient(insecure bool) *http.Client` returning a client whose `Transport` is an
`*http.Transport` with `TLSClientConfig` set to a `*tls.Config` whose `InsecureSkipVerify` is
`insecure`. The zero value is `false`, so the do-nothing path is the secure path (D-14).

Declare `clientFromFlags(cmd *cobra.Command) (engramv1connect.EngramServiceClient, error)`: resolve
the URL, resolve the token, and when `clientInsecure` is true write an unconditional warning to
`cmd.ErrOrStderr()` — never to stdout, never gated by `--output`, never suppressible (D-14/D-07).
Then return `engramv1connect.NewEngramServiceClient(newHTTPClient(clientInsecure), url,
connect.WithInterceptors(bearerInterceptor(token)))`.

**Do not add cookie-jar or anti-forgery-token plumbing.** `02-RESEARCH.md` Pattern 3 verified that
the server exempts the bearer lane totally for write procedures, so any such code here is
unreachable against every server this client can talk to.

Declare `isTerminal(f *os.File) bool` using `f.Stat()` and `info.Mode()&os.ModeCharDevice != 0`,
returning `false` when `Stat` errors — failing toward JSON is the safe default for an unknown
environment (D-05). Use the standard library only. `golang.org/x/term` sits in `go.mod` as an
indirect requirement imported by no file in this repo; importing it would promote it to a direct
dependency on a milestone that advertises none, and Task 2's allowlist gate rejects it.

Declare the `outputFormat` type with `formatJSON` and `formatText`, and
`resolveOutputFormat(flagVal string, isTTY bool) (outputFormat, error)`: `"json"` → JSON, `"text"`
→ text, `""` → text when `isTTY` else JSON, anything else → a `usageErrorf` listing the two legal
values (D-05/D-06). Taking the boolean as a parameter rather than calling `isTerminal` internally
is what lets a table test force both branches without a pty.

Declare the exit-code constants `exitOK = 0`, `exitGeneric = 1`, `exitUsage = 2`, `exitAuth = 3`,
`exitNotFound = 4`, `exitUnavailable = 5` with a doc comment giving each one's meaning verbatim from
D-09. These constants are the single source of truth; Plan 03's self-describe catalog is built from
them, not from a parallel literal list (D-11).

Declare `type cliError struct { code int; err error }` with `Error() string` delegating to the
wrapped error, `Unwrap() error`, and `ExitCode() int`. Declare `usageErrorf(format string, a ...any)
error` returning a `*cliError` with `exitUsage`, and `wrapRPCError(err error) error` returning a
`*cliError` whose code is `exitCodeForConnectErr(err)`.

Declare `exitCodeForConnectErr(err error) int` — the one and only mapper (D-10) — switching on
`connect.CodeOf(err)`:

  - `CodeUnauthenticated`, `CodePermissionDenied` → `exitAuth`
  - `CodeNotFound` → `exitNotFound`
  - `CodeInvalidArgument`, `CodeFailedPrecondition`, `CodeOutOfRange` → `exitUsage`
  - `CodeUnavailable`, `CodeDeadlineExceeded`, `CodeCanceled` → `exitUnavailable`
  - default → `exitGeneric`

Document in the comment that `connect.CodeOf` alone is sufficient and no separate transport check is
needed: the connect-go client wraps any `http.Client.Do` failure that is not already a
`*connect.Error` as `CodeUnavailable`, and a context deadline or cancellation as
`CodeDeadlineExceeded`/`CodeCanceled`, so a genuine dial failure never arrives here as
`CodeUnknown`. Cite `02-RESEARCH.md` Pitfall 5 for the vendored-source line ranges. Do not classify
by matching on the error's text.

Declare `renderJSON(w io.Writer, m proto.Message) error` marshalling with
`protojson.MarshalOptions{UseProtoNames: true, EmitDefaultValues: true, Multiline: false}` and
writing one document plus a trailing newline (D-08 — one JSON object per invocation, not NDJSON).
Two option choices are load-bearing and must be commented: `EmitDefaultValues` is what makes an
empty result render as `"memories":[]` rather than omitting the key or emitting `null` (D-12), and
`UseProtoNames` keeps the field names identical to the `.proto` declaration and therefore to the
`short_id` / `created_at` / `summary_source` vocabulary the MCP tool surface and CLAUDE.md's memory
contract already use. Deriving the field names from the message rather than from a hand-written Go
struct is what makes D-08's "mirror the response field names" structurally true instead of a
convention someone can drift from.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator/CI environment → CLI process | The server URL, the credential, and the TLS policy all enter from `argv`, the environment, or the filesystem. `argv` is world-readable via `ps` and is persisted by shell history; the environment and a file are not. |
| CLI process → engram server | An HTTP(S) hop across an untrusted network. The client decides whether to trust the server's certificate; everything the server returns is untrusted input to the renderer. |
| CLI process → stdout/stderr | The caller is a program, not a human. Anything written to stdout is parsed; anything written to either stream may be captured into CI logs that outlive the run. |
