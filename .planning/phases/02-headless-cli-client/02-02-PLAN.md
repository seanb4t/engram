  <action>
Create `cmd/engram/client_store.go` with `storeCmd`, following the same structure as the other two
client commands — same command-literal shape, `Args: cobra.NoArgs`, `RunE`, and an `init()` calling
`addClientFlags(storeCmd)` and `rootCmd.AddCommand(storeCmd)` (D-01/D-03).

Bind one flag per `StoreMemoryRequest` field: `--content`, `--scope`, `--source`, `--category`,
`--tags` (`StringSliceVar`), `--repo`, `--workspace`, `--worktree`, `--base-dir`, `--summary`.
Take the content through a flag rather than a positional argument, consistent with the other two
commands and with the `NoArgs` rule from Plan 01.

The `--category` help text must name the four values the wire message's constraint accepts —
decision, preference, convention, gotcha — so a caller learns the set from `--help` instead of from
a rejected round trip.

Bind **no** flag for the caller identity or ownership fields. They appear only on the
response-shaped `Memory` message and never in the request, so the wire contract itself enforces
"server-set, never client-supplied"; the test above pins that a flag is never added back.

`RunE`, in this order:

  1. Reject an empty `--content` and an empty `--scope` with `usageErrorf`, **before** building the
     client, so a missing required value costs no network round trip and reports exit 2 rather than
     waiting for the server's `CodeInvalidArgument`. This duplicates the wire constraint
     deliberately, as an ergonomic pre-check; the server's rejection remains authoritative and maps
     to the same exit code either way, so the two can never disagree observably.
  2. Resolve the output format.
  3. Build the client through `clientFromFlags(cmd)`.
  4. Issue **exactly one** `StoreMemory` call with `cmd.Context()`.
  5. On error, return `wrapRPCError(err)` immediately.
  6. On success, render the whole `StoreMemoryResponse` message so both the id and the short id
     reach the caller (D-08), and return `nil`.

**No retry loop, no backoff, no second attempt, on any error class.** A mutating call retried on an
ambiguous failure — a timeout, an `Unavailable`, an `Internal` — can duplicate a record, and this
milestone's requirements place that behavior out of scope until an idempotency key rides on the wire
message. There is no such field on `StoreMemoryRequest` today. Write the call as a single statement
and let the error propagate.

Add no new helper to `client_common.go`.
  </action>
