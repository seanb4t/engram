## Decisions resolved by this plan

**`migrate.CurrentVersion = 0`** — this plan resolves CONTEXT.md's Open Question for the Planner.

Rationale (state this verbatim in the constant's doc comment and in `migrate_test.go`):

1. "Current" means *the version produced by applying every registered migration step*. Phase 2
   creates no registry (Phase 3 does) and registers no steps (Phase 4 does), so the current schema
   is the baseline schema: v0.
2. The milestone already recorded (`.planning/STATE.md`, 2026-08-12 roadmap decisions; ROADMAP
   Phase 4 success criterion 4) that `backfill-short-ids` becomes the **v0→v1** step. Shipping
   `CurrentVersion = 1` here would force one of two contradictions when Phase 4 registers it:
   either every record already written falsely claims to have passed a step that never ran, or the
   step must be renumbered v1→v2 against a recorded decision.
3. `payload()` cannot honour a v1 claim. `payload()` omits `short_id` when `Memory.ShortID` is
   empty, so the codec has no way to guarantee the property that defines v1. Stamping 1 from
   `payload()` would be exactly the false-currency claim D-02 and D-05 reject for partial writes.

**Reversibility: `costly`, not `one-way`.** No checkpoint is inserted. Raising the constant later is
the mechanism the Phase 3 sweep exists to run: records at 0 become backlog and converge. Nothing on
disk needs a migration to *repair*, and nothing is published yet — Connect exposure is Phase 5. The
cost is real but bounded: Phase 3's registry, Phase 4's step numbering, Phase 5's proto mapping and
Phase 7's CLI all reference the symbol.

**Cross-phase gate:** Phase 3's plan must define `CurrentVersion` the same way (count of registered
steps). Flag any disagreement at the plan-checker gate rather than silently diverging.

## Review findings resolved by this plan

Cross-AI review (`02-REVIEWS.md`, Codex + OpenCode/Kimi-K3) raised five items landing here. Each is
resolved in a task below; this section exists so the executor sees the decision, not just the edit.

- **`max(CurrentVersion, m.SchemaVersion)` protects only the version carried in the `Memory`
  argument** (Codex MEDIUM). `Store.Upsert` is public replace-by-id and does not read the stored
  record first (`store.go:731`), so a stale caller CAN lower a stored version through it. **Decision:
  narrow the contract, do not add a CAS.** A stored-version read or compare-and-swap on `Upsert` is
  out of this phase's additive scope and would change the semantics of a public method every existing
  caller relies on. Task 1 writes the narrowed boundary onto the field: normal full writes stamp at
  least current, and rewriting a *decoded* newer record through `Update` preserves its higher
  version; raw `Upsert` replacement is outside the guarantee. Nothing in the phase may claim broader.
- **`Store.Update`'s in-lock refresh does not refresh `SchemaVersion`** (Codex MEDIUM). Verified: the
  refresh at `store.go:1828` copies `Supersedes`, `SupersededBy`, `ArchivedAt` and stops. **Decision:
  take the one-line fix** — Task 1 also copies `fresh.SchemaVersion` there, so the monotonic maximum
  is computed against the latest stored stamp rather than the caller's snapshot.
- **The proposed `-race` goroutine subtest does not test the meaningful race** (Codex LOW).
  Concurrent calls to a pure `payload()` prove only that it holds no package state. **Decision:
  replace it.** Task 2 drops the goroutine subtest; Task 3 adds a deterministic stale-`cur` `Update`
  test driven through the existing `updateAfterReadHook` seam (`store.go:1780`, verified present),
  which forces the actual window open instead of hoping to land in it.
- **Golden-file blast radius is unchecked** (Kimi LOW). A non-`omitempty` field changes every
  `full=true` and `get_memory` JSON response. **Decision: make it a task step**, not a discovery —
  Task 3 runs the whole `internal/server` suite and fixes any exact-JSON golden that newly sees a
  zero-valued member.
- **The upgrade-guide entry references a migration sweep that does not ship until Phase 3/4** (Codex
  LOW). **Decision: keep the entry, label the command forthcoming.** Task 3 requires the guide to say
  the sweep is not yet available in this release, so the guide never advertises a recovery command an
  operator can run today and cannot find.
