#### Independent assessment of the unresolved Critical review finding (shell injection)

02-REVIEW.md (re-review after 02-03) raised a new, unresolved Critical finding: every `Runtime.Plan`
implementation interpolates `opts.URL` (and, for bearer auth, the `--token-file` path via
`bearerProvenance`) into its authored command string with a bare `fmt.Sprintf`, with no
shell-quoting anywhere in the chain. I independently confirmed this by reading
`internal/setup/claudecode.go:46,54-56,63-66` (and the structurally identical `codex.go`/`opencode.go`
sites): the finding is accurate as described, and CR-01's own fix (this plan) is what newly gives
an environment-sourced value — one an operator did not necessarily type at invocation time — a
direct path into that unescaped string.

**Independent verdict, on this phase's own terms (not inherited from the reviewer's severity
label):** this defect does **not** block any of the five ROADMAP.md success criteria, and it does
not defeat any must-have truth or prohibition in 02-01-PLAN.md or 02-02-PLAN.md's frontmatter.
Reasoning:
- D-02 (02-CONTEXT.md) explicitly mandates the URL be carried "verbatim... never appended to,
  stripped, normalized, or guessed." The defect is a byproduct of correctly honoring that decision
  at the string-construction layer, not a violation of it — shell-quoting the *whole command's*
  syntax is a materially different concern from altering the *URL's own bytes*, and 02-CONTEXT.md
  never scoped shell-safety of the rendered string as an in-scope concern for Phase 2.
- Nothing in Phase 2 *executes* this string. `Apply()` is stubbed and returns
  `ErrApplyNotImplemented` unconditionally (D-09) — there is no live injection sink yet. The risk is
  real but prospective: it activates only once Phase 3 implements `Apply()`, and only if Phase 3's
  implementation shells out via a string-interpolated `sh -c` rather than `exec.Command` with an
  argv slice (an implementation choice Phase 3 has not yet made).
- None of REQ-setup-detects-runtimes, REQ-setup-previews-by-default, REQ-setup-non-interactive,
  REQ-setup-partial-failure-legible, or REQ-setup-correct-by-reading mention command-injection
  safety or shell-quoting.

This is a genuine, correctly-identified defect that should be fixed — ideally before Phase 3 wires
`--apply` to execute these strings, and arguably sooner given the preview text is explicitly
designed to be copy-pasted into a shell (02-CONTEXT.md D-15's own accepted-consequence note: "the
exact invocation lives as a FIELD... rather than as a copy-pasteable block," but it is still
rendered as an intact command string an operator or an agent may reasonably paste and run). I am
flagging it as a should-fix-soon item, not gating Phase 2 completion on it, and recommend the human
reviewer file a tracking issue (`gh issue create`) before Phase 3 begins rather than leaving it as
an ambient code-review comment.
