<objective>
Close CR-01: make `engram setup`'s advertised `ENGRAM_URL` / `ENGRAM_AUTH` environment lane real by
routing `--url` and `--auth` through `config.Load(cmd.Flags())`, and make an absent URL a usage error
instead of a silently malformed command.

Purpose: `REQ-setup-correct-by-reading` is BLOCKED as shipped. `engram setup --help` asserts
`(default: ENGRAM_URL)` and `(default: ENGRAM_AUTH)`, but `cmd/engram/setup.go` never calls
`config.Load` — both flags bind only via `config.FlagDefault(...)`, a static registry-default lookup
that never consults the environment. `internal/config.Config.Setup` and the two registry rows are
dead code. A caller who follows the documented environment lane gets a malformed command with
`outcome: would-write` and no error surfaced at all, which is worse than a failure.

Output: `Config.Setup.URL` / `Config.Setup.Auth` actually reach `internal/setup.Plan()`; a
required-URL guard on the established `usageErrorf` path; regression coverage that sets the
environment variables with no matching flag and asserts the emitted command; and a deduped
`internal/setup.Select`.
