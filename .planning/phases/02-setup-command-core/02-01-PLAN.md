<objective>
Land `engram setup` as a real, preview-by-default, fully scriptable operator command, together with
the `internal/setup` package that backs it: the `Runtime` interface, the `Plan`/`Action`/`Outcome`
types, the injectable `Environment` seam, and the package-level `Runtimes` registry carrying real
`Detect()` and real `Plan()` for claude-code, codex, and opencode.

Purpose: `cmd/engram/catalog.go`'s `buildCatalog` and `cmd/engram/destructive.go`'s
`destructiveByClassification` both panic on a cobra command with no `internal/surfaces/toolclass.go`
row, so registering `setup` and classifying it cannot be sequenced across two phases — let alone two
commits. Seven separately-pinned gates additionally fail the moment `setup` joins the command tree.
This plan pays that entire structural cost once, on a working end-to-end slice, before any expansion.

Output: a `setup` command that reports what it would write to each detected runtime and changes
nothing; three runtime implementations; four auth modes; and a green `task test` with regenerated
`catalog.golden` / `help.golden`.
</objective>

**1. `internal/config` plumbing.**
Add `ValidateSetupAuth(v string) error` to `internal/config/client_validate.go`, placed beside
`ValidateOutputFormat` and shaped identically: a `switch v` accepting `"oauth"`, `"oauth-client"`,
`"bearer"`, `"none"`, and `""`, with a default arm returning an `fmt.Errorf` that quotes the bad
value and spells out all four accepted modes. Per D-03 these four values are ONE enum flag, taken
verbatim from the table already shipped in `skill/engram/commands/engram-setup.md` — never separate
per-mode flags (which would need `MarkFlagsMutuallyExclusive`, whose plain `fmt.Errorf` bypasses
`cliError`/`ExitCode()`) and never inferred by probing the URL for a 401. Add two rows to `internal/config/registry.go`'s
`registry` literal, in the `client.*` neighbourhood: `{Key: "setup.url", Env: "ENGRAM_URL",
Flag: "url"}` and `{Key: "setup.auth", Env: "ENGRAM_AUTH", Flag: "auth", Default: "oauth"}`. Add a
`SetupConfig` struct to `internal/config/config.go` with `URL string \`koanf:"url"\`` and
`Auth string \`koanf:"auth"\``, and a `Setup SetupConfig \`koanf:"setup"\`` field on `Config`, so the
env layer actually unmarshals. Per D-04, do NOT add a row for `apply`, `token-file`, or `runtime`;
each omission gets a one-line comment naming its precedent (`apply`: the `client.insecure`

**2. `internal/setup` core, claude-code only.**

`Getenv(string) string`, and `HomeDir() (string, error)`, plus an `OSEnvironment` package-level value
