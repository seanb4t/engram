<objective>
Expose the store-layer `Store.Supersede` primitive (Plan 01) as a dedicated `supersede_memory` MCP
tool: `supersedeArgs` embedding `storeArgs`, the `deps.supersedeMemory` handler (resolve target ->
embed correcting content -> back-stamp via `Store.Supersede` -> 404-indistinguishable error
re-wrap -> enqueue async summary), the tool registration, and the `connectError` sentinel-switch
exhaustiveness case for `store.ErrAlreadySuperseded`.

Purpose: Gives the caller a single explicit verb to correct a memory they own — one atomic-intent
operation from their view (store the correction, mark the old one superseded). Following DEC-90w
(dedicated verb like `schedule_memory`), the tool inherits the full `storeArgs` field set so the
correcting record is a normal, fully-formed memory with an extra `supersedes` link.

Output: `internal/server/tools.go`, `internal/server/connecterror.go`, and their tests — all green
under `task test`; the MCP tool surface wired end-to-end through the owner write gate.
</objective>
