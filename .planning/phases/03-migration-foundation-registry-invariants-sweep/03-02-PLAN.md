**PA-1 (carried forward, RESEARCH A1).** D-03's "panics at package init, before any test runs" claim
holds only when `Irreversible(...)` appears in a package-level `var`/`init()`. This phase's production
`Registry` is EMPTY, so nothing exercises that placement. This plan proves only the
**panics-on-bad-input** half — the half `TestRemapFromPanicsOnEmptyValue` already gives this repo an
idiom for. A test that calls `Irreversible("")` inside a `TestXxx` body and recovers proves the
function panics on bad input; it does NOT prove the init-order claim, and no assertion or comment in
this plan's output may say otherwise. The init-order half is Phase 4's to keep true, and
`Registry`'s doc comment (written in 03-01) is where that obligation is recorded.

**PA-2 (build-probe mechanics).** The seal proof runs `go build` on a fixture package copied out of
`internal/migrate/testdata/sealedprobe/probe.go.txt` into a temporary directory **inside this module**
(the import of `github.com/seanb4t/engram/internal/migrate` only resolves from inside it). The
directory is created under `internal/migrate/` and removed by `t.Cleanup`. If the toolchain is
genuinely unavailable the test FAILS loudly — it does not skip. If this mechanism proves flaky in
practice, say so in the SUMMARY and keep the AST sealing gate (which is unconditional) as the shipped
guarantee rather than silently deleting the probe.

**PA-3 (what the sealing gate can and cannot see).** The AST gate asserts that every declaration of a
method named `isReversibility` in this package has an unexported receiver type. That closes the
embedding hatch mechanically. It says nothing about a future exported FUNCTION returning one of the
unexported types (harmless — the value is still constructed here) and nothing about reflection
(`reflect` cannot call an unexported method from another package). State both limits in the gate's doc
comment at their real strength; do not write a blanket claim that the type is "impossible to forge".

</planner_assumptions>
