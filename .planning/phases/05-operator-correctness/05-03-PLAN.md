<objective>
Make `ParsePlanKeyLinks` honor its doc comment: no empty KeyLink for a fieldless list item (OPS-03, #502). Keep the gate's behavior for every item unchanged.

Code drift since #502 was filed: the issue's suggested fix drops the entry inside `flush()`. Since then, `ShapeMalformed` / `CheckWellFormed` were added (commit `efcfb0ad`), and they depend on `ParsePlanKeyLinks` emitting exactly those fieldless entries. That is how a prose key_links item in an executed plan is reported as `malformed` at its own line instead of a misleading `unsatisfiable`, and `TestMalformedKeyLinkEntry` pins it. The literal flush()-drop would make that subtest find zero offenders. The satisfiability gate would then pass a prose-authored plan silently, which is the no-op-gate failure this package exists to prevent.

Resolution, honoring D-04 as written: `ParsePlanKeyLinks` skips fieldless items, so no empty KeyLink leaves the exported API and the doc comment is true. The frontmatter walk moves unchanged into an unexported `parsePlanKeyLinkItems`, which the scanner (`ScanPlansWithStats`) calls. The gate therefore keeps seeing, and reporting, every item. Well-formed items behave identically (D-04), and so do malformed ones.

#502's "related, separate concern" (a pattern-less link compiling to a match-anything regex) is already closed: `CheckWellFormed` rejects a missing `pattern:` as `ShapeMalformed` (`TestMalformedKeyLinkEntry/partial-entry-missing-pattern-is-malformed`). No work here.

Decisions implemented: D-04 (skip fieldless items in `ParsePlanKeyLinks`, add a regression test, keep the well-formed gate behavior), D-02 (`Closes #502`).
Output: the parser split, doc comments reconciled, one regression test.
</objective>
