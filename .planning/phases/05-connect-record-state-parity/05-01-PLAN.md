<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Qdrant payload → `store.Memory` → `memoryToProto` → Connect response | Persisted record state crosses into a client-visible wire message; the `json:"-"` convention is the only thing keeping two audit stamps on the store side of this line. |
| `.proto` schema → committed `gen/` trees → every Connect client binary | A field number/type, once merged, is consumed by clients this repo does not build. |
| Recall/authz filter ← `store.Memory` fields | Not crossed by this plan; listed because reading a new field here is the highest-impact way this change could go wrong. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-01 | Information Disclosure | `memoryToProto` / `store.Memory` json tags | high | mitigate | Parity is satisfied only by adding a missing mapping. `EmbedderIdentity` and `IdempotencyFingerprint` keep `json:"-"` (asserted: exactly 2 remain, task 2) and gain no proto field. Plan 05-02 makes the `json:"-"` exclusion the enforced inclusion rule rather than a convention. |
| T-05-02 | Tampering | proto field numbers 23-30 | medium | mitigate | Numbers assigned once via the blocking `checkpoint:decision` above; `go tool buf breaking --against ...#branch=main` is run locally in task 1 and by the CI `buf` job; no field in 1-22 is renumbered or newly deprecated (asserted by diff criterion). |
| T-05-03 | Denial of Service | recall gate / authz filter | high | mitigate | This plan adds no filter code. `schema_version`'s absence is the majority state at adoption, so a filter reading it would exclude every pre-migration record from recall — the constraint already recorded at `internal/store/store.go` (D-13/D-16) is honored and is authored as a `must_haves.prohibitions` entry. |
| T-05-04 | Spoofing | request-side messages | low | accept | None of the eight fields is added to `StoreMemoryRequest`, `ScheduleMemoryRequest`, or any other request message, so no new client-writable surface exists. All eight are server-set and response-only. (Generic mass-assignment is canon — covered by `/gsd-secure-phase`; not minted as a bespoke prohibition.) |
| T-05-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install task exists in this phase. `05-RESEARCH.md` § Package Legitimacy Audit records that no new external Go or JS dependency is added; all work is on already-vendored `google.golang.org/protobuf`, `connectrpc.com/connect`, and `buf`. |
