<objective>
Prove the two read-side properties the roadmap's SC3 and CONTEXT's D-03 name, without adding a
single line of read-path rounding code (D-09) or a second rounding call site.

Purpose: SC3's honest property is not "the read path applies the write path's rounding" — it is
that the store's whole-second encoding makes read-side rounding a no-op by construction, so a
read-path rounding call would be a branch that can never change an outcome (the constant-gate shape
recorded in `k000pn14qp`). This plan makes that property observable instead of asserted. In
parallel it anchors Phase 2's D-10 promise — an operator asking what version a record is always
gets an answer — to the one CLI renderer whose marshal options actually deliver it.

Output: a boundary-second read-lane-identity test in `internal/server`, and a `renderJSON`
`schema_version: 0` anchor test in `cmd/engram`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Connect write RPC → `formatWindowBound` → store `.Unix()` encode → both read lanes | A scheduling bound crosses three representations; an inconsistency between the two read lanes means two callers disagree about when a record reveals or expires. |
| CLI stdout → operator | The rendered JSON is what an operator reads to answer "what version is this record"; an omitted key reads as "no answer" rather than "v0". |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-05-09 | Tampering | scheduling-window bounds across lanes | high | mitigate | One write, two reads, exact-instant equality asserted between the MCP and Connect lanes; the expected value is computed independently of the production rounding helper (asserted by a source criterion) so the check cannot be a tautology. |
| T-05-10 | Information Disclosure | `not_after` truncation | high | mitigate | Rounding is asserted OUTWARD: a sub-second `not_after` is widened to the containing whole second, never floored — a floor would silently collapse a scheduled expiry to immediate-expiry and drop a record out of recall early. Both the sub-second and the exact-threshold cases are covered. |
| T-05-11 | Repudiation | operator's view of record version | medium | mitigate | `schema_version: 0` presence is gated on a decoded map key rather than a stdout substring, so a value merely containing the text cannot register as a pass and a duplicate key cannot survive the decode. |
| T-05-12 | Tampering | test fixture isolation in the shared Qdrant collection | medium | mitigate | Each boundary sub-test uses its own `iso-test:project:*` scope with a deferred `DeleteAll`, matching the established idiom; an interrupted or parallel sibling test cannot observe or corrupt the fixture. |
| T-05-13 | Denial of Service | silent test skip with no Qdrant | medium | mitigate | The boundary test runs under `ENGRAM_REQUIRE_QDRANT=1`, which turns the absent-Qdrant path into a failure rather than a skip; the verify asserts no skip line in the `-v` output. |
| T-05-SC | Tampering | npm/pip/cargo installs | high | accept | No package-manager install task exists in this plan; no new external dependency is added. `05-RESEARCH.md` § Package Legitimacy Audit records this. |
