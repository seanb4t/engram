<objective>
Take `engram setup --apply` from Phase 2's always-fail stub to a real, production-quality
end-to-end registration for ONE runtime — codex — through every layer: the `Args`-authored
action model, the `Environment.Run` process seam, the shared `internal/setup` executor with its
read → write → read convergence probe, the derived display string, and the report row plus exit
code in `cmd/engram/setup.go`. Codex is chosen as the tracer runtime because it is the only one
whose live-verified surface needs no correction: a single silently-overwriting `mcp add`, an
ideal side-effect-free `codex mcp get engram --json` probe, and an already-correct
`--bearer-token-env-var` auth form.

The two remaining tasks complete the executor's failure legibility (D-11) and the display-quoting
half of issue #523 (D-02), so the shared machinery is finished before Waves 2–4 expand it to the
other runtimes.

Purpose: prove the whole architecture end-to-end on one path before three more runtimes are
built on top of it, and close the two security controls (#523's argv form and display quoting)
that `02-SECURITY.md` names as preconditions of this phase.

Output: `internal/setup/apply.go`, `internal/setup/quote.go`, their tests, and a real
`setupApplyRun`.

Complete the executor's failure and capture policy. Nothing in this task may branch on the CONTENT of a runtime's stderr: engram reports rather than diagnoses (D-11), and `classifyOperatorErr`'s typed-cause-never-message-text discipline applies — stderr is carried as data and never string-matched to decide an `Outcome`.

Build the failure `Reason` from four components in a fixed order: the runtime's `Name()`, the failing action's `Command()` (the derived, quoted display of the exact argv), the numeric exit code, and the bounded captured stderr.
