<objective>
Make an invalid target set reject the whole call once, naming every offending target of one failure
class, without ever letting a caller learn that a record they cannot read exists.

Purpose: D-11 requires that a caller fixing a bad five-target set learns the full picture in one round
trip. INV-01 requires that the widened message echo the caller's own input strings and collapse
"not yours" into "does not exist". Those two requirements pull in opposite directions unless the
preflight is staged by class — and getting that wrong is how a merge becomes an existence oracle for
another actor's records.

Output: `resolveSupersedeTargets`, a staged-by-class preflight returning input-and-resolved-id pairs;
set-shape validation including an explicit maximum; a handler that gates every target before the
embed; and per-class rejection tests including the indistinguishability proof.
</objective>

<planner_decisions>
Three contract-shaped decisions CONTEXT.md left open. RESEARCH.md Open Question 1 flagged the first as
a genuine fork and recommended, but did not lock, the staged option.

- **PD-05 — staged-by-class preflight, existing sentinels, no new error type.** Each rejection keeps
  its current sentinel (`store.ErrInvalidArgument` via `argError`, `store.ErrAmbiguousShortID`,
  `store.ErrNotFound`, `errRuleImmutable`, `store.ErrAlreadySuperseded`) and widens only its *message*
  to name every offending target of that class, comma-joined, in the caller's input order. Rejected:
  a heterogeneous per-target `{target, reason}` envelope — a Connect response carries exactly one
  status code, so a mixed envelope forces an arbitrary choice of which code represents the whole call,
  and it would need a new wire shape. Rejected: reusing `argError.Fields` to carry target ids —
  `Fields` means *argument names* on every other rejection in the tree, and overloading it would make
  `field=` ambiguous for every existing parser. The `connecterror.go` sentinel-to-code switch is
  therefore UNCHANGED. Reversibility: costly — `docs-site/.../errors.md` publishes this as a
  machine-stable contract and narrowing it later breaks callers parsing the list.

- **PD-06 — the class order is fixed and documented.** A: set shape (empty, oversized, blank entry) →
  B: ambiguous short_id → C: not found or not owned → D: rule target → E: already superseded. One
  class per response; a later class is only evaluated once the current one is clean. A fixed order is
  what makes the rejection deterministic across concurrent runs; picking whichever class is
  encountered first per target is not.

- **PD-07 — `maxSupersedeTargets = 256`, rejected with the existing `too_many` hint.** SURFACED FOR
  DEVELOPER VETO: no CONTEXT.md decision addresses a cap, and D-15 explicitly declined capping the set
  *at 32* to eliminate the cross-chunk partial-application class. 256 is far above 32, so it does NOT
  close that class and does NOT contradict D-15 — its only job is bounding the amplification an
  authenticated caller can cause, since every target costs a resolve round trip and a held lock. If
  the developer prefers no bound at all, delete the constant and its check; nothing else in the phase
  depends on it. Reversibility: costly — it becomes a published input contract.
</planner_decisions>

Add the preflight to `internal/server/tools.go`.

Declare `const maxSupersedeTargets = 256` alongside the existing bound constants, with a doc comment
stating what it bounds and what it deliberately does not: it caps caller-driven amplification, since
every target costs a resolve round trip and a held lock; it is far above the server's payload-operation
chunk size and therefore does not eliminate the cross-chunk partial-application class, which is
covered by the store's reconciliation pass instead.

Declare `type resolvedSupersedeTarget struct { Input, ID string }` — `Input` is exactly what the
caller sent, `ID` is the canonical UUID. Every rejection message is built from `Input`; nothing
downstream of this function may build a caller-facing message from `ID`. Say that in the type's doc
comment: echoing a resolved UUID would hand back another owner's real id for a short_id the caller
guessed, which is the leak the 404-indistinguishability rule exists to prevent.

Add
`func (d *deps) resolveSupersedeTargets(ctx context.Context, c caller, inputs []string) ([]resolvedSupersedeTarget, error)`
implementing the fixed class order, each stage completing across ALL inputs before the next begins:

Class A — set shape. Reject an empty slice with the existing required-hint argument error on the
`supersedes` field. Reject a slice longer than the maximum with an out-of-range argument error using
the existing `too_many` hint, naming the bound and the received count but never echoing the values.
Reject any entry that is empty or whitespace-only with the malformed-shape argument error. All three
run before any store call.

Class B — resolution. Call `ResolvePointID` for every input, collecting each input whose resolution
returned the ambiguous-short-id sentinel. If any, return that sentinel wrapped with every ambiguous
input joined by comma-space, in input order. Inputs that resolve, and inputs that fail as not-found,
both carry forward to class C — a not-found from resolution and a not-found from the ownership gate
must be the same class, or the two become distinguishable.

Class C — existence and ownership. For every input that either failed resolution with not-found or
resolved successfully, call `FetchForUpdate` with the caller's subject and collect the input when it
returns not-found. If any, return the not-found sentinel wrapped with every collected input joined by
comma-space, in input order. This single stage is what makes "not yours" and "does not exist"
indistinguishable: a non-owned record fails the same gate, joins the same list, and produces the same
sentinel and the same count as a nonexistent id.

Class D — rule immutability. For every fetched record whose category is the rule category, collect the
input. If any, return the rule-immutable sentinel wrapped with every collected input, keeping the
existing guidance text about deleting the rule instead.

Class E — already superseded. For every fetched record whose `SupersededBy` is non-nil and non-empty,
collect the input. If any, return the already-superseded sentinel wrapped with every collected input.
Note in a comment that this stage is a preflight, not the authority: the store re-checks under lock
because a concurrent caller can supersede a target between this read and the write, and the store's
re-check is what closes that race.

On success return the pairs, deduped by resolved `ID`, preserving the first occurrence's `Input` and
the caller's input order. Reuse the same slice for the dedupe as the caller-facing echo, so a
duplicate never produces two entries in a later rejection message.

Add a package-level doc comment above the function recording the class order and why one class per
response is the shape: a Connect response carries exactly one status code, so a homogeneous rejection
is what keeps the existing sentinel-to-code mapping intact. Do not modify `connecterror.go`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| MCP client → `deps.supersedeMemory` | The whole `supersedes` array is attacker-controlled: count, content, and whether each id belongs to the caller |
| handler rejection message → MCP client | Every byte of a rejected tool call's error string is the wire payload; anything in it is disclosed |
| handler → embedder / short-id minter | Billable and Qdrant-hitting calls sit behind the preflight; a set that cannot succeed must not reach them |
