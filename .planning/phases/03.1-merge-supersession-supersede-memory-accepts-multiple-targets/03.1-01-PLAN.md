<objective>
Promote `supersedes` from a scalar to a set, end to end, and prove one real two-target merge
works through every layer it touches: the MCP argument struct, the handler, the store method,
the Qdrant payload writer, and the payload decoder.

decoder, `Store.Supersede(ctx, newMem, vec, targets []string, subj)` with sorted deduped

<assumption_delta_decision>
**Checkpoint:** assumption-delta — FIRED (`detected: true`, kind `pluralization`, term "multiple").

**Primary noun:** the supersession *target set* (`supersedes`).

**Decision:** `promote` — not `add-alongside`. `supersedes` becomes a list; the single-target call
becomes the one-element case of the general form. The wire shape is ALWAYS an array (D-03). The
decoder is tolerant (accepts a bare string or a list) with NO backfill command (D-04), because a
legacy scalar record loses nothing functionally under a tolerant read.

**Rationale:** `add-alongside` — keeping `supersedes` scalar and introducing a second plural key —
would leave the singular form required and silently contradict the generalized intent: two payload
keys encoding overlapping truth, and every future reader forced to know which one wins. Locked by
CONTEXT.md D-01/D-03/D-04 and confirmed by the developer.

**Not pluralized:** `superseded_by` stays scalar and is untouched (D-02). Each predecessor has
exactly one successor; the four `IsEmpty("superseded_by")` recall gates (`store.go:954`, `1054`,
`1191`, `1426`) are not modified by this phase. The pluralization is strictly one-directional.

**Companion invariant test (required by the checkpoint):** `TestSupersedeMultiStamp` uses N=3, not
N=1, precisely so that a future phase quietly reintroducing the singular assumption goes red rather
than passing on a degenerate case.
</assumption_delta_decision>

<planner_decisions>
Discretion items CONTEXT.md left to the planner, resolved here and load-bearing for the
whole phase:

- **PD-01 — duplicates are deduped, not rejected.** The *resolved* target-UUID set is deduped.
  `[A, A]`, and `[short_id_of_A, uuid_of_A]`, both mean `[A]`. Rationale: the wire form accepts a
  short_id or a UUID for the same record, so a duplicate is usually two spellings of one target,
  not caller error; rejecting would force the caller to resolve ids itself. The dedupe pass is
  mandatory regardless of this choice — `inProcessTargetLocker.Lock` wraps a plain `sync.Mutex`
  and is not reentrant, so locking one target twice on one goroutine hangs forever with no panic
  and no race-detector hit. Reversibility: reversible.

- **PD-02 — a merge MAY span scopes, categories, and visibilities.** No homogeneity requirement.
  Each target is independently owner-gated; homogeneity would add a rejection class with no
  security value and would block a legitimate cross-scope de-duplication. `rule` remains excluded
  for every target (INV-02). Reversibility: reversible.

- **PD-03 — the async summary queue is unchanged.** One `tryEnqueue` per successful write, and a
  merge of N targets still produces exactly ONE new record, so the existing single call at the
  handler tail is already correct. Confirmed by reading, not assumed.

- **PD-04 — `Store.Supersede`'s signature pluralizes.** No slice-taking sibling; callers pass a
  one-element slice for the degenerate case. This follows D-01's promote logic and keeps one code
  path. The store API is internal, so this is a code-shape call, not a contract call.
  Reversibility: reversible.
</planner_decisions>
