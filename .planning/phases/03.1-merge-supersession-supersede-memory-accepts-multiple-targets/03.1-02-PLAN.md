<objective>
Close the failure class this phase creates: a multi-ID `SetPayload` that errors has, at the pinned
Qdrant version, already stamped every target it found. Detect that, compensate the survivor, and
reconcile the targets — then prove it against a real Qdrant with a forced mid-sequence failure.

The single multi-ID back-stamp call stays exactly as plan 03.1-01 wired it, per D-06 as revised: it is
retained as the fast, common path for its batching and its smaller race window, NOT as an atomicity
guarantee. This plan adds only what that revision obligates.

Purpose: without the reconciliation pass, a *failed* merge permanently soft-hides live records.
Targets stamped before the error keep a `superseded_by` pointing at an id the compensating delete
just removed; that value is non-empty, so all four `IsEmpty("superseded_by")` recall gates drop
those records from `search_memory`, `list_memory`, `search_discovery`, and `list_scheduled` forever.
This failure class did not exist at N=1 and is the correctness core of the phase, not hardening.

Output: a compensating delete plus a reconciliation pass inside `Store.Supersede`'s lock scope, a
documented chunk-size constant, and `TestSupersedeMultiTOCTOU` asserting both that the error surfaces
and that no target is left dangling.
</objective>

<upstream_correction>
CONTEXT.md D-06 originally asserted that stamping all N targets in one multi-ID `SetPayload` made
partial stamping *unrepresentable*. That premise is FALSE and was verified false against the pinned
server's own Rust source (`qdrant/qdrant:v1.18.2`, `lib/shard/src/update.rs`): `set_payload` chunks
point ids by `PAYLOAD_OP_BATCH_SIZE = 32` and, within a chunk, runs
`apply_points_with_conditional_move(...)` — mutating every point that exists — BEFORE
`check_unprocessed_points(chunk, &updated_points)?` raises the missing-id error.

**An error from a multi-ID `SetPayload` means possibly-partial, never "nothing was written."**

D-06 was revised on 2026-08-10: the single call is retained as the fast/common path for its batching
and its smaller race window, NOT as an atomicity guarantee. D-07's compensating delete is necessary
but no longer sufficient. D-15 adds the reconciliation pass, and ROADMAP SC3 / REQ-merge-atomicity
were reframed from "not reachable" to "not observable". Do not plan or implement against the old
framing.
</upstream_correction>
