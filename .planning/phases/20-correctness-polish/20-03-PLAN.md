<objective>
Close #308 (MintShortID collision cap) — the store/shortid subsystem slice of Phase 20 (per D-10 subsystem split).

Bound `MintShortID`'s currently-unbounded collision-retry loop (`internal/store/store.go`, `for {}` around L1779) at 16 real Qdrant collision checks (D-04 — extra headroom over the ~8 already astronomically safe in a 32^10 Crockford base32 space), and return a wrapped sentinel `ErrShortIDExhausted` following the existing `ErrAmbiguousShortID` idiom (store.go:56 — package-level `errors.New`, `%w`-wrapped, `errors.Is`-checkable). Exhaustion bubbles up as a normal write failure through `store_memory`/`store_discovery`/`store_rule`. Per D-05, `seen`-map dedup hits (the in-batch `continue` around store.go:1786) MUST NOT consume the attempt budget — only real `Count()` calls count. Per D-06, exhaustion rides the existing telemetry deferred wrapper (store.go:1767-1772); no new metric.

Purpose: A pathological Qdrant state surfaces as a normal write error instead of hanging the request forever.
Output: `ErrShortIDExhausted`, a 16-capped `MintShortID`, and tests proving the cap and the seen-map budget rule.
</objective>
