  <name>Task 1: Add resetCommandFlagState — clear pflag's Changed latch between table rows</name>
  <files>cmd/engram/clienttest_test.go</files>
  <read_first>
    - `cmd/engram/clienttest_test.go` (the existing `resetClientFlags` helper and its doc comment about the latched `stringSliceValue.changed`, plus `runClient`)
    - `cmd/engram/root.go` (`rootCmd`, `Execute`, `exitCodeFromError`)
  </read_first>
  <action>
Add `resetCommandFlagState(t *testing.T, cmd *cobra.Command)` to `cmd/engram/clienttest_test.go`,
next to the existing `resetClientFlags`.

Why it is required: every cobra command in this binary is a package-level var shared across the
whole test binary, and `pflag.Flag.Changed` latches `true` the first time a flag is supplied. Every
mechanism this phase introduces (`ValidateFlagGroups`, `MarkFlagsMutuallyExclusive`,
`MarkFlagsOneRequired`, and koanf's changed-flag overlay in `config.Load`) branches on `Changed`,
not on the flag's value. Without a reset, row N+1 in a table sees row N's supplied flags as still
supplied and the whole table silently reports the wrong codes.

`pflag.Flag.Changed` is an exported struct field, so it can be cleared directly from this package.
The helper walks `cmd.Flags().VisitAll` and, for each flag, sets `f.Changed = false` and calls
`f.Value.Set(f.DefValue)` (ignoring the error for slice flags, which the existing
`resetClientFlags` already handles by nilling the Go var). It must walk the *root* command's
persistent flags too, via `cmd.Root().PersistentFlags().VisitAll` with the same body.

Register it via `t.Cleanup` in the same style as `resetClientFlags` so a row cleans up after
itself, and also expose it as a direct call so a table row can reset before it runs.

Do not modify `resetClientFlags` — the two are complementary: one resets the Go vars the flags
write into, the other resets pflag's own bookkeeping.
  </action>
  <acceptance_criteria>

    - `rg -c 'f\.Changed = false' cmd/engram/clienttest_test.go` returns at least 2 (own flags + root persistent flags).
    - A new test proves the latch is cleared: run `list` once with `--offset 1`, call the helper, then assert `listCmd.Flags().Changed("offset")` is `false`.
    - `go test ./cmd/engram/... -run 'TestResetCommandFlagState' -v` prints a RUN/PASS pair (not `no tests to run`).
    - `go vet ./cmd/engram/...` is clean.
  </acceptance_criteria>
  <verify>
    <automated>go test ./cmd/engram/... -run 'TestResetCommandFlagState' -v</automated>
  </verify>
  <done>A table row can supply a flag without contaminating any later row's `Changed` state.</done>

  <action>
Create `cmd/engram/exitcode_baseline_test.go` with the Apache-2.0 SPDX header (`task license:add`
applies it; `task license:check` gates it) and `package main`.

Declare the row type with exactly these fields:

  - `name string` — subtest key, e.g. `"list/offset+page-token"`
  - `args []string` — the full argv handed to `runClient`
  - `env map[string]string` — vars set with `t.Setenv` for the row
  - `before int` — the exit code observed against production code as it stands at this commit
  - `after int` — the exit code this phase claims the row will have once it ships
  - `changes bool` — the declared intent that `after != before`
  - `landed bool` — set to `true` by the later plan that actually moves the row
  - `introduced bool` — reserved for rows a later plan adds for a capability that does not exist yet
    (a flag or code with no meaningful `before`); such rows assert only `after` and are exempt from
    the distinct/identical rules

Declare `var exitCodeBaseline = []exitCodeBaselineCase{ ... }` at package scope so later plans edit
one literal.

Write three tests:

1. `TestExitCodeBaselineClaims` — a pure structural test over the table, no command execution:
   for every row with `changes == true` assert `after != before`; for every row with
   `changes == false` assert `after == before`; for every row assert `introduced` implies
   `!changes`. This is the memory `nczgrtfec2` discipline — a loose "codes are as expected"
   assertion passes while classification silently collapses, so the *claim itself* is typed.
2. `TestExitCodeBaselineRowCount` — assert `len(exitCodeBaseline)` equals an explicit integer
   literal, so a silently-deleted row fails rather than quietly shrinking coverage. Also assert
   every `name` is unique.
3. `TestExitCodeBaseline` — the observation test. For each row: `t.Run(c.name, ...)`, apply
   `c.env` with `t.Setenv`, call `resetClientFlags(t)` and `resetCommandFlagState(t, rootCmd)`,
   run `_, _, err := runClient(t, c.args...)`, compute `got := exitCodeFromError(err)`, and compare
   against `want := c.before; if c.landed || c.introduced { want = c.after }`.

Build on `exitCodeFromError` + `runClient` — **not** on `assertExitCode`. `assertExitCode`
`t.Fatal`s the moment an error lacks `ExitCode()`, which is precisely the untyped rows this table
exists to pin (flag-group errors, `config.CheckLegacy`, `buildRemapSource`); using it would abort
instead of recording "falls through to 1".

Do not mark subtests `t.Parallel()` — rows mutate process-global env and shared cobra flag state.
  </action>
