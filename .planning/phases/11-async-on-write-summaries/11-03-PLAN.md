## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client → MCP handler | Untrusted tool input authenticated + authorized at the existing `Upsert`; enqueue happens strictly after and adds no new crossing. |
| engram → summary gateway | Worker's outbound `/v1/chat/completions` call (529-brownout-prone), unchanged from v1, isolated off the synchronous write path. |
| process → OS signal (SIGTERM) | Shutdown drain rides the existing `signal.NotifyContext` + 15s window; ordering is the security-relevant surface here. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-11-02 | Denial of Service | storeMemory/scheduleMemory write-path availability | high | mitigate | Enqueue is a non-blocking tryEnqueue fired only post-Upsert; the handler returns unconditionally even with the summarizer down (SC#2). Verify: TestStoreMemoryReturnsWhenSummarizerHangs. |
| T-11-04 | Denial of Service (crash) | serve.go shutdown ordering | high | mitigate | Drain is invoked STRICTLY after `httpSrv.Shutdown(shutdownCtx)` returns and never in parallel — no HTTP handler can send on the enqueue channel once Shutdown returns, eliminating the send-on-closed-channel panic (D-08, RESEARCH Pitfall 1). Verify: drain call textually after Shutdown; `-race` handler tests. |
| T-11-01 | Denial of Service | queue construction bound | high | mitigate | buildDepsFromEnv sizes the channel from the validated ENGRAM_SUMMARY_QUEUE_SIZE; the AND-gate keeps it entirely absent (nil) unless explicitly opted in (D-01/D-03). |
| T-11-05 | Information Disclosure / Elevation | enqueue scope (D-06) + worker re-fetch | low | accept | Only store_memory/schedule_memory enqueue; discovery/rule (which own summaries) do not. The worker re-fetches via store.Get exactly as the existing summarize-missing sweep does — no new authz surface; summary derives only from already-authorized content. |
| T-11-SC | Tampering (supply chain) | backoff/v5 (consumed here) | high | mitigate | No install in this plan; backoff/v5 was audited OK and promoted to direct in Plan 11-01 (already resolved in go.sum). No new module fetch. |
