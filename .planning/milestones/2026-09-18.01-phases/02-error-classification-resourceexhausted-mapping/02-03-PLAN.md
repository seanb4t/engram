D-05 verification (ROADMAP note), recorded here as the plan that ships the doc: `internal/surfaces`
declares conditional-rule sentences only (`ConditionalRule.Hint` is a plain string referencing the
vocabulary); the vocabulary's single declaration is `argerror.go`'s const block. The surfaces
single-declaration pattern therefore does not cover hint codes, and this plan's gate closes the gap.

The operator tier gets the same code: `reindex`, `spine-review`, `prune-expired`, `summarize-missing`,
`migrate` and the other Subject-less operator commands read Qdrant directly (no Connect), so a sweep
whose own read overflows reaches `classifyOperatorErr` as `store.ErrResponseTooLarge` itself. That switch
is kept exhaustive over store sentinels by convention (Phase 1 01-05's classify-all decision), and this
sentinel has a live trigger there until Phase 5 bounds the sweeps — so it maps to `exitTooLarge` rather
than falling to the unclassified exit 1. This applies D-07's code; it does not add a new one.

No `internal/e2e` binary-level exit-10 subtest is added: `engram serve` dials Qdrant with no named receive
limit until Phase 5's REQ-recv-limit-backstop, so a binary-level overflow would depend on grpc-go's default
limit (rule m45p2b4bp7). The chain is proven in two halves joined at the Connect wire: plan 02-02 proves a
real named-limit overflow reaches a Connect client as `resource_exhausted`, and this plan proves the CLI
turns `resource_exhausted` into exit 10 through its real command path.
