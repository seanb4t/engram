<objective>
Classify a Qdrant response that exceeded the client's receive limit into one typed sentinel in
`internal/store`, in one place that covers every Qdrant RPC in production and in every test: a gRPC
unary client interceptor installed in `store.NewQdrantClient`'s base dial options (D-01). It relabels a
`ResourceExhausted` status ONLY when the message carries grpc-go's client-side receive-limit shape
(D-02), returning `*store.ResponseTooLargeError` — the stdlib `*fs.PathError`-style pair of an exported
sentinel (`store.ErrResponseTooLarge`, for `errors.Is`) plus an error type carrying the RPC method and
the observed/limit byte counts for server-side logs (D-03). The error keeps `GRPCStatus()` so every
existing `status.FromError` inspection keeps working (D-01). Every other error passes through as the
identical value.

Framing (D-00): upstream hooks and stdlib idiom only — grpc-go's own `WithChainUnaryInterceptor`, the
`status` package's `GRPCStatus()` contract, an exported sentinel plus a typed error. No wrapper option
type, no per-call-site handling (the #583 → #585 lesson). D-03 locks an error TYPE carrying method and
byte counts, so RESEARCH's multi-`%w` alternative (Open Question 1) is not taken.

Research correction (verified at planning time against the pinned module source): grpc-go v1.83.2 has
FOUR receive-side `ResourceExhausted` shapes, not three — `rpc_util.go:795` (received message larger
than max length allowed on current machine, two numbers), `:798` (received message larger than max, two
numbers), `:1008` (message after decompression larger than max, two numbers), `:1039` (received message
after decompression larger than max, one number — the shape Phase 1's real traffic produced). The
send-side shapes (`server.go:1215` with a `grpc: ` prefix, `stream.go:991/1496/1779` without one) say
"trying to send". The matcher below covers all four receive shapes and none of the send shapes.

Chain position (verified: qdrant-go-client v1.19.2 `grpc_client.go:34-55` appends `Config.GrpcOptions`
after its own metadata and rate-limit interceptors; grpc-go `clientconn.go:517-536` makes the first
chained interceptor outermost): the classifier sits INSIDE qdrant-go-client's rate-limit interceptor, so
a genuine server-side `ResourceExhausted` must pass through untouched for that interceptor's retry-after
handling to keep working (RESEARCH Pitfall 2). A caller option added with `grpc.WithChainUnaryInterceptor`
sits inside the classifier; one added with `grpc.WithUnaryInterceptor` is outermost of all.

Purpose: REQ-exhausted-sentinel; the sentinel every later lane (plan 02-02 Connect/MCP, plan 02-03 CLI)
and every later phase's regression test asserts.

Output: `internal/store/responsetoolarge.go`, one added base option in `NewQdrantClient`, a real-Qdrant
end-to-end regression over both fixture shapes, and synthetic-status unit tests for the matcher.
</objective>
