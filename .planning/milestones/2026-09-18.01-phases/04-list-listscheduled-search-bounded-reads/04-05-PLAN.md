<objective>
Turn the bound into a saving and the silent clamp into a refusal. With every read path now assembled
from budgeted RPCs, `Store.List` can finally request only the projection its caller needs — the
summary view excludes exactly the two fields that dominate a record's size — while the one visible
behavior that depended on always-full payloads, the server's no-summary truncation fallback, is
preserved through a shared content backfill rather than by reverting the projection. In the same
plan the store stops quietly shrinking an over-maximum count and starts refusing it, which is the
backstop under the server boundary's published rejection.

Decisions covered: Phase 3 D-04 read forward into this phase's read paths and 04-CONTEXT's
Claude's-Discretion item on the no-summary fallback; D-10's store-level backstop (including the
conversion of the cursor page's silent clamp into a rejection).

Purpose: REQ-list-bounded and REQ-search-k-bounded (the byte saving that makes a large count cheap),
REQ-list-contract-unchanged (the visible recall view does not move), REQ-list-limit-contract-decided
(the store half of reject-never-clamp).

Output: a projection-aware `Store.List`, a shared no-summary backfill, and pre-RPC rejections on
every recall entry point.
</objective>
