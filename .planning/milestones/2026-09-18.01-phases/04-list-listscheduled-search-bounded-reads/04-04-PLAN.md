<objective>
Split both search paths into a no-payload vector query and a batched, byte-budgeted payload fetch, so
a search can safely ask for any count up to the recall maximum without its single response
overflowing. The fetch re-applies the identical authz/recall filter the query used, which is exactly
why the two-phase shape is adopted here and was rejected for `List` in Phase 3 — the order is held by
the caller and the filter is re-applied, so the ordering and time-of-check risks that ruled it out
for `List` do not apply. A verifier should NOT look for Phase 3 D-05's `GetPoints`-order and
TOCTOU acceptance criteria here: this design has neither a `GetPoints` call nor an unfiltered
re-read.

Decisions covered: D-09 (two-phase search, its filter requirement, and its drop-on-disappear
semantics), D-02 (the recall maximum now also bounds a search count safely).

Purpose: REQ-search-k-bounded.

Output: a shared id-set payload fetch, two rebuilt search entry points, and the real-Qdrant
regressions that prove both stay under the named receive limit.
</objective>

and returns `RerankHits(query, hits, int(k))`.

and adds only a `MustNot` id-set condition, returning a NEW filter and never mutating `f`.
