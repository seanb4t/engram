
Its body builds `dialOpts` with capacity `2+len(opts)`, appends
`grpc.WithStatsHandler(otelgrpc.NewClientHandler())`, then

`qdrant.Config.GrpcOptions`. Its doc comment (the paragraph immediately above it) currently ends with
a sentence reserving the receive-limit backstop as a later requirement, and separately documents that
a caller passes a receive limit in upstream vocabulary,
`grpc.WithDefaultCallOptions(grpc.MaxCallRecvMsgSize(n))`, never through a wrapper option type.

`internal/store/storetest/storetest.go`:
`const RecvLimit = 4 << 20`; `func Dial(t testing.TB, recvLimit int, opts ...grpc.DialOption) *qdrant.Client`
builds its options through `dialOptions(recvLimit, opts)` and dials through `store.NewQdrantClient`.
`dialOptions` returns the caller's opts in order followed LAST by
`grpc.WithDefaultCallOptions(grpc.MaxCallRecvMsgSize(recvLimit))`, and its doc comment states the
reason: "so no caller-supplied option can widen the named limit."

Introspection facts, verified against the pinned dependencies — these decide what the test can
assert:
- `qdrant.Client` (go-client v1.18.3) holds only unexported fields (`clients`, `next`, `closeOnce`)
  and exposes NO accessor for its config or dial options. A constructed client cannot be inspected,
  so the assertion must sit on the option slice BEFORE it is handed to `qdrant.NewClient`.
- `grpc.MaxCallRecvMsgSize(n)` (grpc-go v1.83.2) returns the EXPORTED comparable value type
  `grpc.MaxRecvMsgSizeCallOption` with an exported `MaxRecvMsgSize int` field, so a type assertion
  reads the configured number back out.
- `grpc.WithDefaultCallOptions(...)` and `grpc.WithUserAgent(...)` both return pointer-backed
  `DialOption` values, so an interface comparison against the exact value a test constructed is an
  identity check and is safe.

`internal/store/qdrant_client_convergence_test.go` holds
`TestQdrantClientConstructedOnlyByNewQdrantClient` — the existing construction-site gate. It is the
model for "gate the shape we own, not the dependency's behaviour" and is NOT modified by this plan.
`internal/store/schemaversion_stamp_gate_test.go` holds `qdrantClientHolderAllowlist`, also
unmodified.

`internal/server/tools.go` calls `store.NewQdrantClient(host, port)` with no extra options — the

<ordering_trap>
Read this before touching the append order. It is the single highest-value thing in this plan.

The backstop option MUST be appended BEFORE `opts...`, exactly where the two existing base options
sit. grpc-go's default call options are last-wins, and `storetest.dialOptions` relies on that: it
appends its own `MaxCallRecvMsgSize(RecvLimit)` LAST specifically so no other option can widen the
limit a test names.

If the backstop is appended AFTER `opts...`, every existing oversized regression in this milestone
silently starts running at 64 MiB. None of them turns red. They all keep passing — and every one of
them stops proving the thing its own name claims, because the response that used to be bounded by
the mechanism is now simply under a much higher ceiling. That is the exact outcome
REQ-recv-limit-backstop forbids with the words "never relied on by a regression test", and it is
undetectable by reading the test results.

The ordering assertion in task 1 exists for this, and nothing else in the suite would catch it.
</ordering_trap>
</context>
