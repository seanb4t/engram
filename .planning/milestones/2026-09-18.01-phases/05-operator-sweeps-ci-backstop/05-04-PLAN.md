<objective>
Migrate the last two own-loop sweeps — `engram summarize-missing` and `engram reindex` — onto the
shared byte-budget iterator, and remove the two classification rows that stop being true the moment
their last direct emission disappears.

Decisions covered: D-01 (the last two hand-rolled loops are deleted; stateful bits become closure
state and early termination rides a sentinel), D-02 (no new characterization test — the 25 in-place
tests are it), D-03 (a real-Qdrant regression per sweep), D-04 (the full view is required for both:
one summarises content, the other embeds it).

Purpose: with these two gone, every site in the inventory routes through a shared primitive or
carries a written exemption, which is the closing half of REQ-bounded-read-mechanism.

Output: two deleted loops, two sentinels, a collection-aware reindex walk with its page accumulator,
two removed classification rows, and two new real-Qdrant regression files.
</objective>

`func (s *Store) scrollAllPoints(ctx context.Context, collection string, filter *qdrant.Filter, view readView, fn func(*qdrant.RetrievedPoint) error) error`.

`internal/store/summarize.go`, the loop this plan removes: a cursor walk of `filter` with a literal
`uint32(256)` limit and full payload. Its per-point body, in order: a mid-page
`if opts.Limit > 0 && res.Scanned >= opts.Limit { return res, nil }` early exit, `res.Scanned++`,
`fromPayload`, an `opts.OlderThan` age filter incrementing `res.Skipped`, a `shouldSummarize(m, opts.MaxChars)`

on both the failure and the filled paths. The loop returns `res, nil` when the cursor is exhausted.
`SummarizeResult` carries `Scanned`, `Skipped`, `Filled` and `Failed`.

`internal/store/store.go`, the loop this plan removes: `Store.Reindex`'s cursor walk. Two things
make it structurally different from every other site in this phase:
- It reads `source`, computed as `opts.Source` when non-empty else `s.collection`, and the
  target-differs guard and the existence check both key off that effective value. The iterator's
  collection parameter (plan 05-01) exists for exactly this caller.
- Its resume path calls `s.reindexTargetContents(ctx, opts.Target, pts)` once per PAGE with the
  whole page's points, and `store.go`'s own comment records why: "One Get per page keeps the lookup
  O(pages), not O(points)." That helper is unchanged by this plan.
Its scroll also sets `WithVectors` false, which the iterator now does for every caller.
`const reindexBatch = 256`; `batch` is `opts.Batch` defaulted to it. `ReindexResult` carries
`Scanned`, `Upserted`, `Skipped` and `Unchanged`.

`internal/store/schemaversion_recallgate_test.go`: `recallEmissionMethods` is exactly
`{Query, QueryBatch, Scroll, ScrollAndOffset, Count}` — `Get` is NOT in it, and a call to

`TestRecallEmissionSetIsCompleteAndClassified`'s second subtest asserts the union of the three
classification lists equals the derived set and prints missing and extra names by name through

`Store.SummarizeMissing` and `Store.Reindex`.

`internal/store/storetest`: unchanged — `RecvLimit`, `Shape` (`FewLarge` = 40 records of
