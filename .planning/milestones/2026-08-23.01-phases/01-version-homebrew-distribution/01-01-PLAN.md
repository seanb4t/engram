<objective>
Deliver the phase's one end-to-end contract: `engram version --output json` emits a machine-readable
payload, and the Homebrew cask's post-install hook is the consumer that asserts it. Both ends land
together so the contract is proven at the point it is created rather than assumed across a phase
boundary.

Implements D-01 (unconditional text default, no TTY detection), D-02 (cobra's built-in `-v/--version`
untouched), D-03 (`--output bogus` routes through the existing validator to exit 2), D-06 (the JSON
payload carries `version` and nothing else), D-07 (`version` writes its own minimal render pair),
D-08 (no `v` prefix on the version string), D-09 (quarantine strip first, then the version assertion),
D-10 (bash/zsh/fish completions and their removal on uninstall), and D-11 (verification is Go-only —
nothing here gates Homebrew's, Apple's, or GoReleaser's own behavior).

Purpose: `version.go:16` prints a bare string today, so a cask has nothing machine-readable to assert
against. Without this the install gate cannot exist, and Homebrew's `generate_completions_from_executable`
cannot substitute for it because it rescues a broken binary's failure to a warning.

Output: a `version` subcommand with a stable json lane, a behavioral test suite pinning the
text==json invariant, regenerated `--help`/catalog goldens, and a `homebrew_casks:` block in
`.goreleaser.yaml` whose post-install hook consumes exactly that json lane.
</objective>

**Go side — `cmd/engram/version.go`:**

Keep the Apache-2.0 SPDX header and `package main`. Declare a `versionDoc` struct with exactly one
exported field, `Version string`, tagged `json:"version"` — D-06 pins the payload to this single
field, because D-04's version string already folds the commit and dirty state in as SemVer build
metadata and a separate `commit` field would be a second spelling of the same fact.

Convert `versionCmd` from `Run` to `RunE` so an error can carry an exit code. In an `init()` in this
file, register the flag as `versionCmd.Flags().String("output", "text", …)` — the default is the
string literal `text`, hardcoded. Do **not** route it through `config.FlagDefault("output")` the way
`addClientFlags` and `addOperatorOutputFlag` do: that helper resolves to the empty string (the
`client.output` registry row carries no `Default`), which means "auto-detect from stdout", and
adopting it would silently make `engram version | cat` emit JSON. Write the flag's usage sentence to
state the divergence out loud, in the repo's correct-by-reading style: json or text, defaulting to
text always, and unlike every other `--output` flag in this binary this one never auto-detects from
