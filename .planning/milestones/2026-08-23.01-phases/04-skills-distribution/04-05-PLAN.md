<objective>
Close audit blocker B01 / GitHub issue #559: `internal/skills.Install`'s `FormatAgentsMD` branch
treats EVERY read error on the operator's AGENTS.md index as "no index exists", splices a fresh
document containing only the managed block, and overwrites the whole file — destroying every byte
outside the block while reporting the path in `Report.Wrote` with no error. Read and write
permission are independent, so a writable-but-unreadable `~/.codex/AGENTS.md` (or one hit by a
transient read failure) takes this path today.

The fix is one predicate at one call site: only confirmed nonexistence
(`errors.Is(readErr, fs.ErrNotExist)`) is the create case. Every other read error preserves the
file — zero index writes — and is reported as a skills failure that wraps the cause and names the
index path, while the independent skill-file pass (D-07) continues and the failure reaches the
`engram setup` row and the partial/total exit classification unchanged through the already-wired
`SkillsOutcome` → `AggregateOutcome` → `Classify` chain.

Purpose: REQ-skills-agents-md-fallback promises "content outside the block is left byte-for-byte
untouched." D-15 already refuses to guess at a region engram did not author when the file is
ambiguous; an unreadable file is the most ambiguous state of all, and the same refusal applies.

Output: the corrected `installAgentsMDIndex`, corrected seam documentation, and two regression
tests — one at the package boundary flipping the audit's own reproduction from red to green, one
at the CLI boundary proving the failure surfaces in the codex row and the exit code.

**Verification safety (MANDATORY — repo gotcha ryr82bf2s2, MEASURED in this phase):** an executor
previously ran the plan's own documented `engram setup --apply` against the operator's REAL `$HOME`
to build a verification fixture and overwrote the real MCP registrations for all three runtimes.
`--apply` always does registration AND skills with no opt-out (D-12). Every verify command and
acceptance criterion in this plan exercises the fake seams only — `fakeInstallEnv` in
`internal/skills`, and `withFakeSetupEnv` / the package-level `skillsEnv` seam in `cmd/engram` —
NEVER a live `engram setup --apply`, and never a real `$HOME`. If a live CLI invocation is ever
wanted, it must be the preview lane (no `--apply`) or run under an explicitly fake `HOME=` scratch
directory. No task in this plan needs either.
