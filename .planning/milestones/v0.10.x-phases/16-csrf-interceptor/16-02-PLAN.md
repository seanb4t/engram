<objective>
Install the Connect double-submit CSRF token interceptor into the write lane
(D-01 layer 2). Create `newConnectCSRFInterceptor`, gate it to the six write
Procedures via the generated constants (D-07 write-only allowlist), place it
between the subject and validate interceptors (D-02), fail closed on an empty
Owner (D-05), and reject with `CodePermissionDenied` (D-03). Thread the verify
function from serve.go through Register into mountConnect (mirroring the existing
connectResolver plumbing) and update every call site of the two changed
signatures. Prove the behavior with a permanent regression matrix (D-06, SC2,
SC3).

Purpose: no write RPC does real work without a session-bound, same-origin-secret
double-submit token — the transport-layer defense-in-depth behind
CrossOriginProtection.
Output: `internal/server/connectcsrf.go`, `internal/server/connectcsrf_test.go`,
mountConnect/Register wired for csrfVerify, and serve.go supplying the real signer.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser console (untrusted origin) → Connect write RPC | A cross-site page could attempt a state-changing write using the victim's ambient session cookie |
| resolved Subject (upstream interceptor) → CSRF interceptor | The CSRF layer must not blindly trust that an upstream interceptor already guaranteed a non-empty Owner |
| double-submit cookie vs echoed header | The attacker can force the cookie to be sent (ambient) but cannot read it to echo the header (same-origin secrecy) |

## STRIDE Threat Register (ASVS L1, blocking threshold: high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-01 | Spoofing / Tampering | write RPC interceptor | high | mitigate | Double-submit HMAC token required + validated on all 6 write Procedures before handler logic; proven by TestNoAnonymousWrite (Task 3) |
| T-16-06 | Elevation of Privilege | newConnectCSRFInterceptor (fail-open on reorder) | high | mitigate | D-05 independent re-read of Subject.Owner and fail-closed even if the upstream subject interceptor is later reordered/weakened; proven by TestConnectCSRFInterceptor_EmptyOwner |
| T-16-03 | Spoofing | token/Owner binding | medium | mitigate | Cookie value must verify for the resolved Owner (HMAC-bound); cross-owner cookie rejected — TestConnectCSRFTokenMatrix cell (d) |
| T-16-08 | Tampering | write-only allowlist drift | high | mitigate | csrfWriteProcedures keyed on generated Procedure constants (never hand-listed); exact-6 assertion + SC3 read-exempt table guard both drift directions |
| T-16-05 | Information Disclosure | rejection message | low | mitigate | Every rejection returns a fixed generic message, never err.Error(); acceptance grep confirms absence of err.Error() |
| T-16-04 | Tampering | Connect mux CORS posture | high | mitigate | TestConnectNoCORSHeaders kept green after the signature change (SC4 permanent gate) — verified in Task 2 |
| T-16-SC | Tampering | go.mod dependencies | high | accept | Zero new external packages (stdlib + existing connect/gen only) |
</threat_model>
