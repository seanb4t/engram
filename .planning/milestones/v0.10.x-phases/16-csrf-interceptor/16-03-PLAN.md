<objective>
Install the HTTP-layer primary CSRF defense (D-01 layer 1) and mint the
double-submit cookie so the whole mechanism is live end-to-end this phase. Wrap
the fully-assembled top-level mux with Go stdlib `net/http.CrossOriginProtection`
(D-07 whole-server wrap, verified safe), give it a custom `SetDenyHandler` that
emits the same Connect-shaped `permission_denied`/403 envelope as the interceptor
(D-04), and mint a non-HttpOnly `engram_csrf` cookie in `webauth.Handler.Callback`
alongside the session cookie.

RESOLVED OPEN QUESTION (RESEARCH § Open Questions Q1 / Assumption A1): this phase
DOES mint the CSRF cookie now, in Callback. Rationale: CONTEXT.md's "issuance
timing lands with the Phase-19 client" refers to the client-side ATTACH + silent
retry behavior, not cookie minting; minting here is a low-risk extension of the
existing Callback path (Owner is known) and makes SC2 live for same-origin browser
sessions this phase instead of stranding it until Phase 19. Tests do NOT depend on
the issued cookie — the plan-02 regression tests mint tokens directly via the
signer; the cookie-mint test here asserts the Set-Cookie shape independently.

Purpose: cross-origin browser writes are rejected at the HTTP edge before Connect
parses, uniformly shaped for the Phase-19 console, and a real cookie exists to echo.
Output: `cmd/engram/csrf.go` (CrossOriginProtection + deny handler), serve.go wrap,
Callback cookie minting, and SC1/D-04/cookie tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| cross-origin browser → top-level http.Handler | An attacker page issues a state-changing request using the victim's ambient cookies; must be rejected at the HTTP edge before Connect parses |
| deny-handler response → client | The rejection body must not leak internal error detail while still being a parseable Connect envelope |
| Set-Cookie(engram_csrf) → browser JS | The cookie is deliberately readable by same-origin JS (SC2) but must be Secure so it never crosses plaintext |

## STRIDE Threat Register (ASVS L1, blocking threshold: high)

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-16-01 | Spoofing / Tampering | CrossOriginProtection wrap | high | mitigate | Whole-server wrap rejects cross-origin unsafe-method requests via Sec-Fetch-Site/Origin (SC1); proven by TestCrossOriginProtectionRejectsCrossOrigin |
| T-16-05 | Information Disclosure | SetDenyHandler body | low | mitigate | Fixed generic message ("cross-origin request rejected"), never the underlying error text; asserted by the D-04 envelope test |
| T-16-04 | Tampering | CORS posture | high | mitigate | No AddTrustedOrigin/permissive CORS registered; strict same-origin; SC4 gate (plan 02) stays green |
| T-16-09 | Information Disclosure | engram_csrf cookie transport | medium | mitigate | Cookie is Secure + SameSite=Lax; non-HttpOnly is a deliberate SC2 requirement (JS must echo it), not a leak — same-origin secrecy is the load-bearing property |
| T-16-10 | Tampering | wire-name drift (issuance vs verification) | medium | mitigate | TestCSRFWireNamesMatch asserts server/webauth cookie+header name constants are equal |
| T-16-SC | Tampering | go.mod dependencies | high | accept | Zero new external packages (stdlib net/http + existing webauth/server) |
</threat_model>
