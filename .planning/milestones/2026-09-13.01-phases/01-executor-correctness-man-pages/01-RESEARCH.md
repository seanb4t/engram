## User Constraints (from CONTEXT.md)

### Locked Decisions

**Man-page determinism & header**
- **D-01:** `GenManHeader.Date` is pinned to a **fixed constant** in code (a release-independent date such as the Unix epoch), never left nil. cobra/doc renders `.TH`'s date as `"Jan 2006"` from `time.Now()` when `Date` is nil (honouring `SOURCE_DATE_EPOCH` only as a fallback), so the default is byte-stable merely within a calendar month. No env-var dependency: the cask hook runs on an end user's machine with nothing exported.
- **D-02:** `GenManHeader.Source = "engram <version>"` (the ldflags-injected `main.version`, the same value `rootCmd.Version` and `engram version` already report — a dev build reads `engram dev`) and `Manual = "Engram Manual"`. Re-running the same binary is byte-identical; the version changes only when the binary does.
- **D-03:** `rootCmd.DisableAutoGenTag = true` — set once on the root, propagated to every child by cobra/doc's `VisitParents` walk — so the `# HISTORY … Auto generated by spf13/cobra` footer (the last date-bearing surface besides `.TH`) is dropped from every page.
- **D-04:** Byte-stability is proven by a Go test that runs the generator twice into two temp dirs and requires identical bytes per file, plus asserts the `.TH` line carries the pinned date/Source and that no `HISTORY` footer appears. **No golden files** — a help-text edit must not force a regen across N pages. `cmd/engram/golden_test.go`'s harness is not extended for this.

**Man-page command coverage**
- **D-05:** The page set is **cobra/doc's default walk**, unfiltered: every command for which `IsAvailableCommand()` holds and that is not the help command. That means the visible `engram --help` tree **plus the `completion` subtree** (`engram-completion.1`, `engram-completion-zsh.1`, …), and automatically excludes the hidden `man` command itself, `help`, and the `Deprecated`-marked aliases (`backfill-short-ids`, `migrate-set-owner`). No filtering code; `cmdwalk.go` and `internal/surfaces` are untouched.
- **D-06:** A Go test derives the expected set from the live tree — walk `rootCmd` with cobra's own `IsAvailableCommand()` / not-help predicate, expect exactly `<dashed command path>.1` per command — and asserts `engram-man.1` and the deprecated aliases' pages are **absent**. It must not reuse `surfaces_test.go`'s `nonHiddenCommands()` helper, which deliberately skips `completion` and would disagree with D-05.

**Cask install/uninstall shape**
- **D-07:** `post_install` generates **straight into** `#{HOMEBREW_PREFIX}/share/man/man1`: `FileUtils.mkdir_p` the directory, then `system_command binary, args: ["man", man1_dir]`. No tmpdir, no copy loop. `system_command`'s default `must_succeed: true` raises on failure exactly as the completions step does — fail-closed, never Homebrew's rescuing helper and never the declarative cask `manpage:` stanza.
- **D-08:** `post_uninstall` removes exactly the pages the binary wrote by globbing `engram.1` and `engram-*.1` under `share/man/man1` and calling `FileUtils.rm_f` on each match — the file-scoped remover, never the directory, never `rm_rf`. No install-time manifest.
- **D-09:** The man step is **appended after completions** as the hook's fourth exercise of the installed binary: `xattr` strip → `version --output json` gate → completions → `man`. `TestReleaseConfigCaskInstallGate` extends its `checkOrdering` chain by one link (`args: ["completion"` → `args: ["man"`), counts exactly one non-comment `args: ["man"` occurrence, requires the uninstall glob string to appear exactly once, and adds `manpage:` to the forbidden-strings list alongside `generate_completions_from_executable`, `brews:`, `rm_rf`. Because those gates are literal occurrence counts, the hook's **comments must not spell `manpage:`** or name the helper either. — **Reversibility:** reversible — a config + test edit.

**Timeout row wording (osRun)**
- **D-10:** `osRun` adds `case ctx.Err() != nil:` as the **first** switch case and returns `RunResult{}, ctx.Err()` — the bare sentinel, covering **both** `context.DeadlineExceeded` and `context.Canceled` (Ctrl-C / parent cancel). Any context termination is "never got an answer" per `Environment.Run`'s documented contract.
- **D-11:** The `timed out` wording lives in `runSeam` (`internal/setup/apply.go`), the sole owner of `execTimeout` (20s): when `errors.Is(err, context.DeadlineExceeded)`, wrap as `fmt.Errorf("timed out after %s: %w", execTimeout, err)`. The row then reads `<runtime>: <argv>: timed out after 20s: context deadline exceeded` via the existing `describeSeamError`. `errors.Is` still resolves for callers; `Canceled` passes through unwrapped.
- **D-12:** The `RunResult` returned alongside a ctx error is the **zero value** — no partial stdout/stderr — matching `RunResult`'s doc ("only ever meaningful alongside a nil error"). Nothing on the error path reads it (`describeSeamError` takes only `err`).

### Pattern 1: `ctx.Err()`-first classification in a subprocess-exec seam
**What:** Check `ctx.Err()` before unwrapping `*exec.ExitError` from `cmd.Run()`'s return value, because a context-killed process still satisfies `errors.As(err, &exitErr)`.
**When to use:** Any `exec.CommandContext`-based wrapper that must distinguish "the process ran and exited badly" from "the process never got to finish because its context ended."
**Example — current buggy code, read verbatim this session:**
```go
// Source: internal/setup/environment.go:84-104 (this repo, current state)
func osRun(ctx context.Context, path string, args []string) (RunResult, error) {
	cmd := exec.CommandContext(ctx, path, args...)
	cmd.Stdin = nil
	var stdout, stderr bytes.Buffer
	cmd.Stdout = &stdout
	cmd.Stderr = &stderr

	runErr := cmd.Run()
	result := RunResult{Stdout: stdout.String(), Stderr: stderr.String()}

	var exitErr *exec.ExitError
	switch {
	case runErr == nil:
		return result, nil
	case errors.As(runErr, &exitErr):
		result.ExitCode = exitErr.ExitCode()
		return result, nil
	default:
		return result, runErr
	}
}
```
**Example — D-10's minimal fix (one new case, first in the switch):**
```go

	switch {
	case ctx.Err() != nil:
		return RunResult{}, ctx.Err()
	case runErr == nil:
		return result, nil
	case errors.As(runErr, &exitErr):
		result.ExitCode = exitErr.ExitCode()
		return result, nil
	default:

	}
```

### Pattern 3: cobra/doc's `GenManTree` — verified mechanics
**What:** `doc.GenManTree(cmd *cobra.Command, header *doc.GenManHeader, dir string) error` recursively walks `cmd.Commands()`, generating `dir/<CommandPath-with-spaces-as-dashes>.<section>` for every available command.
**Source (read in full this session):** `/Users/sean/go/pkg/mod/github.com/spf13/cobra@v1.10.2/doc/man_docs.go`
```go
// Source: cobra@v1.10.2/doc/man_docs.go:38-80 (verified read this session)
func GenManTree(cmd *cobra.Command, header *GenManHeader, dir string) error {
	return GenManTreeFromOpts(cmd, GenManTreeOptions{
		Header:           header,
		Path:             dir,
		CommandSeparator: "-",
	})
}

func GenManTreeFromOpts(cmd *cobra.Command, opts GenManTreeOptions) error {
	header := opts.Header
	if header == nil {
		header = &GenManHeader{}
	}
	for _, c := range cmd.Commands() {
		if !c.IsAvailableCommand() || c.IsAdditionalHelpTopicCommand() {
			continue
		}
		if err := GenManTreeFromOpts(c, opts); err != nil {
			return err
		}
	}
	section := "1"
	if header.Section != "" {
		section = header.Section
	}
	separator := "_"
	if opts.CommandSeparator != "" {
		separator = opts.CommandSeparator
	}
	basename := strings.ReplaceAll(cmd.CommandPath(), " ", separator)
	filename := filepath.Join(opts.Path, basename+"."+section)
	f, err := os.Create(filename)
	if err != nil {
		return err
	}
	defer f.Close()
	headerCopy := *header
	return GenMan(cmd, &headerCopy, f)
}
```
Note the loop filters **children before recursing**, but the CURRENT command (`cmd` itself, on every recursive call including the outermost) always gets a file — so `GenManTree(rootCmd, ...)` unconditionally generates `rootCmd`'s own page (root is never itself excluded by this predicate; only its children are, before descent).

## Common Pitfalls

### Pitfall 1: Reusing `nonHiddenCommands()` for the D-06 expected-set test
**What goes wrong:** `surfaces_test.go`'s `nonHiddenCommands()` (`cmd/engram/surfaces_test.go:107-109`) calls `walkCommands(rootCmd, commandWalkSkip)`, and `commandWalkSkip` (`cmd/engram/cmdwalk.go:23`) explicitly returns true for `cmd.Name() == "completion"` — deliberately excluding the whole `completion` subtree from every catalog/golden/flag-group gate in this repo.
**Why it happens:** It looks like the obvious "give me every visible command" helper, and it IS the right helper for every other test in this repo.
**How to avoid:** D-06's man-page test must derive its own expected set by walking `rootCmd.Commands()` recursively and testing `IsAvailableCommand()` / `IsAdditionalHelpTopicCommand()` directly (cobra's own predicate, quoted above) — the same predicate `GenManTree` itself uses — never `commandWalkSkip`. The two predicates genuinely disagree on `completion`, and D-05 requires the man-page test to agree with cobra's predicate, not this repo's catalog-scoped one.
**Warning signs:** A man-page expected-set test that imports or calls `nonHiddenCommands()`/`commandWalkSkip` will silently expect zero `engram-completion*.1` files and pass — until someone notices the cask actually installed pages the test never checked for.

### Pitfall 2: `#{` interpolation truncation in `releaseconfig_test.go`'s comment stripper
**What goes wrong:** `stripComment` (`cmd/engram/releaseconfig_test.go:14-29`) strips a line at its first `#`, EXCEPT when that `#` is immediately followed by `{` (Ruby string interpolation, e.g. `"#{HOMEBREW_PREFIX}/share/man/man1"`). Any new Ruby line for the man-page hook that puts a bare `#` before an interpolation in an unexpected position, or that the test's own `#{` lookahead doesn't anticipate, silently truncates to nothing under `nonCommentLines`.
**Why it happens:** `gotcha 6dt7nh9tse` (durable memory, already cited in CONTEXT.md) — a plan-time `rg`/string-match gate over `.goreleaser.yaml` is a one-shot check that breaks the moment the Ruby source shape changes even slightly.
**How to avoid:** Write the man-page hook's Ruby lines the same way the existing completions loop does — using `#{HOMEBREW_PREFIX}/...` interpolation only inside string literals, never a bare `#` as an actual Ruby comment marker inside a line that also needs to be matched by `countMatches`/`checkOrdering`. Verify any new literal the test greps for is not itself preceded by an un-escaped `#` on the same logical line.
**Warning signs:** `TestReleaseConfigCaskInstallGate` reporting "expected a non-comment line containing X, found none" for a literal that is visibly present in `.goreleaser.yaml` — the classic symptom of the comment-stripper eating a real line.

### Pitfall 3: `execTimeout` as a `const` blocking a short-deadline test
**What goes wrong:** `execTimeout = 20 * time.Second` (`apply.go:25`) is a package-level `const`, not a variable — a test that wants to exercise `runSeam`'s real 20-second timeout end-to-end cannot shorten it without either waiting 20 real seconds or restructuring the constant into a var/seam.
**Why it happens:** D-12/D-11 do not ask for `execTimeout` to become configurable; that would be a scope expansion CONTEXT.md never authorized.
**How to avoid:** Do not test `runSeam`'s wrap by racing the real 20-second timeout. Test it exactly the way `apply_test.go`'s existing `probe-seam-error-under-apply-fails` subtest already tests seam errors (`internal/setup/apply_test.go:193-208`): inject the error directly via `scriptedResult{Err: context.DeadlineExceeded}` on the FAKE `Environment.Run`. Since `runSeam`'s new wrap logic runs on whatever `env.Run` returns — real or fake — this exercises the exact `errors.Is`/`fmt.Errorf` wrap logic without waiting for any real timer, and is the correct level to test D-11 at (D-10's own real-subprocess test, in a *different* file, is the one that needs a genuine live deadline).
**Warning signs:** A new test in `apply_test.go` that calls `time.Sleep(21 * time.Second)` or otherwise waits out `execTimeout` for real — this is both slow and untestable in CI budgets, and is never necessary given the existing fake-`Environment` idiom.
