**Heading:** `## Unreleased — One CLI exit-code taxonomy, enforced flag groups, and a client request
timeout`. Do not hand-author a version number. release-please computes the next version from commit
messages at merge time and syncs `charts/engram/Chart.yaml` and the skill plugin manifest, but not
this file — a hand-written `v0.13.0` here could contradict whatever is actually cut. Add an HTML
comment directly under the heading instructing the releaser to replace `Unreleased` with the cut
version.

Sub-sections to write, each naming the affected commands explicitly:

  1. **Framework flag errors now exit 2, not 1.** An unknown flag, an unparseable flag value, and a
     violated mutually-exclusive flag group all exit 2. Retract the previous published guidance that
     told callers not to assume every usage-shaped failure exits 2. Name the two remaining exit-1
     cases: a mistyped verb (rejected during command resolution, before any engram hook runs) and a
     genuinely unclassified internal error.
  2. **Operator commands now return classified exit statuses.** Name every one:
     `reindex`, `prune-expired`, `summarize-missing`, `backfill-short-ids`, `migrate-remap-owner`,
     `migrate-set-owner`, `serve`. State the vocabulary (2 bad flag or configuration value, 4
     missing target, 5 backend unreachable) and the single documented exception: `serve`'s listener
     failing to bind still exits 1, because 5 means "the remote backend is unreachable" everywhere
     else in this taxonomy.
  3. **`--page-token` with `--offset` is now an error.** Previously `--page-token` silently ignored
     `--offset`. State the widened radius plainly: cobra's flag groups count a *supplied* flag, not
     its value, so `--offset 0 --page-token ""` is rejected too. Same for `--scope` with
     `--cross-spine=false` on `search` and `list`.
  4. **New exit code 6 for a request timeout.** Distinguish it from 5. Anyone branching on 5 to mean
     "retry later" should decide whether a timeout warrants raising `--timeout` instead.
  5. **New client `--timeout`, default 30s, and `0` is rejected.** Call out the divergence
     explicitly: the operator commands' pre-existing `--timeout` still treats `0` as unbounded. Same
     flag name, opposite zero-semantics, different commands — a reader must not have to infer it.
  6. **Client configuration now resolves through the `ENGRAM_` registry.** `--server`,
     `--token-file`, `--output`, `--insecure`, and `--timeout` all resolve flag-then-environment-
     then-default. Note that `ENGRAM_TIMEOUT` is new and that `--insecure` deliberately has no
     environment fallback.
  7. **In-repo consumer audit** — the table from Task 1, plus the external-posture statement.

Then add one line to `RELEASING.md`'s checklist: before or as part of cutting the release, rename
any `## Unreleased` heading in `docs-site/src/content/docs/guides/upgrade.md` to the version being
cut. Place it alongside the existing release-please steps so it is not a free-floating note.

Every sub-section's list of affected commands must be derived from the baseline table's
`changes: true` rows, not from memory — Task 3 asserts exactly that.
