  <action>
Each of the three client verbs passes `cmd.Context()` straight into its single Connect call today,
and `newHTTPClient` sets no transport timeout, so a server that accepts the connection and never
writes a response blocks the invocation forever.

At each of the three call sites, immediately after the `clientFromFlags` call and before the RPC:
derive `ctx, cancel := context.WithTimeout(cmd.Context(), timeout)` using the duration
`clientFromFlags` returns, `defer cancel()`, and pass `ctx` — not `cmd.Context()` — to the Connect
method. Add the `context` import where it is not already present.

Do not add a `http.Client.Timeout` in `newHTTPClient` as well. A transport-level timeout would fire
as a plain I/O error that connect-go reports as `CodeUnavailable`, which would land on 5 and
silently defeat the 5-versus-6 distinction this phase just created. The context deadline is what
connect-go surfaces as `CodeDeadlineExceeded`, and that is the only path that reaches `exitTimeout`.

Do not derive a second deadline anywhere, and do not read the timeout from config again at these
sites — `clientFromFlags` is the single resolution point.

Leave every other line of each `RunE` untouched: the request message construction, the rendering
path, the coverage footer, and each command's error wrapping through `wrapRPCError`.
  </action>

  <action>
Create `cmd/engram/timeout_test.go` (Apache-2.0 SPDX header, `package main`).

The hung server: start an `httptest.Server` whose handler blocks on the request context's `Done`
channel and never writes a response body or status. Blocking on the request context — rather than
`time.Sleep` — is what makes the handler unblock the instant the client hangs up, so the test does
not leak a goroutine for the life of the suite. Do not use a bare `net.Listener` that only accepts:
the Connect client needs a real HTTP endpoint for the deadline to surface as
`CodeDeadlineExceeded` rather than as a transport error.

The closed-port case: open a listener on `127.0.0.1:0`, record the address, close it immediately,
and use that address. Do not hard-code a port.

Write `TestTimeoutHungServerExitsTimeout` covering the three hung rows, and
`TestTimeoutDistinctFromUnavailable` covering the closed-port row plus an explicit assertion that
the hung-case code and the closed-port code are not equal. Per memory `nczgrtfec2`, an assertion
that both are "nonzero" or "as expected" passes while the classification collapses; assert the
values and their inequality.

Write `TestTimeoutSuccessInsideDeadline` for the responsive-stub row, asserting exit 0 and that the
rendered output matches what the same call produces today — the deadline must add nothing to the
success path.

Keep every timeout short (a few hundred milliseconds for the hung rows) so the package suite stays
inside its 60s budget, and call `resetClientFlags(t)` plus `resetCommandFlagState(t, rootCmd)` in
each subtest. Run the file under `-race`, since the hung handler and the client run concurrently.
  </action>
