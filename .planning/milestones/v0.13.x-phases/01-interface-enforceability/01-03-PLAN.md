<objective>
Declare every client setting in the one place this binary already treats as the single source of
truth for configuration, so `--timeout` is the *first field declared the new way* rather than a
fourth hand-rolled resolver (D-04).

Purpose: the phase goal is "one contract, declared where enforced". Configuration is the second of
the three mechanisms (after flag shape, before error classification) where a second implementation
was creeping in.
Output: five `client.*` registry rows, a `ClientConfig` struct, a deliberately-separate
`ValidateClient`, and a `config.Load` overlay that can bind a non-string flag.

This plan touches only `internal/config`. It changes no CLI behavior and shares no file with any
other plan in this wave; plan 01-07 consumes what it produces.
</objective>

`Load`'s overlay currently reads a changed flag with `flags.GetString(name)`, which returns an error
for any flag whose type is not string. That is fine today only because every registry-bound flag in
`serve.go` is registered as a string flag. D-04 puts `--insecure` (a bool, and it must stay a bool
so a bare `--insecure` keeps working) into the registry, so the overlay must read a flag of any
type.

Replace the value read with `flags.Lookup(name).Value.String()`. The `Changed(name)` guard already
ran, so `Lookup` is non-nil. `pflag.Value.String()` returns the canonical string form for every
flag type this registry will ever carry, and for a string flag it returns exactly what
`GetString` returned — so the change is behavior-preserving for all 20+ existing rows.

Keep the `err`-returning shape of the loop for the surrounding code, or simplify it if no error
path remains; do not silently swallow a nil `Lookup`.

Add `TestLoadOverlayBindsNonStringFlag` to `client_validate_test.go` covering the three behaviors
above, plus one regression case asserting an existing string-flag row (`server.listen_addr` via
`--listen-addr`) still overlays correctly.

## Flagged assumptions

- Registry rows with an empty `Env` are assumed harmless to `envToKey`'s map builder (they collapse
  to a single `""` key that `Load`'s TransformFunc ignores). Task 1 requires reading the builder to
  confirm; if the collision is not benign, guard the builder rather than inventing env vars for
  `client.token_file`/`client.output`/`client.insecure`.
- `pflag.Value.String()` is assumed to return the plain value for a `String` flag (not a quoted or
  bracketed form). Task 2's regression subtest on an existing string-flag row exists to catch this.

No probe-surfaced edge item is left unresolved by this plan.

**E-17** (concurrency) is this plan's one backstop marker, for the reason recorded inline on it.
