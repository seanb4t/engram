Why it is required: every cobra command in this binary is a package-level var shared across the
whole test binary, and `pflag.Flag.Changed` latches `true` the first time a flag is supplied. Every

supplied and the whole table silently reports the wrong codes.

`pflag.Flag.Changed` is an exported struct field, so it can be cleared directly from this package.
The helper walks `cmd.Flags().VisitAll` and, for each flag, sets `f.Changed = false` and calls
`f.Value.Set(f.DefValue)` (ignoring the error for slice flags, which the existing
`resetClientFlags` already handles by nilling the Go var). It must walk the *root* command's
persistent flags too, via `cmd.Root().PersistentFlags().VisitAll` with the same body.

Register it via `t.Cleanup` in the same style as `resetClientFlags` so a row cleans up after
itself, and also expose it as a direct call so a table row can reset before it runs.

Do not modify `resetClientFlags` — the two are complementary: one resets the Go vars the flags
write into, the other resets pflag's own bookkeeping.

### Why exactly these three are backstops

A backstop is not "hard to test" and it is never a place to park work. It is reserved for a claim
where **no automated acceptance criterion can defensibly prove it**, so the honest outcome at verify
time is `human_needed` rather than a green tick earned on the wrong evidence.

- **E-10 — temporal provenance.** The claim is that the `before` column was *observed* against
  production code as it stood at 01-01's commit. By the time the end-of-phase verifier runs, plans
  02-08 have changed that code, so `go test -run TestExitCodeBaseline` now exercises the *after*
  state. A green run at verify time confirms something other than the claim — exactly the
  silent-pass-on-wrong-evidence failure a backstop exists to stop. The re-runnable half (this plan's
  commit touches no production `.go` file; rows are order-independent under `-shuffle=on`) is split
  out and kept as ordinary plain truths.
- **E-11 — the deadline boundary.** "Just inside the deadline" means responding at `T - epsilon`. Any
  assertion at that boundary is a timing race against CI scheduler jitter, and this phase's own
  validation contract caps feedback at 60s with no tolerance for flaky tests. The neighbouring
  non-boundary cases *are* automated as plain truths in 01-08 (well inside the deadline exits 0; a
  never-responding server exits 6; 5 and 6 asserted DISTINCT in the same run) — what stays backstop
  is only the boundary itself.
- **E-17 — cross-invocation configuration immutability.** Real concurrency for this binary is
  process-level: each invocation is its own process, and no Go test can assert a cross-process
  property. The one in-process harness available — driving the shared cobra command tree from
  parallel goroutines under `-race` — races on pflag's package-global `Changed` latches, which is
  precisely why `resetCommandFlagState` exists in this plan. Such a test would report races that are
  not the property under test, which is a false signal, not a proof.

### Why the fourth marker was demoted, not deleted

The plan set previously carried a fourth structured marker on E-04 ("a flag-group rejection performs
no I/O, so no concurrent or interrupted call can observe partially-applied state"). It is now a plain
truth in 01-02. The property reduces to *the rejection path performs zero I/O*, which is finitary and
already asserted there by an accept-counting listener; extending that assertion to a set of
rejections driven concurrently against one shared counter is non-flaky and needs no timing window.
Nothing was dropped — the claim survives verbatim, with a stronger disposition.
