<objective>
Give the four sweep-style operator commands the same error contract as the client verbs (D-03).

Purpose: "one taxonomy" is only true if it reaches the commands a CI job actually schedules. Today
`reindex`, `prune-expired`, `summarize-missing`, and `backfill-short-ids` return plain errors that
all land on exit 1, so a script cannot tell "fix your flags" from "retry later".
Output: a single classifier modeled on the existing `connectError` shape, plus its four call sites.

`migrate-remap-owner`, `migrate-set-owner`, and `serve` are classified in plan 01-06 — they share
`migrate.go`/`serve.go` with earlier work and carry their own decisions.
</objective>

    - `classifyOperatorErr(nil)` returns nil.
    - A `store.ErrNotFound`-wrapping error yields a `*cliError` with `exitNotFound`.
    - `store.ErrInvalidArgument` and `store.ErrAmbiguousShortID` each yield `exitUsage`.
    - `store.ErrShortIDExhausted`, `store.ErrIdempotencyConflict`, `store.ErrAlreadySuperseded` each yield a classified, non-generic code (choose per the store's own semantics and record the choice).

    - A gRPC `codes.Unavailable` error and a raw dial failure each yield `exitUnavailable`.
    - `context.DeadlineExceeded` and `context.Canceled` each yield `exitUnavailable`.
    - An error that already carries `ExitCode()` is returned unchanged (idempotent — a doubly-classified error keeps its first code).
    - An unrecognized error is returned unchanged and therefore still reaches `exitGeneric`.

  <action>
Create `cmd/engram/operror.go` (Apache-2.0 SPDX header, `package main`) exporting
`func classifyOperatorErr(err error) error`.

Why a new function rather than reusing `exitCodeForConnectErr`: the operator commands never dial
through the Connect handlers. They call `server.StoreFromEnv()` / `StoreAndEmbedderFromEnvNoEnsure()`
/ `StoreAndSummarizerFromEnv()` and then a `store.*` method directly, so a store or Qdrant error
never becomes a `*connect.Error` and `connect.CodeOf` would report `CodeUnknown` for all of them.

Mirror `connectError`'s structure exactly: an `err == nil` early return, then a single `switch`
with `errors.Is`/`errors.As` arms, then a default. Two ordering constraints carry over and must be
respected and commented:

  - Any arm matching a wrapper type whose `Unwrap()` returns a sentinel must precede the arm for
    that sentinel, or the sentinel arm swallows the wrapper's own class. Read `connectError`'s
    `*argError`-first comment and STATE.md's durable record `667p88n2be` before ordering the switch.
  - The already-classified check (`errors.As` for `interface{ ExitCode() int }`) must be the very
    first arm, so a client-typed error passing through an operator path is not re-classified.

Construct results as `&cliError{code: ..., err: err}` — do not invent a second error-carrier type.
Add sibling constructors alongside `usageErrorf` in a small block in this file:
`notFoundErrorf` and `unavailableErrorf`, each following `usageErrorf`'s exact shape. Place them
here rather than in `client_common.go` so this plan owns one file and the constructors sit next to
their only consumer.

For the gRPC-unavailable arm, read what a failed Qdrant dial actually returns from
`internal/server/tools.go`'s construction path before choosing the predicate; prefer
`google.golang.org/grpc/status`'s `status.Code(err) == codes.Unavailable` over string matching. If
the dial failure arrives as an opaque wrapped error with no gRPC status, record that in the SUMMARY
and classify by the construction site instead (the call site knows it was building the store), not
by matching the message.

Do **not** map `exitAuth` (3) in this classifier. None of these commands authenticates against the
server — they bypass the OIDC/Connect chain entirely — so there is no live trigger, and a mapping
with no trigger is a claim the binary cannot honor.

Write the behavior table above as `TestClassifyOperatorErr` in `cmd/engram/operror_test.go`, and add
`TestClassifyOperatorErrCodesAreDistinct`: build the set of codes produced across all sentinels and
assert the expected distinct values with `reflect.DeepEqual` on a set, copying
`TestCatalogExitCodesMatchMapper`'s set-equality discipline. A test asserting only "not 1" still
passes when every class collapses into a single code.
  </action>

## Flagged assumptions

- **RESEARCH A2:** no live trigger exists today for `exitAuth` (3) from any operator command,
  because none authenticates against the server. This is a documented absence, not a forced
  mapping; if a future auth-gated operator path lands, revisit the classifier.

  determinable by reading `internal/server/tools.go`'s construction path. Task 1 requires confirming

  on an operator path is a judgment call this plan delegates to the executor, constrained to the
  existing 2/4/5 vocabulary and required to be recorded in the SUMMARY with its rationale.
