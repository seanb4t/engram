<objective>
Build the conformance gate that fails CI the moment a declared conditional rule's canonical sentence
diverges from any surface that advertises the rule's fields.

Purpose: REQ-surface-conformance-gate. D-05 widens the requirement's two surfaces to six; D-08
requires applicability be derived from the fields a rule names rather than declared per rule, so a
failing gate cannot be silenced by shortening a list. Two mechanisms make this non-trivial and are
built here: the `registerTools` seam (without it, no test can read the real MCP tool Descriptions
without live Qdrant/embedder config) and the field-name normalizer (without a correct one, a rule
silently resolves to zero surfaces and passes).

Output: the extraction seam, the normalizer plus surface-applicability resolver, and the gate itself
split across the three packages that can each see their own surfaces.

**Roadmap note for the verifier:** the six-surface scope is CONTEXT.md D-05, an accepted expansion
of REQ-surface-conformance-gate's stated two. The `/gsd-phase` roadmap edit recording this is the
user's outstanding action and is deliberately not performed by any task here (rule `8dfdhfs5nn`).
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
