# Phase 03.1 Plan 01: End-to-End Multi-Target Supersede Summary

**`supersede_memory`/`Store.Supersede` promoted end to end from a single scalar target to a deduped, sorted, lock-safe target set — new `Memory.Supersedes []string`, a `setPayloadKeys` fault seam with inline back-stamp-failure compensation, and a typed `*MultiTargetError` — proven by a real two-and-three-target merge against Qdrant plus concurrency and legacy-decode regression tests.**

## Performance

- **Duration:** ~25 min (not precisely instrumented at start; bounded by container/session timestamps)
- **Tasks:** 3/3 completed
- **Files modified:** 8

## Accomplishments

- `Memory.Supersedes` promoted `*string` → `[]string`; `payload()` writes a `[]any` list (mirroring the existing `citations` list-write pattern); `supersedesFromPayload` is the sole, `Kind`-branching, tolerant decode call site (bare string OR list, never an unconditional `GetStringValue()`).
- `Store.Supersede(ctx, newMem, vec, targets []string, subj)`: `lockTargets` clones/sorts/dedupes before acquiring per-target locks in sorted order (D-10 — two overlapping concurrent merges can never hold each other's next lock); the ownership gate and already-superseded checks both run over the full deduped set before any write; one multi-ID back-stamp lands through the new `setPayloadKeys` fault seam.
- Minimal, same-commit compensation: on a back-stamp failure, the survivor is deleted and `superseded_by` is cleared (via `DeletePayload`, never an empty-string write) from every target still pointing at it, then the original error is returned unchanged — so no commit in this wave can leave a dangling link.
- `*MultiTargetError{Err, IDs}` (PD-10): the already-superseded rejection now carries every offending canonical id, `errors.Is`-compatible via `Unwrap`, `errors.As`-recoverable by the handler tier without parsing prose.
- `memStore.Supersede` and `spyStore.Supersede` pluralized; the spy's gates (ownership, already-superseded) and its back-stamp loop over the FULL target set, proven non-vacuous by `TestSpyStoreSupersedeGatesEverySetMember` (a two-element set failing on the SECOND member).
- `supersedeArgs.Supersedes []string`; `deps.supersedeMemory` resolves every entry, dedupes the RESOLVED set (never the caller's spellings — mandatory because the in-process locker is non-reentrant), gates ownership + rule-immutability for every target before the billable embed, and re-wraps `ErrNotFound` with the caller's ORIGINAL joined inputs (never a resolved UUID).
- Decoder tolerance pinned: a table test drives `supersedesFromPayload` directly with hand-built payloads (bare string / 3-element list / absent key / list-with-empty-string / zero-length list); a legacy-scalar record written via raw client `Upsert` (bypassing `payload()`) decodes to a one-element list, not empty.
- Dedupe-before-lock and sorted-acquisition proven: a 3x-repeated target completes within a bounded 5s wait instead of self-deadlocking the non-reentrant per-target mutex; two goroutines merging `{A,B}` and `{B,C}` both terminate (bounded 10s wait) with exactly one success and one `ErrAlreadySuperseded` conflict, and the losing call's non-shared target is never stamped. All three concurrency-adjacent tests pass under `-race`.

## Decisions Made

- **Ownership-gate vs already-superseded collection asymmetry (deliberate, not an oversight):** `Store.Supersede`'s ownership loop is first-failure-wins (matches pre-phase `getWritable` semantics — no typed multi-offender shape exists for that class); the already-superseded loop collects every offender into `*MultiTargetError.IDs` because PD-10 explicitly requires it. Both loops still iterate every target before any write, satisfying D-05.
- **`lockTargets` does not touch `newMem.Supersedes`:** the field holds whatever order the caller/store method received (per its doc comment); `TestSupersedeMultiStamp` supplies its three target UUIDs already lexically sorted so the round-trip assertion is deterministic without implying the store re-sorts caller-supplied `Supersedes` content.
- **No `minItems`/`maxItems` jsonschema constraint added to `supersedeArgs.Supersedes`:** the tag is descriptive prose only (matching every other array field in this codebase — no `jsonschema:"minItems=..."` precedent exists), and per the 03.1-00 ruling no maximum is ever advertised.
