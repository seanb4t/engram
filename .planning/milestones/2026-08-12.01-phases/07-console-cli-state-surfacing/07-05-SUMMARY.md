**Closed issue #505 structurally (one-line fix: route renderOperatorView's headline through sanitizeViewValue) as a precondition, then shipped `engram get <id|short_id>` — the ungated GetMemory verb rendered through the typed operator view with a state-bearing, sanitized headline.**

## Accomplishments

- `renderOperatorView`'s headline write is routed through `sanitizeViewValue` — the exact same sanitizer the field path already used — closing issue #505 (D-11, threat T-07-01) by construction rather than by convention. Confirmed RED before the fix (`TestRenderOperatorViewSanitizesHeadline`'s ESC and DEL subtests failed with the raw control byte still present) and GREEN after, with the full `cmd/engram` suite (19 `renderOperator(` call sites, derived via `rg`, not asserted as a premise) unchanged.
- `engram get <id>` fetches one memory over the ungated `GetMemory` RPC — no `--full` flag, `cobra.ExactArgs(1)`, `addClientFlags` (never `addOperatorOutputFlag`) — and renders it through `renderOperatorView` via a single `protojson.MarshalOptions{UseProtoNames, EmitDefaultValues}` marshal shared by both the text and json lanes, so the text field set cannot widen past the json document.
- `getHeadline` builds `record {short_id}` plus `memoryStateWords`' canonical-order state words in parentheses, comma-space-joined, when the record carries non-default state — deliberately diverging from the STATE table cell's comma-no-space join (cell optimised for `cut`/`awk`; headline is prose), while both draw from the same D-13 derivation.
- `internal/surfaces/toolclass.go`'s existing `get_memory` row gained `CLICommand: "get"` (no second row); `operatorCommands()`'s doc comment was re-derived onto the structural grounds (`Lookup("server") != nil`) that were already true underneath its now-invalidated "exactly search/list/store" claim, without pre-announcing the verb a later plan in this phase adds.
