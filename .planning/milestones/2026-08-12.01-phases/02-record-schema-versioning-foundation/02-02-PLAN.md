## Correction this plan is built on

CONTEXT.md's D-01 states that `Upsert`, `Update`, `Supersede` **and `Reindex`** all funnel through
`payload()`. RESEARCH.md disproves the fourth by reading the code: `payload()` has exactly one call
site — `internal/store/store.go:749`, inside `Store.Upsert` — and `Store.Reindex`'s per-point write
calls the raw Qdrant client directly with `Payload: p.Payload`, the payload map scrolled verbatim
off the *source* collection. `Update` and `Supersede` reach `payload()` transitively through
`s.Upsert`; `Reindex` never reaches it at all.

**Consequence this gate must encode:** Reindex's per-point write is a *named, justified exception*
in the classification, mirroring the existing `embedder_identity` exception comment already at that
write. It is NOT a conforming site and must NOT be forced to route through `payload()` — refactoring
Reindex is outside this phase's additive scope. A gate written on D-01's stated premise would red on
a write path that was never broken.

## The gate redesign this revision makes (review findings H1 + H2)

Cross-AI review (`02-REVIEWS.md`) landed two HIGH findings on this plan's previous design, and both
are correct. The previous gate scanned `qdrant.PointStruct` **composite literals** and classified the
`Payload` field's value expression. That is the wrong surface, twice over:

1. **A bypass need not construct a literal.** `s.client.Upsert(ctx, req)` where `req` — or the points
   inside it — came from a helper, a clone, a function parameter or a generated builder adds no new
   `qdrant.PointStruct{...}` to the scanned package. The gate stays green while a raw point write
   ships. Scanning the construction is scanning one *possible* upstream of the write, not the write.
2. **A literal need not be transmitted.** A fixture containing only a `PointStruct` literal was
   classified as a "point write" even though nothing ever sends it, so the fixtures did not pin the
   property the gate advertised.

**The corrected anchor is the transmitted boundary: call sites of `Upsert`.** Note this is MORE
faithful to CONTEXT.md D-03's instruction — "anchor this gate on identity (does this call site route
through `payload()`) rather than on argument shape" — not less. The previous design anchored on the
identity of the wrong thing.

The redesign **replaces** machinery rather than adding to it. The literal classifier survives, but
demoted: it is no longer the completeness derivation, it is the *conformance check applied to the one
call site the boundary scan classifies as conforming*. The two halves are now complementary and each
does one job:

| Half | Question it answers | Failure it catches |
|---|---|---|
| Boundary scan (`Upsert` call sites → enclosing function) | *Which functions transmit a full point write?* | A new write path, however its payload was built |
| Conformance check on the conforming site | *Does that site's payload come from `payload()`?* | Replacing `payload(m)` with a hand-built map at the legitimate call site |

### Verified against source at revision time — with the scanner's OWN matching rule

**Cycle-2 review found a real contradiction here and it is fixed below.** The previous revision
cross-checked with `rg -n 'client\.Upsert\('`, which returns 2 hits — but that pattern is *narrower
than the scanner this plan specifies*. The scanner matches any selector call whose `Sel.Name` is
`Upsert` with the receiver deliberately ignored, so it derives **four** sites, and the acceptance
criteria asserted "exactly two". An executor following the plan literally would have hit an
unexplained RED on the first real-package run and had to improvise — either adding entries
(contradicting "exactly two") or narrowing the match (contradicting the explicit "Do NOT narrow
this"). Off-plan gate weakening is this repo's recorded failure mode, so the root defect was the
mismatch between the spec and its own cross-check, not the count.

**The verification command must implement the scanner's matching rule.** It is:

```
rg -n '\.Upsert\(' internal/store/*.go --glob '!*_test.go'
```

which returns exactly four hits in non-test source:

| Site | Receiver text | Enclosing function | Shape |
|---|---|---|---|
| `store.go:744` | `s.client` | `Store.Upsert` | direct transmission, payload from `payload(m)` |
| `store.go:1872` | `s` | `Store.Update` | delegation — `return s.Upsert(ctx, cur, vec)` |
| `store.go:2279` | `s` | `Store.Supersede` | delegation — `s.Upsert(ctx, newMem, vec)` |
| `store.go:3213` | `s.client` | `Store.Reindex` | direct transmission, verbatim raw-map copy |

**Resolution: option (a) — classify by (enclosing function, receiver path), with the two delegations
as named entries.** This is not a concession to the scanner's noise; a delegating call is
*genuinely conforming*: it routes through `Store.Upsert` and therefore through `payload()`, which is
exactly what D-01 says about `Update` and `Supersede`. Four entries in three dispositions is a
*truer* description of the write boundary than the two-entry table was.

The receiver text is recorded as **classification metadata, never as a match filter** — the match
stays deliberately over-approximating (that is the H1 fix and it survives intact), while the
classification becomes precise enough to tell a delegation from a direct transmission. That buys a
property the two-entry table could not express: if `Store.Update` ever stops delegating and starts
calling `s.client.Upsert` itself, its receiver text changes from `s` to `s.client` and the gate goes
RED — even though the derived site count did not move.

## What this gate proves, and what it does not (cycle-2 HIGH — the claim is narrowed, deliberately)

Both cycle-2 reviewers agree that `go/ast` without `go/packages`/`go/types` cannot establish that a
matched `Upsert` belongs to `*qdrant.Client`. They offered two ways out: **narrow the claim**, or
**add type resolution**.

**Decision: narrow the claim.** Recorded here so it is not relitigated at execution. The reasoning:

- **D-03 locked the idiom.** It names the stdlib-only source-level conformance-gate pattern of
  `internal/surfaces` and Phase 1's `internal/keylinks` / `collectionprefix_conformance_test.go`.
  Adopting `go/packages` means a `golang.org/x/tools` dependency and a test that typechecks its own
  package from inside itself — a different mechanism than the one the user locked.
- **This repo's own recorded lesson is that a gate must not claim more than it proves**
  (`x6v6qxqd6f`). An honestly-narrowed gate is worth more than an overclaiming one; the failure this
  phase exists to prevent is a *false assurance*, and an exhaustive-sounding success criterion over a
  selector-name scan is itself a false assurance.
- **The recall-side authority moves to runtime, where it belongs.** Plan 02-03 captures the objects
  actually transmitted to Qdrant through a gRPC interceptor. That is evidence, not inference, and it
  is unaffected by how the call was spelled. The AST scan's job is to catch *tomorrow's* write path,
  and it does that for every shape short of the five escapes below.

**The narrowed claim, stated once and carried into `must_haves.truths`, the acceptance criteria and
`<success_criteria>`:** this gate establishes that **every direct selector-call transmission in the
`internal/store` package directory** is classified and, where direct-conforming, routes its payload
through `payload()`. It does not establish operation identity.

**The five escapes it cannot see, each with its disposition:**

| Escape | Disposition |
|---|---|
| Method value — `write := s.client.Upsert; write(ctx, req)` | **Pinned as a tested limit.** The `limits_pkg.go.txt` fixture contains one and the derived set is asserted EMPTY for that fixture, so the blind spot is a checked property. If someone later adds type resolution, that subtest tells them the limit closed. |
| Method expression — `write := (*qdrant.Client).Upsert; write(s.client, ctx, req)` | Same fixture, same assertion. |
| Cross-package writer — a helper package that holds the client and calls `Upsert` | **Converted from silent to loud** by `TestQdrantClientIsHeldOnlyByStorePackage` (Task 2). Not closed, but no longer invisible. |
| Differently-named in-package wrapper | Already caught — the wrapper's own inner `.Upsert(...)` call site is in the scanned directory and surfaces unclassified. Only the cross-package variant escapes, per the row above. |
| An alternate Qdrant mutation verb this plan does not enumerate | **Open and disclaimed.** The method vocabulary is a maintained list whose incompleteness is invisible to the gate. Task 2's classification cannot backstop a verb that produces no subject. Stated in the test file's doc comment. |

## Scope decision (review MEDIUM: "the phase may be over-engineered")

Codex raised, and Kimi disputed, whether five plans and thirteen tasks are disproportionate for one
additive field. **Decision: keep the task count; the redesign above is what makes it proportionate.**
The reasoning, recorded here so it is not relitigated at execution:

- The redesign is net-neutral in machinery, not additive. One scanner replaces another; the fixtures
  change shape rather than multiply; Task count in this plan stays at 3.
- Codex's own ranking of the five highest-value proofs — codec round trip and absent decode, Qdrant
  Upsert emission-site classification, transmitted recall-filter capture, raw future-payload
  compatibility, MCP wire visibility — maps one-to-one onto plans 02-01, 02-02, 02-03, 02-04, 02-05.
  There is no plan in this phase outside his own top five. Cutting a plan means cutting a proof he
  ranked as load-bearing.
- The one genuinely additive item in this revision is the partial-write classification gate in Task 2.
  It is ~15 lines on a scanner that already exists, and it converts D-02's "partial writes never
  stamp" from a claim proven for one method behaviorally into a property a newcomer must classify.
- The cost this phase is guarding against is not hypothetical. Phase 1 shipped gates carrying the
  exact defect they were built to eliminate, and a goal-backward verifier passed them 3/3 with "no
  gaps" (durable memory `x6v6qxqd6f`). The verification weight here is calibrated to that record.
