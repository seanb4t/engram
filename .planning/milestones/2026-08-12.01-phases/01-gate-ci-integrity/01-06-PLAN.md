Create `internal/store/collectionprefix_conformance_test.go` — a stdlib-only source-level gate
(`go/ast`, `go/parser`, `go/token`, `os`, `path/filepath`, `sort`, `strings`, `testing`) asserting
that no test file in a Qdrant-backed package constructs a store over a raw collection name.

It lives in `internal/store`'s test scope because that is the package that owns the collection
concept; it adds no production dependency and no import edge, since it reads sibling packages as
source text rather than importing them. Say so in a file comment so a later reader does not move it
somewhere that would create one.

The rule: for each scanned package, parse every `_test.go` file and walk the AST for call expressions
whose callee is the store constructor — the unqualified constructor inside `internal/store`, the
package-qualified one elsewhere. A call whose collection argument is a string literal is a finding.
A call whose collection argument is anything else (an identifier, a call to the package's
`testCollection`, a parameter) is clean, because plan 01-05's runtime seam is what checks the value;
this gate only forces every construction through that seam. State that division of labour in a
comment — the two mechanisms are deliberately complementary, and a reader who mistakes either for the
whole thing will weaken the wrong one.

Report every finding in one run as `file:line` plus the offending literal, collecting into a slice
and calling `t.Error` per finding — never `t.Fatal` on the first, matching this repo's existing
conformance-gate shape.

Committed fixture pair under `internal/store/testdata/collectionprefix/`: `good_pkg_test.go.txt`
contains a small synthetic package source whose store constructions all route through a seam, and
`bad_pkg_test.go.txt` contains one that passes a raw collection literal directly. Use the `.go.txt`
suffix so the fixtures are not swept by `gofmt`, `go vet`, or the linter while remaining parseable by
`go/parser` from explicit source bytes. Factor the scanner so it takes source bytes and a display
path, letting the same function serve both the fixtures and the real packages.

`TestEveryStoreConstructionRoutesThroughSeam` asserts three things in one run: the good fixture
yields zero findings, the bad fixture yields at least one naming its offending literal, and the four
real packages (`internal/store`, `internal/server`, `internal/e2e`, `internal/retrievaleval`) yield
zero findings. The fixture pair is the fail-first proof and it re-runs forever, so a future
contributor cannot defang the gate without the fixtures going quiet — which is itself a failure.

Add a zero-applicability guard modeled on `TestZeroApplicableSurfacesFailsGate`: if the scan visits
zero files, or if a named package directory does not exist, the test fails loudly. A gate that
silently scans nothing is the exact false-green this phase exists to eliminate, and it is the most
likely way this particular gate rots — a package rename would otherwise turn it into a no-op.

Run `task license:check` after adding the fixtures. If it flags the new `.go.txt` files, add the
Apache-2.0 SPDX header to them as a leading Go comment (the parser tolerates it). Do NOT hand-edit
`.licenserc.yaml` to change scope — if the correct resolution appears to be a scope change, stop and
surface it.

Extract each Qdrant-backed package's `testCollectionPrefix` value by parsing that package's
`_test.go` files and reading the constant's string value out of the AST. Reading it from source
rather than importing it is what lets one test see all four: the constants live in four separate test
scopes that no single package can import.

Assert, over every ordered pair of the four packages: the two prefix values are not equal, and
neither is a leading substring of the other. Equality is the obvious collision. The leading-substring
case is the subtle one and it is the reason this is not just an equality check — two distinct
prefixes can still concatenate to the same final collection name when one is a prefix of the other
and the shorter package happens to use a name beginning with the remainder. Name that reasoning in a
comment; it is precisely the kind of check a future reader would otherwise simplify into a set
comparison.

Assert also that every one of the four named packages actually yielded a prefix. A package whose
constant could not be found is a finding, not a skip: a Qdrant-backed package that declares no prefix
is exactly the state this gate exists to prevent, and treating "not found" as "nothing to check" would
let a fifth package join the shared instance unnamespaced and silent.

Report all violations in one run rather than failing on the first pair.

Prove it goes red: temporarily change one package's prefix so it becomes a leading substring of
another's, confirm the test fails naming both packages and both values, then revert. Do the same for
