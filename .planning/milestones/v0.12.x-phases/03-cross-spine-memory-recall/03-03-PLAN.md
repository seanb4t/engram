<objective>
Expand the proven tracer outward on the MCP lane: the second verb, and the provenance half of the
phase.

Two capabilities land here. First, `list_memory` gains cross-spine (D-08 — Sean's override of the
recommendation to leave it scope-confined; an agent that can search across spines but not list
across them has an arbitrary hole). Second, a cross-spine response starts reporting which scopes the
query covered, which is what makes "found nothing here" distinguishable from "searched everywhere I
can see and found nothing."

One precision this plan must not get wrong: `Store.ListScopes` applies the authorization predicate
ALONE — no recall-window gate, no superseded soft-hide, no tag or category filter. So
`searched_scopes` can name a scope that contributed zero hits. That is CORRECT for what criterion 5
asks for: the field reports the *span the query covered*, which is exactly the thing that
disambiguates a zero-hit result. It is not a hit-distribution report, and a test asserting
`searched_scopes` equals "the scopes with results" would be pinning the wrong contract.

Purpose: complete the MCP lane so wave 4 has only the wire to mirror.
Output: cross-spine `list_memory`, `searched_scopes` / `scopes_truncated` on both MCP verbs, and the
result-provenance pin.
</objective>
