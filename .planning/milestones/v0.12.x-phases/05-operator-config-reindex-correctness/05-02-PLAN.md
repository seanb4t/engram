<objective>
Make `reindex --resume` tag-aware, and make `--dry-run --resume` able to size the repair before it is
run.

The defect: the skip predicate compares the source point's content against the *target's* content and
never looks at tags, while the vector is computed from `EmbedText(content, tags)` — which appends a
tags line. A tags-only edit therefore leaves a stale vector behind and resume reports the record
`Unchanged`. The fix is a third conjunct in a predicate that is already a conjunction of content plus
an identity guard (Phase 13 SC3), so tags is an established shape, not a redesign (D-07, D-09).

Two research findings de-risk this and must not be re-litigated:

- `reindexTargetContents`' `Get` already uses `qdrant.NewWithPayload(true)`, which `go doc` confirms
  is an all-fields alias and **not** a field selector. Tags are already fetched from the target and
  are merely never read out of the response. There is no "silent no-op fix" hazard here and no
  defensive task is warranted. Do not narrow the payload selector "to be efficient" — that would be a
  regression.
- D-13's premise holds structurally: `Reindex` writes vector and payload in one `Upsert` built from
  one source read, and re-scrolls the source fresh on every invocation. A record the buggy predicate
  skipped therefore holds both a stale vector and a stale tag snapshot, and the patched predicate
  detects it on a plain re-run. No new one-time repair command is warranted (D-13); the repair path is
  this patched predicate plus D-14's dry-run sizing plus plan 05-03's documentation.

The real hazard this plan designs out is D-08's: a second, subtly different tag decode loop on the
target side. An encoding asymmetry surfaces as permanent false re-embeds — resume never converges —
which is strictly worse than the bug being fixed. Research left the shape as Claude's Discretion
between calling `fromPayload` wholesale and extracting a shared helper. **This plan picks the shared
helper**, because it makes "both sides decode through the same path" a structural fact a reviewer can
check in one grep (one function, two callers) rather than an incidental consequence of someone
noticing that a bigger function happens to also be called here. It also avoids decoding and
discarding a dozen fields per target point.

Purpose: close #345 and give REQ-reindex-stale-repair its operator-usable preflight.
Output: one tag decoder, one comparison helper, a three-conjunct predicate with an honest comment, a
dry-run arm that honors resume, and the two integration tests that pin all of it.
</objective>
