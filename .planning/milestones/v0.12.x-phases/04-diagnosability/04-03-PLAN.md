<objective>
Stop discarding the one piece of information that tells an operator why their embedder said no, and
stop leaking the connection that carried it.

`internal/embed/embed.go:248-249` returns `embeddings: status 502` and throws the provider's error
body away unread. The chat lane four directories over already does this correctly
(`summarize.go:180-183`), which makes this the same "fixed one lane, not its sibling" shape as the
doubled-`/v1` URL-join bug that survived from Phase 13 to Phase 26.

Criterion 4's audit clause resolves asymmetrically and the plan must not flatten it: **surfacing** is
embeddings-only, because the chat lane already surfaces. **Draining** is both, because neither lane
drains — `io.LimitReader(body, 4096)` leaves the remainder unread, so `Close` tears the connection
down instead of returning it to the pool.

This plan is fully independent of the other three fixes in the phase: different packages, no shared
files, no shared types. It is wave 1 for that reason.

Purpose: an embedder failure that is diagnosable from the error alone, on a connection that survives it.
Output: a bounded read-and-drain on both provider lanes, a dimension-sized success bound on the
embeddings lane, and the phase's only new test helper.
</objective>

| Provider error body -> engram error -> operator log | `connectError`'s default arm logs unmatched errors server-side, so provider text can reach a durable operator sink. |
