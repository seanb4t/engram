<objective>
Finish the sweep on the two files outside `tools.go`, and make the Connect lane actually honor the
class it is now being handed.

**D-20 (checkpoint resolved 2026-08-01):** Sean confirmed the class-to-code mapping stays inside the
CLI-compatible trio — `InvalidArgument` for a malformed or unknown enum value, `OutOfRange` for
length and numeric bounds, `FailedPrecondition` for mutually-exclusive or ordering violations
between individually-valid fields. These are exactly the three codes `exitCodeForConnectErr`
(`cmd/engram/client_common.go:237-249`) already groups under one exit code, so the CLI's exit-code
contract is unchanged and the breaking surface is confined to callers branching on the Connect code
itself. Do not map to any code outside that trio. Ships as `feat!` per D-11.

Two distinct pieces of work share this plan because they share `internal/server`'s Connect-facing
surface and because the second is meaningless without the first.

**`rules.go` carries the third of D-11a's three unwrapped validators.** `validateStoreRule`'s content
and scope checks return bare errors that fall through `connectError`'s switch to `CodeInternal` — a
caller's invalid input reported as a server fault. It is latent rather than live only because
`store_rule` has no Connect RPC yet; the defect is real and is fixed here rather than filed.

**`connectapi.go` currently overrides the class.** Its seven inline
`connect.NewError(connect.CodeInvalidArgument, err)` sites exist for a good historical reason — the
comment at `:139-141` says a bare argument error would otherwise be misclassified as `CodeInternal`.
Plan 04-01 removed that reason by making `connectError` classify on the error's class. Left in place,
those seven hand-wraps now pin every Connect validation failure to `CodeInvalidArgument` regardless of
class, shipping D-11 as a no-op on the very lane it was written for — and every existing test would
still pass, because they assert `CodeInvalidArgument`.

This plan is wave 3, after 04-04, because `effectiveSearchScope` lives in `tools.go` and four of the
call sites being rewired here call it.

Purpose: one classification path, on both lanes, with no file left half-converted.
Output: rows 22-30 converted, seven hand-wraps removed, the relational Connect check reshaped, and
three pins.
</objective>
