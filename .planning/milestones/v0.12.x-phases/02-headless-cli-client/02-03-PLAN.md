<objective>
Make the binary describe itself. `engram` with no arguments emits one JSON document naming every
command, every flag, and every exit code, so an agent discovers the surface by running the program
rather than by scraping help text whose formatting is not a contract (D-15/D-11).

This plan lands last because the catalog is derived from the live cobra command tree: it can only be
proven complete once `search`, `list`, and `store` are all registered. It also touches `root.go`,
which Plan 01 touches — hence wave 3, strictly after both, so the two edits to that file never race.

Purpose: `REQ-cli-self-describing` and `REQ-cli-agent-output` reinforce each other here. An agent
that reads the exit-code taxonomy out of the binary can branch on it without carrying documentation,
and D-17's one surprising edge — a flag typo exits 1, not 2 — is only safe to ship because the
catalog says so.
Output: the catalog, the two-field change to `rootCmd` that makes a bare invocation reach it, and
the drift gates that keep the advertised taxonomy identical to the real one.
</objective>

## The cobra control-flow facts this plan turns on

Verified against the vendored `github.com/spf13/cobra@v1.10.2` source in `02-RESEARCH.md` § Pitfall
1. Do not re-derive them; do not contradict them either.

| Fact | Consequence for this plan |
|---|---|
| `rootCmd` has no `Run`/`RunE` today, so cobra's `Runnable()` is false | A bare `engram` returns cobra's help sentinel, which the executor special-cases into printing help to stdout and returning nil — exit 0 with help text. This is exactly what contradicts D-15. |
| The help-flag check runs **before** the runnable check inside cobra's `execute()` | Adding a root `RunE` does not disturb `--help`. D-16 is preserved with no extra code — but it still gets a test, because "preserved automatically" is a claim about a dependency's internals, not about ours. |
| `SilenceUsage` and `SilenceErrors` are already true on `rootCmd` | Nothing to add for stdout cleanliness; Plan 01 already pins it. |
| Once the root is runnable, a first argument matching no subcommand is passed to the root's own handler as an argument instead of erroring | **This is the landmine.** Without an argument validator, `engram <typo>` would stop erroring and start printing the catalog at exit 0, silently swallowing a mistyped verb. `cobra.NoArgs` restores the unknown-command error. |
| `SetArgs(nil)` makes cobra fall back to the process argument vector | Under `go test` that vector is the **test binary's** own flags. Every test driving a bare invocation must pass a non-nil empty slice, never nil. Plan 01's `runClient` already does this. |

Create `cmd/engram/catalog.go` holding the self-describe document, its builder, and its renderer.

Declare the document types as plain Go structs with JSON tags. This is the CLI's own contract rather
than a wire message, so it is hand-declared, not protobuf-derived:

  - the top-level document carries the binary name, the build version, a list of commands, a list of
    exit codes, and a list of notes;
  - a command entry carries its name, its one-line summary, and its flags;
  - a flag entry carries its name, its type, its default value rendered as a string, and its usage
    text;
  - an exit-code entry carries the numeric code and its meaning.

Use snake_case JSON tags, matching the field-name convention the client commands' own output already
uses.

Declare `buildCatalog(root *cobra.Command) catalogDoc` walking the **live** cobra tree: for each
non-hidden subcommand of `root`, record its name and its short description, then walk its flag set
recording each flag's name, type, default value, and usage text. Include the root's persistent flags
on each command entry, since a caller may legitimately pass them there. Deriving from the tree
rather than from a hand-written literal is the entire point: a command or flag added later appears
with no edit here, and cannot silently go missing.

Skip cobra's auto-generated help and completion commands, and skip hidden commands — they are not
part of the advertised surface. Say so in a comment so a later reader does not read the omission as
a bug.

Build the exit-code section by pairing the exit constants declared in `client_common.go` — `exitOK`,
`exitGeneric`, `exitUsage`, `exitAuth`, `exitNotFound`, `exitUnavailable` — with the meanings D-09
gives them: success; generic or unclassified failure; usage or validation error; authentication or
authorization failure; not found; transport or server unavailable. Build it from those constants,
never from a second literal list of integers. D-11's whole value is that the advertised taxonomy and
the mapper's real output are the same thing, and Task 2 gates that they stay so.

Add a notes list carrying, plainly and in substance, D-17's rule: a flag-parsing error raised by the
command framework itself — an unknown flag, an unparseable flag value, a mistyped verb — exits 1,
not 2; exit 2 is emitted only by engram's own semantic validation, such as a missing server URL, an
invalid output-format value, or a missing required value. An agent branching on 2 that does not know
this will misclassify its own typo, and D-17 accepted that cost specifically on the condition that
the catalog say so. Also note that an empty result set is a success and exits 0 (D-12), so a caller
does not read "found nothing" as a failure.

Declare `runSelfDescribe(cmd *cobra.Command, _ []string) error` that builds the catalog from
`cmd.Root()` and encodes it as JSON to `cmd.OutOrStdout()`, returning the encoder's error. Nothing
is written to stderr on this path (D-07). Writing through the command's writer rather than the
package-level print family is what lets the test capture it.

In `cmd/engram/root.go`, add exactly two fields to the existing `rootCmd` literal:

  - a `RunE` referencing `runSelfDescribe`. This is what makes the root runnable, so a bare
    invocation runs the catalog instead of falling into cobra's help-and-exit-0 path (D-15). Do not

    preserved for free (D-16), and hooking help would break exactly that.

Change nothing else in `root.go`. Leave the version string, the legacy-environment pre-run hook,

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI process → stdout | The self-describe document is parsed by a program. Anything else written to that stream on this path breaks the parse. |
| binary → agent's control flow | The exit codes and the catalog together are what an agent branches on. A catalog that misdescribes the taxonomy causes silent misrouting rather than a visible failure. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-13 | Tampering | `rootCmd` argument handling | high | mitigate | Making the root runnable would, without an argument validator, cause a mistyped verb to succeed silently at exit 0 while printing the catalog — an agent's command going unexecuted with no error is worse than a failure. `cobra.NoArgs` restores the unknown-command error, and `TestRootUnknownSubcommandStillErrors` is observed RED with the validator removed before being trusted. |
