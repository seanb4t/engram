# Quick 260926-st6: Fix Phase 2 UI-REVIEW result-row grid blocker and facet-strip scroll cue

Fix the Phase 2 UI-REVIEW BLOCKER (row summary collapses to ~0px when the results list is
narrow) and its two coupled warnings (facet strip overflows with no scroll cue; score column
clips / list scrolls horizontally at 1024px with the pane open).

## Root cause

`ResultRow.svelte`'s `@container list` drop-outs only `display: none` the tags / scope /
category-word cells. The grid template (`--cols`) is never swapped, so:

1. the hidden cells' tracks stay reserved (172u tags, 132u scope, 96u category), and
2. the remaining cells auto-place one track to the LEFT (age lands in the 172u tags track,
   score in the 132u scope track), so the row's fixed-track minimum exceeds the list width,
   the `minmax(0,1fr)` summary track goes to 0, and the row overflows the list viewport
   (the horizontal scrollbar + clipped score in `14-tablet-detail-dark.png`).

Even with `--cols` swapped, the fixed optional tracks (tags/scope/state chips) still starve
the summary near each band's lower edge (e.g. at 861px list width with rel on and a state
chip, the summary gets ~20px), because every non-flexible track is sized before an `fr`
track receives anything.

## Tasks

### Task 1: ResultRow grid — swap `--cols` per container band, summary floor

- files: `ui/src/lib/components/ResultRow.svelte`, `ui/src/lib/components/ResultRow.browser.test.ts`
- action:
  - Keep the locked sketch pattern: the column template is ONE variable (`--cols`) that each
    `@container list` band swaps (recall-surface.md CSS Patterns).
  - Band > 860px: `cat 96u · summary · states auto · tags ≤172u · scope ≤132u · age 34u · score 70u`.
  - Band ≤ 860px: tags track removed from `--cols` (not just the cell hidden).
  - Band ≤ 560px: tags and scope tracks removed; category track shrinks to the dot (6u); score
    track shrinks to the number (bar hidden) — 40u.
  - Summary track `minmax(var(--sum-min), 1fr)` with `--sum-min: min(120u, 20cqi)` (list-width
    relative so it can always be met) and the optional tracks as `minmax(0, <width>)` so tags /
    scope yield before the summary; age / score / rel keep fixed tracks and always stay.
  - Breakpoints stay 860px / 560px (design decision unchanged).
- verify: new vitest-browser test renders ResultRow (rel on, state chip, tags, scope) inside a
  `container-name: list` box at 1000 / 861 / 800 / 561 / 520 / 390px and asserts the summary cell
  width ≥ a usable minimum, the score (and rel) cells lie fully inside the row, and the row has
  no horizontal overflow. Must FAIL on the pre-fix component.
- done: summary readable and score/rel/state chips visible at every tested width.
