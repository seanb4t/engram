<objective>
Add the additive `service_auth.*` configuration surface to `internal/config`: the client-credentials
lane's issuer/audience/owner-claims and the static-token→owner map (D-11 / D-05 / D-14), following the
existing koanf field-registry pattern exactly, plus a parser for the token→owner map and the
self-gated validation mirror. This is the config the Plan 06 wiring threads into `withAuth`.

Every new mechanism is independently enablable by config presence (D-03): absent `service_auth.*` =
mechanism simply not built = today's human-only behavior preserved.

Purpose: express "which service mechanisms are enabled" purely through ENGRAM_ config, with no mode
enum and no reuse of the human lane's owner-claim default or audience.
Output: four registry rows, `ServiceAuthConfig`, `ParseServiceStaticTokens`, and validation.
</objective>
