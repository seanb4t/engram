<objective>
Prove tenancy isolation (#373) for service principals against the store filters Phase 22 already
wired — ZERO new store code (SC4 / D-07). A client-credentials/static-token-resolved owner (a
`namespacedOwner`-encoded string) cannot read another human's or another service principal's private
records, does not collide with the anonymous bucket or a human owner, and recalls empty (not an
error) when it owns nothing. Also encode the SC5 / D-15 / D-16 decision as a PERMANENT test: two
service-tenant owners, one `shared` record, and the other tenant's principal CAN read it — global
shared-read is the intended, documented v0.11.x behavior, so it can never be silently reinterpreted.

This plan is independent of the auth chain (Plans 01-03) and config (Plan 04): the store treats the
owner as an opaque authz key, so these tests construct service owners as literal namespaced-shaped
strings and exercise the store directly, mirroring the existing isolation/sharing suite.

Purpose: make the isolation guarantee and the cross-tenant shared-read decision executable oracles,
not assumptions.
Output: `internal/store/service_principal_isolation_test.go` (needs Qdrant / testcontainers).
</objective>
