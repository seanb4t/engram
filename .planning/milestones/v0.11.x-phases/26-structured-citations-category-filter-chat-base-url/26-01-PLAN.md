<objective>
Thread a category filter through the store's search lane, using a `store.SearchOptions` struct
instead of a 9th positional parameter (D-09), and extract the OR-condition builder that
`listFilter` already contains into a shared `categoryMatchCondition` helper so the list lane and
the new search lane cannot drift.

Purpose: this is the largest and most call-site-invasive slice of Track B, so per D-17 it goes
first and everything else in the phase waits behind it. The store already proves the exact filter
composition this needs (`listFilter`'s category `Should`-sub-filter appended to the outer `Must`,
live-Qdrant-tested by `TestListCategoryAndVisibilityFilter`) — this plan generalizes that one
proven block rather than inventing a second filter shape.

Output: `internal/store/store.go` (SearchOptions, categoryMatchCondition, reshaped Search /
SearchReranked, listFilter refactor), `internal/server/tools.go` (`coreSearchRequest.Categories`
threaded into the one production call site), and five new store tests covering OR semantics,
pre-ranking, the SC4 authz invariant, and the empty/adjacency/ordering edges.
</objective>

<assumption_delta_decision>
The deterministic scan fired (`pluralization`: "alongside"; `optional`: "optional"/"optionally").

- **Primary noun:** the *filter set applied inside the authz-outer-`Must`*. Categories join tags,
  visibility, the temporal window, and the supersession gate as one more peer constraint composed
  inside the authz condition — not as a new top-level query concept.
- **Decision:** `no-change`. The identity model (`owner` + `scope` as the authz/partition key,
  `id`/`short_id` as record identity) is untouched. A category filter narrows a result set; it is
  not an identity or a partition. Adding a peer filter to an already-plural filter set is the
  shape this code was built for — there is no singular assumption losing its monopoly here.
- **Invariant test accepted:** `TestCategoryFilterDoesNotWidenVisibility` (Task 2) is the test that
  goes red the instant a future phase composes a request filter outside the authz `Must`.

(The genuine singular→plural transition this phase does contain — one shared OpenAI base URL
becoming two per-lane base URLs — is recorded in `26-04-PLAN.md`, which owns that change.)
</assumption_delta_decision>
