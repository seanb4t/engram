<objective>
Give the summarizer its own base URL. Add `ENGRAM_OPENAI_CHAT_BASE_URL` (koanf `openai.chat_base_url`)
resolved with `cmp.Or` at the single `summarize.New` call site (D-12), validated only when set
(D-15), and fix the chat endpoint construction so a real hosted provider URL actually works: hoist
the embedder's shape-aware provider join into one shared `internal/openaiurl.Join` helper (D-14) and
call it from both lanes (D-13).

Purpose: without D-13 this feature ships a 404. The stated use case is "a local embedder plus a
hosted chat model", every hosted chat base URL ends in `/v1` or `/v1beta/openai`, and the current
summarizer builds its endpoint with a naive concat — so the very first thing an operator tries
produces a doubled `/v1` path. The embedder was given the shape-aware join in Phase 13; the chat
lane never was.

Output: a new zero-dependency `internal/openaiurl` package, the config field/registry/validate trio,
a one-line resolution change at the summarizer construction site, the endpoint fix in
`internal/summarize`, a behavior-preserving refactor of `internal/embed`, and Helm chart wiring.
</objective>

<assumption_delta_decision>
This plan is where the phase's genuine singular→plural transition lands.

- **Primary noun:** the *per-lane OpenAI-compatible endpoint*. Before this plan there is one shared
  OpenAI base URL serving both the embeddings lane and the chat lane; after it there are two, with
  one designated as the shared fallback.
- **Decision:** `add-alongside`, deliberately and per locked D-12. `ENGRAM_OPENAI_BASE_URL` stays
  required and primary; `ENGRAM_OPENAI_CHAT_BASE_URL` is an optional override resolved by
  `cmp.Or` at one construction site. The alternative — promoting a per-lane provider group
  (`openai.lanes.{embed,chat}.{base_url,api_key,timeout}`) to primary and demoting the shared URL to
  a default — is a larger config redesign, and its two companion fields (per-lane API key, per-lane
  timeout) are explicitly deferred in `26-CONTEXT.md`.
- **Accepted debt and the trigger that forces a promote:** the API key remains global. That is fine
  while the target deployment is a *local* embedder plus a hosted chat model, because local
  embedders ignore the `Authorization` header — the single shared key can simply be the hosted chat
  key. The moment BOTH lanes are hosted with different providers, the shared key breaks and the
  per-lane group must be promoted to primary. Record that as the trip-wire, not as a surprise.
- **Invariant test accepted:** `TestJoin` (Task 2) is a table over every supported provider shape
  crossed with BOTH lane suffixes. It goes red the instant a future change reintroduces a
  lane-specific join, and it is why the helper is shared rather than duplicated.
</assumption_delta_decision>
