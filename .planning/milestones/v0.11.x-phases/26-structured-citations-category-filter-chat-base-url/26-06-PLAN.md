  <action>
1. Add a Citations section to `skill/engram/curating-memory/SKILL.md`, placed alongside the existing
   Supersession and Scheduling sections and written in their voice. It must cover four things.
   **What:** a memory may optionally carry structured source anchors reusing the same citation shape
   `store_discovery` uses — `kind` (file, commit, url, or repo), `ref`, and the optional `locator`,
   `pin`, and `excerpt`. **When to attach:** a claim whose value depends on being checkable against a
   specific source — a convention traced to the file that establishes it, a gotcha traced to the
   commit that introduced it, a decision traced to the ADR or issue that records it. **When not to:**
   a preference, an opinion, or anything where the anchor would be decorative; citations are optional
   provenance, never a routine field to fill in, and attaching them reflexively would erode the
   zero-junk invariant from the guidance layer. **Constraints an agent needs:** at most 50 citations
   per record, at most 16 KiB per excerpt, `ref` is required, and citations are never inferred from
   content — only what the caller explicitly supplies is stored. Also state plainly that citations do
   not affect ranking or recall and are not returned in the compact recall view, so an agent that
   needs them should use `get_memory` or pass `full=true`.

2. In `docs-site/src/content/docs/reference/memory-record.md`, move `Citations` out of the
   discovery-only framing. Add it to the main field reference as an optional field available on any
   category, keep the Citation fields sub-table where it is (it describes the same shape for both
   uses), and restate the one remaining asymmetry: a discovery requires at least one citation, a
   curated memory requires none. Leave `Kind` documented as discovery-only — that half of the gate
   did not move.

3. In `docs-site/src/content/docs/reference/tools.md`, add a `citations` argument row to the
   `store_memory`, `schedule_memory`, and `supersede_memory` argument tables, describing it as an
   optional array of source anchors and pointing at the memory-record reference for the object shape.
   Add a short recall-behavior note to `search_memory` and `list_memory` stating that citations are
   omitted from the default compact view and returned when `full=true`, and a matching note on
   `get_memory` that it always returns them. Do not document a `citations` argument on
   `update_memory` or `store_rule` — neither accepts one, and both are explicitly deferred or out of
   scope.
  </action>
