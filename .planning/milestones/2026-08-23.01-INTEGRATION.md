## Detailed Findings

### B01 — [#559](https://github.com/seanb4t/engram/issues/559) — RESOLVED: AGENTS.md preservation on index read failure

- **Requirements:** REQ-skills-agents-md-fallback (now satisfied). Also
  restores correctness for REQ-setup-partial-failure-legible (the skills
  facet now reports failure instead of false success) and the
  preservation statement referenced by REQ-docs-setup-documented.
- **Closing commits:** `95daee01`, `bae018f2`, `c773d80e` (gap-closure plan
  04-05).
- **Fix:** `internal/skills/install.go` — `installAgentsMDIndex` now
  branches on `errors.Is(readErr, fs.ErrNotExist)`. Confirmed nonexistence
  (bare or wrapped) is still the create case. Every other read error
  (permission denied, transient I/O, etc.) appends a wrapped error naming
  `target.IndexFile` and returns immediately — before render, splice,
  mkdir, or write — leaving the existing file byte-for-byte untouched.
  `internal/skills/environment.go`'s `ReadFile` doc comment was updated to
  state the asymmetry between `installFiles` (any-error-is-empty,
  unchanged) and `installAgentsMDIndex` (narrowed to confirmed
  nonexistence only), including the requirement that any fake
  `Environment` return a `fs.ErrNotExist`-satisfying sentinel for a
  missing file so fakes and production (`os.ReadFile`) agree.
- **Regression coverage — now permanent:**
  - `internal/skills/install_test.go:TestInstallPreservesIndexOnReadError`
    — table test over `{permission denied, transient error, bare
    nonexistence, wrapped nonexistence}`; asserts zero index writes and
    byte-identical preservation on the first two, a wrapped
    path-naming error via `errors.Is`, and that the independent
    skill-file pass (3 files) still completes in every case; asserts the
    create path still writes and reports success on the latter two.
  - `cmd/engram/setup_test.go:TestSetupIndexReadFailureReachesPartialExit`
    — full CLI-boundary trace: `setup --apply --output json` with a
    codex-only unreadable index reaches `exitPartial`, renders a 2-row
    JSON report before the nonzero exit, codex row is
    `Outcome=failed`/`Skills=failed`/`Registration` not failed/`Reason`
    contains the index path, claude-code row is unaffected, zero writes
    to the index, and native skill files under
    `/home/fake/.agents/skills/` are still written.
  - Verified live: `go test ./internal/skills/ ./cmd/engram/ -run
    'TestInstallPreservesIndexOnReadError|TestInstallAgentsMdConverges|TestSetupIndexReadFailureReachesPartialExit'
    -count=1 -v` — all PASS (`TestInstallAgentsMdConverges` 4 subtests,
    `TestInstallPreservesIndexOnReadError` 4 subtests,
    `TestSetupIndexReadFailureReachesPartialExit`).
- **Disposition:** RESOLVED. No re-opened concern found; the fix matches
  the "required correction" the baseline report specified verbatim
  (preserve on non-nonexistence read errors, report a skills failure,
  keep independent skill-file work).
