## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, state-chip gaps, inline padding |
| sm | 8px | Compact element spacing, chip internal padding |
| md | 16px | Default element spacing, section padding in the detail pane |
| lg | 24px | Section padding, dialog padding |
| xl | 32px | Layout gaps |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing |

Exceptions (all sketch-fixed dense-grid measurements — locked, not to be rounded to the 8-point
scale; every value is still a multiple of the underlying 4px unit):

- **Row height:** `28px` at the default 13px scale anchor (scales with `--u`; see Typography). A
  dense-tool density choice, not a touch-target constraint — this UI has no touch-target
  requirement (desktop keyboard-first console).
- **Row grid column gap:** `10px`; row horizontal padding: `14px` (left) / `12px` (right).
- **Chip height:** `20px`. **Hover card width:** `480px` (`480 / 4 = 120`, still on-unit).
- **Detail pane:** `280px` minimum, `~440px` default, `72%` of body width maximum. Resize step is
  a **percentage**, not a pixel count — see Pitfall B below; do not wire a literal `32px` step
  into `keyboardResizeBy`.
- **Radii** (`4 / 6 / 10px`, sm/md/lg) are a separate radius scale, not spacing, and are not
  required to be multiples of 4 — this is the sketch's fixed radius token set.

## Typography

Four sizes (the sketch's own `--text-2xs`/`--text-xs`/`--text-sm`/`--text-lg` tokens), two
weights. All sizes scale with the site-wide text-size preference via `--u: calc(var(--ui-font) / 13)`
(D-13) except where noted.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body (detail-pane Content markdown, hover-card preview) | 16px equivalent at default (`calc(16 * var(--u))`; range 12–16 → ~14.8–19.7px scaled) | 400 | 1.5 |
| Label (dense row text: summary, meta, chips, ids, ages, scores) | `var(--ui-font)` — **12–16px, default 15px**, persisted per viewer (D-13) | 400 | 1 (fixed single-line row; the row never wraps) |
| Micro-label (`--text-2xs`, `--text-xs`: state chips, kbd hints, section-header source-RPC labels) | 11–12px equivalent (`calc(11 * var(--u))` / `calc(12 * var(--u))`) | 400 (600 for the active/emphasized chip, e.g. the "kind" chip) | 1 |
| Heading (detail-pane record title, section labels "State"/"Content"/"Tags"/"Metadata", dialog headings) | `calc(16 * var(--u))` (16px default) | 600 | 1.2 |

Weights: **400 (regular)** for all prose, row text, and default chips; **600 (semibold)** for
headings, section labels, the results-header's bolded counts (`**12 hits**`), and the
"interpreted-as kind" chip. No third weight.

**Default text size is 15px, not 13px.** `ui/src/app.css`'s current `body { font-size: 13px; }`
is superseded by the `display.js` contract's `--ui-font` (default `15`) — this phase removes the
hardcoded value and derives from the preference instead (see Foundations reference, "Scaling in
Tailwind 4").

## Interaction & Accessibility Notes

Not a template section, but load-bearing: the executor must build against these exactly, not
infer them from the CSS alone.

### Keyboard model (WAI-ARIA APG Listbox)

DOM focus stays on the list container (`role="listbox" tabindex="0"`), rows are `role="option"`
with stable ids, `aria-activedescendant` points at the active row. `j`/`k`/arrows/`Home`/`End`
move the active row; `Enter` toggles the detail pane (second `Enter`/click on the already-open
row closes it); `Esc` closes the topmost layer only (hover card, then pane), then blurs; `/`
focuses the header search from anywhere not already a text field; `↓` in the search box moves
focus into the list; `Enter` in the search box runs immediately and moves focus to the list.
Pointer hover tracks by `mousemove`, not `mouseenter`, so keyboard-driven scrolling never steals
the hover (Pitfall 4, `PITFALLS.md`). Row-action keys on the active row (D-17): `e` edit · `s`
share/make-private · `#` delete (through the existing confirm dialog) · `c` copy short_id ·
`⇧C` copy full UUID — all ignored while a text field has focus or any modifier is held, and all
shown as `<kbd>` hints in the listbox legend.

### Pitfall A — virtualizer viewport role conflict (spike required, first plan wave)

`@humanspeak/svelte-virtual-list`'s scrollable viewport hardcodes `role="region"` with no prop to
override it — there is no built-in way to make it `role="listbox"`. Two candidate resolutions
(neither assumed to work without a live check): (1) a post-mount action rewriting the rendered
`role` attribute (fragile — may not survive internal re-renders) or (2) accept `region` on the
library's own scroll container and place the real `listbox`/`option` ARIA roles on an inner
wrapper the `renderItem` snippet fully controls, verified against a real accessibility-tree
inspector or screen reader. Do this before the row-list component's shape is locked in, not
after. Fallback if neither resolves cleanly: `svelte-tiny-virtual-list` (builds its own container
from scratch, per D-07's own fallback clause).

### Pitfall B — paneforge's `keyboardResizeBy` is a percentage, not the sketch's pixel step

The sketch's resizer shows pixel-based `aria-valuemin="280" aria-valuemax="900"
aria-valuenow="440"`, but paneforge's `keyboardResizeBy` prop steps by a **percentage** of the
pane group (e.g. `keyboardResizeBy={5}` = 5%), confirmed live against the installed package.
Either compute a percentage that approximates the sketch's implied step from the live container
width and pass that, or skip the prop and drive `pane.resize(pct)` imperatively from a custom
`keydown` handler. Do not wire a literal `32` into `keyboardResizeBy` expecting pixels.

### Pitfall C — ambiguous short_id vs. rejected-envelope: same Connect code, different message shape

Both `store.ErrAmbiguousShortID` and a `field=/hint=`-envelope rejection map to
`CodeFailedPrecondition`. The classifier (`connect-error.ts`) must pattern-match on
`err.rawMessage` (not `.message`, which is code-prefixed, and not `.code` alone):
`/^ambiguous short id: (.+)$/` for D-04's warning-tone case, `/^field=([^ ]+) hint=([^:]+): (.+)$/`
for the rejected-envelope case, `Code.NotFound` for not-found, everything else opaque (still
shown with a request id and Retry — never silently swallowed).

### Honest-reporting contract (D-01–D-06, D-09)

Every result set — ranked or unranked, populated or empty, on every surface (`/search`, header
dropdown, `?q=`, `/`, `/observe`) — states: which resolution path ran (id / short_id / text),
hit count, scope count, the per-state recall-gate hidden count (new this phase, tooltip-split by
state), `scopes_truncated`/`scopes_unknown` verbatim (never inferred client-side), and whether
the order came from cosine or Jev (never both blended into one number). A rejected search always
shows the server's real `field=/hint=` envelope, never an opaque Connect error. Nothing is ever
silently hidden without the header saying so.
