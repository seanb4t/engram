## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-19 | Tampering / XSS | DetailPane content | medium | mitigate | Content renders only through the existing `renderMarkdown` (DOMPurify-sanitized) path; every other field is text interpolation. |
| T-02-20 | Spoofing / CSRF | make-private, share, delete | medium | mitigate | All three go through the existing `engramWrite` client (double-submit CSRF interceptor) via the existing mutations; delete keeps DeleteConfirmDialog; share keeps ShareWarningInline. Authorization stays in internal/store (owner-only writes). |
| T-02-21 | Elevation of Privilege | make-private on a record the caller does not own | low | mitigate | The server rejects non-owner visibility changes (store owner gate); the UI surfaces the rejection toast and never assumes success (the mutation's optimistic patch rolls back on error). |
</threat_model>
