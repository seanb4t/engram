<interfaces>
- `engram.relatedMemories({ id, k, full })` → `RelatedMemoriesResponse { anchor?: Memory; related: RelatedMemory[]; truncated: boolean }`; `RelatedMemory { memory?: Memory; edges: RelatedEdge[] }`; `RelatedEdge { type: EdgeType; evidence: { case: 'supersession'; value: SupersessionEvidence } | { case: 'vector' | 'tag' | 'citation'; … } | { case: undefined } }`; `SupersessionEvidence { direction: SupersessionDirection; depth: number }`; enums `EdgeType.SUPERSESSION = 1`, `SupersessionDirection.SUCCESSOR = 1`, `PREDECESSOR = 2`. Always read `evidence.case` before `value` (engram-connect-client).
- Server semantics (internal/store/relatedmemories.go): the supersession walk is capped at 8 hops per direction (`relatedSupersessionDepth`), follows `superseded_by` forward and `supersedes` backward breadth-first, and returns only records the caller can read. `k` adjusts only vector neighbours (0 → default 8); pass `k: 1n`.
- Compact memories (full=false) keep `supersedes` and `supersededBy` (only content/citations/kind are cleared).
- `engram.getMemory({ id })` returns the full record; NotFound is `Code.NotFound`.
- Query keys start with the RPC name: `['relatedMemories', id, 1, false]`, `['getMemory', id]`; pass `{ signal }`.
</interfaces>
