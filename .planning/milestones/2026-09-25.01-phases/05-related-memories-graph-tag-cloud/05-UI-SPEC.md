| Element | Category | Status | Truth |
|---------|----------|--------|-------|

| E1 | populated | resolved (explicit) | Four lane cards (supersession, citation, tag, vector) stack in that canonical order; the supersession lane is the one horizontal-timeline exception, the other three are one-line row lists. |

Every new key/behavior is documented as a `<kbd>` legend hint where a legend exists (graph

### Graph node accessible name and screen-reader equivalent (D-11)

Each node's accessible name is `{short_id}, {category}, {edge types}, {state words}` — matching
the visually-hidden neighbourhood list's per-item text exactly (D-11: "The list … names each
node"). A polite `aria-live` region announces re-centre, toggle, and filter results, e.g.
`14 related · supersession 3 · citation 2 · tag 6 · vector 8`. The lanes remain the visible text
equivalent of the graph at all times — the graph is never the *only* way to read the
neighbourhood (D-02).

### Settle, drag, and reduced motion (D-09, D-20)

A fixed 300-tick simulation runs synchronously **before first paint**, seeded deterministically so
renders and tests are stable; the layout is static thereafter. A drag briefly reheats
(`alphaTarget(0.25)`) and the dragged node springs back on release — it is never pinned. Under
`prefers-reduced-motion`, there is no animated reheat and zoom transitions are instant, not
eased.

### Refit vs. retained zoom (D-20)

The graph **refits** (recomputes scale/translate to fit the current node set) whenever lane
membership changes — vector-lane expand/collapse, a legend/type toggle, or a re-centre. The zoom
level is **retained** (not refit) across selection, focus, and drag alone, since those do not
change which nodes are drawn. A retained zoom across a membership change clipped newly-drawn
nodes in sketch 006 and is explicitly rejected.

### Vector-lane collapse mirrors the graph (D-07)

The vector lane and the graph always show identical membership. The lane's "show all N" expansion
is client-side over the one already-fetched `k=64` response (D-15's "one fetch" pattern applied
to `RelatedMemories` too) — expanding needs no refetch, and the graph redraws its vector nodes the
instant the lane expands, triggering the refit rule above.

### Resume envelope — this route is read-only (Claude's Discretion, resolved)

`/related/<id>` is **not** added to `ui/src/lib/resume.ts`'s `ALLOWED_DESTINATIONS`. The route has
no write form, no draft state, and no CSRF-protected action of its own — the one write-adjacent
affordance ("Supersede head…" on a chain card) hands off to Phase 4's existing `ChainDialog`/
`SupersedeDialog`, which already own their own resume entries on `/search`. There is nothing on
this route itself that a re-auth round trip needs to restore.

### Component composition

`TagBars.svelte` (new, shared) takes `{ scope, mode: 'panel' | 'rail', anchorTags?, onToggle }` and
is instantiated twice: once inside `/search`'s docked right slot (`mode: 'panel'`, D-13) and once
inside `/related`'s rail `Tags` tab (`mode: 'rail'`, D-13's "counts are for all readable scopes"
variant). Both instances share one `['listTags', scopeKey, 1000]` query per the
`engram-connect-client` query-key convention (discretion item, resolved) — `scopeKey` is the
single scope chip's scope string when exactly one is set, else a sentinel for "all readable
scopes" (D-17). `TagCombobox.svelte` (new) reuses the identical cached query and the identical
row-rendering logic as `TagBars`' picker affordance, so the header search Tags group, the
`FacetStrip` "+ tag" picker, and the bar list itself can never render three different tag lists
for the same scope key.

The graph is a new `RelatedGraph.svelte` owning the `<svg>` element, its own `$state` node/edge
position array fed by the d3-force simulation's `tick` callback, and the d3-zoom/d3-drag call
targets via `d3.select()` on mount — per `STACK.md`'s pattern, d3 never touches rendering.
