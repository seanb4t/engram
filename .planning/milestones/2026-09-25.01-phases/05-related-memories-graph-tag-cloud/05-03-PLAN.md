## Flagged assumptions (not silently dropped)

- **Rarity in the /search tooltip is dropped (D-15's own fallback).** Rarity needs `n`, the recall-visible record count. ListScopes counts are not it: `Store.ListScopes` (internal/store/store.go) scrolls the owner-or-shared set without the recall gate and is capped at `scanCap = 1000` (`approximate`). So TagBars shows rarity only when its host passes weights; plan 05-08 passes the server's exact `WeightedTag.weight` values from the tag edges on /related, and /search passes none.
- **Tooltip mechanism:** each bar row's tooltip is its native `title` (two lines) and its accessible name carries the same facts. A shadcn Tooltip trigger inside a `role="option"` would nest an interactive control in an option (axe `nested-interactive`).
- **Footer copy beyond the table:** after "show all" with `more=true` the footer reads `showing the {loaded} most-used tags — more exist` (warning); the table only fixed the collapsed and filtered strings.
- **TagCombobox keeps the default Popover portal.** CONTEXT.md describes ScopeCombobox as "portal disabled inside a Popover", but the shipped ScopeCombobox uses the default portal and works inside FacetStrip; the portal-disable half of gotcha `3tz15e733n` applies only when Command.Root spans a trigger outside the popover (HeaderSearch). TagCombobox's Command.Root is wholly inside `Popover.Content`, and an inline popover would be clipped by FacetStrip's horizontal ScrollArea. Tests query the page (portaled content lands in `document.body`).
- **Edge probe rows:** TAGS-01 boundary, adjacency, empty, ordering and precision are resolved (explicit) as truths above. TAGS-02's `unclassified` row stays unresolved; planner coverage: the E5 rows here and in plan 05-06.
