<objective>
Make the exit-code baseline test independent of the contributor's shell (OPS-01, #476).

`reindex --target` and `migrate-set-owner --owner` take their pflag default from `os.Getenv(...)` at package `init()` (`cmd/engram/reindex.go` ~line 152, `cmd/engram/migrate.go` ~line 246). `TestExitCodeBaseline` resets every flag to its `DefValue` before each row, so an ambient `ENGRAM_REINDEX_TARGET` / `ENGRAM_MIGRATE_OWNER` flows into the bound variable. The "missing" rows then dial Qdrant instead of failing validation. `t.Setenv` cannot help, because `init()` captured the value before any test ran. The same hazard was fixed for the goldens by `withGoldenDeterminism`, which blanks `DefValue` for every `envDerivedFlagDefaults` entry. This plan moves that loop into one shared helper and calls it from each baseline row.

Decisions implemented: D-03 (isolate the test from ambient env and leave production behavior alone), D-02 (the fix commit carries `Closes #476`). D-03 gave `t.Setenv` as an example. It does not work here for the init-time reason above, so the isolation is done by `DefValue` neutralization, the mechanism the goldens already use. No production file is touched.

Verified at planning time: with both variables set, `go test ./cmd/engram/ -count=1` fails exactly `TestExitCodeBaseline/reindex/missing-target` and `TestExitCodeBaseline/migrate-set-owner/missing-owner`, and nothing else. With `ENGRAM_RUNTIME` / `ENGRAM_HEADERS` set, the baseline passes today.

Output: the shared helper and the baseline wiring, in one commit.
</objective>

- `t.Cleanup` runs LIFO. The reset's cleanup runs before the helper's `DefValue` restore, so the bound variable ends a row at `""` while `DefValue` returns to the env value. The next caller of `resetCommandFlagState` re-syncs from `DefValue`, so no state leaks.
