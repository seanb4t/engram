<objective>
Cover the one migrate-sweep case no test exercises: a record inserted mid-sweep whose id sorts BELOW the sweep's advanced cursor (OPS-04, #501).

`Store.Migrate`'s default mode re-derives its backlog every pass: a fresh exact Count, then a fresh Scroll with a nil Offset (migrate.go's doc comment and the loop at ~line 484). It never threads a cursor across passes. `TestMigrateConvergesWithoutLock` inserts its laggard with an id that sorts AFTER every seeded id, so a forward-only cursor could never skip it. That is why #501's persisted-cursor patch could not go RED against it. This plan adds the missing case. The sweep's full-view page size is pinned to 2 (the package var `spineScrollBatch`, the way `revert_test.go` and `spine_test.go` already do it), so a single pass issues several ScrollPoints requests. The mid-sweep hook fires on pass 1's second request, when the cursor sits on a seeded id, and inserts two records with lower ids:
- an ordinary write, which D-05's documented contract says needs no sweep work because the write path stamps the current version;
- a raw-injected below-target laggard, which pass 1 cannot reach and a later pass's re-derivation must pick up.

Decisions implemented: D-05 (assert the documented convergence contract; test-only unless the test exposes a real defect), D-02 (`Closes #501`).

Scope note: #501's acceptance also asks to restore `03-04-red-1-persisted-cursor.patch` and its `redEvidenceDirs` entry. Both are obsolete. The red-evidence harness was removed repo-wide in `c1afd6c1` under rule `3p0zsqrhmb` (no tests for tests), and `internal/store/redevidence_harness_test.go` no longer exists. The fix commit body says so, because `Closes #501` closes the issue with those two boxes unchecked. Non-vacuity is shown instead by the in-test cursor assertion and a hand-applied, never-committed mutation run (step 4).

Output: one test plus a small addition to the shared hook.
</objective>
