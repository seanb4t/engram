<objective>
Bring the CLI guide's operator-command list in line with the live tree (OPS-05, #503), and gate it so it cannot drift again.

`docs-site/src/content/docs/guides/cli.md` §Operator commands (~line 129) says "Every operator command — `reindex`, …, every `engram spine-review` leaf … — also accepts `--output`". It omits `migrate`, `migrate status` and `migrate revert`, which #503 names. It also omits `setup`: `operatorCommands()` in `cmd/engram/cmdwalk.go`, the structural predicate the `--output` parity gates already use, returns 16 commands, and `setup` registers the same flag through `addOperatorOutputFlag`. No gate covers this list, and that is how the drift happened. Per D-06 this plan adds one, derived from `operatorCommands()`, then fixes the prose until it passes.

Decisions implemented: D-06 (list the three `migrate` commands consistent with `guides/migrate`; add a docs gate), D-02 (`Closes #503`). Adding `setup` is the gate's own finding. An exclusion for it would make the gate state something false, because `setup` does accept `--output`.

Output: a docs-gate test with two pure helpers, and the corrected list paragraph.
</objective>
