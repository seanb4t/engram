<objective>
Build the D-10 async get-path incrementer: a smaller variant of the Phase 11
`summaryQueue` that reuses its shutdown-safety kernel (RWMutex `closed` guard +
`inFlight` reserve-before-send, the CR-01 fix) MINUS all retry/backoff machinery.
The worker fires a single best-effort `IncrementAccess` per enqueued id; a full
queue drops-and-counts; a Qdrant blip is logged, not retried, and never surfaces
to the caller.

Purpose: The get-path counter bump must be fire-and-forget so `get_memory`
latency and success are never coupled to the counter write (D-04). Isolating the
engine in its own file with an injected `fill func` makes it Qdrant-free and
time.Sleep-free to test.
Output: `internal/server/usagequeue.go` + deterministic shutdown-safety tests.
</objective>
