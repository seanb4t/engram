## Trust Boundaries

| Boundary | Description | Data Crossing |
|----------|-------------|---------------|
| client → MCP/Connect handler → store | Untrusted caller triggers a counter bump only after passing the existing `GetReadable` ownership gate; `access_count`/`last_accessed_at` are server-set below this boundary, never client-supplied. | record id, server-set counters |
| get_memory / Connect GetMemory handler → usageQueue (async) | Fire-and-forget hand-off; enqueue outcome never propagates to the caller. | point id |
| usageQueue worker → store (`IncrementAccess`) | Best-effort partial-payload write (SetPayload RMW, last-writer-wins); failures are counted, never retried. | `access_count`, `last_accessed_at` |
| store → Qdrant | Payload counter write; no new index on `access_count`. | uint64 counter, RFC3339 timestamp |
| store → OTLP exporter → ClickStack | Result-set record ids ride recall spans (owner/scope-filtered before Search/List); usage-queue counters are content-free scalars. | opaque UUIDs (span attr), scalar counters |
| operator env → config loader | `ENGRAM_USAGE_SIGNALS` is operator-set; parseability validated at startup (fail-loud). | bool string |
| build/codegen → committed `gen/` tree | Codegen output is a checked-in build artifact; CI's `git diff --exit-code -- gen/` verifies it matches the schema. | generated Go/TS |
| store/Connect read → response serialization | The two new fields are serialized only for records the caller already proved readable. | `access_count`, `last_accessed_at` |

## Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation | Status |
|-----------|----------|-----------|----------|-------------|------------|--------|
| T-12-01 | Tampering | tool args (`storeArgs`/`updateArgs`/`idArgs`) + `Memory.AccessCount`/`LastAccessedAt` | high | mitigate | No client arg struct exposes `access_count`/`last_accessed_at`; both server-set. Grep-verified: neither field appears in any arg struct. | closed |
| T-12-02 | Information Disclosure | `access_count`/`last_accessed_at` on `recallView` + `memoryToProto` | high | mitigate | Both fields ride the EXISTING per-actor read gates (`GetReadable`, List owner/scope filter); serialized only on already-gated records; neither field is indexed/filterable. | closed |
| T-12-03 | Denial of Service | get-path write amplification / unbounded goroutine spawn | high | mitigate | Get-path bump is async best-effort via the bounded `usageQueue` (fixed worker pool + queue size, non-blocking drop-on-full → `Dropped` counter); `ENGRAM_USAGE_SIGNALS=false` disables the read-path write entirely (D-09). | closed |
| T-12-04 | Denial of Service (crash) | send-on-closed-channel at shutdown | high | mitigate | CR-01 kernel: RWMutex `closed` guard + `inFlight` reserve-before-send; a late enqueue drops instead of panicking. Proven by the shutdown-after-close test. | closed |
| T-12-05 | Tampering (integrity) | ranking isolation — `rerank.go` / recall-span path | high | mitigate | `rerank.go` has zero `access_count` references (grep-verified); `TestRerankHitsIgnoresAccessCount` (D-08) + D-02 negative-space test; recall-span path is analytics-only inside the span defer with no store mutation. | closed |
| T-12-06 | Information Disclosure | `IncrementAccess` | medium | mitigate | Reads/writes only an id the handler-boundary caller already proved readable; runs no ownership gate itself (grep-verified — no `GetReadable`/`getWritable` inside), so it cannot be tricked into cross-actor access. | closed |
| T-12-07 | Denial of Service | misconfigured `ENGRAM_USAGE_SIGNALS` | low | mitigate | `Config.Validate()` unconditional `strconv.ParseBool` fails loud + early on an unparseable value (mirrors `OnWrite`); no silent fallback. | closed |
| T-12-08 | Information Disclosure | usage-queue OTLP counters | low | accept | Counters are scalar increments (enqueued/dropped/failed) carrying no record content or owner; no disclosure surface. | closed |
| T-12-09 | Tampering | stale / hand-edited `gen/` tree | medium | mitigate | `gen/` is regenerated by `task proto:gen`, never hand-edited; CI's `git diff --exit-code -- gen/` drift-check blocks a stale commit (verified clean). | closed |
| T-12-10 | Repudiation | wire-schema change without regen | low | mitigate | The 12-03 verify step reproduces CI's drift-check locally so a missed regen fails before merge. | closed |
| T-12-11 | Denial of Service | `engram.recall.ids` attribute cardinality | high | mitigate | `recallIDs` caps the slice at `recallIDCap = 50` (grep-verified); a huge-k recall cannot blow up span-attribute size unboundedly. `TestStoreListRecallIDsCappedAtLimit`. | closed |
| T-12-12 | Information Disclosure | recall ids on spans | low | accept | Ids are the same opaque UUIDs the caller already received in the result set; the span is emitted only for the caller's own owner/scope-filtered recall. No cross-actor leak. | closed |
| T-12-13 | Denial of Service | worker wedged by a panicking / slow fill | medium | mitigate | `recover()` in the worker `process` loop + ctx-bounded `Shutdown`; `Wait()` returns despite a panic (usagequeue tests). | closed |
| T-12-14 | Repudiation | counting on a denied / `ErrNotFound` get | medium | mitigate | `tryEnqueue` fires only on the `err == nil` success branch (`tools.go:959`, `connectapi.go:204`); the denied-get test proves no increment on failure (D-01). | closed |
| T-12-SC | Tampering (supply chain) | package installs | low | accept | No new external packages (Go-only; otel/koanf/buf already vendored; the plan deliberately drops the backoff import). | closed |
