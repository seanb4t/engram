**The coverage gate was RED-proved, not merely observed passing.** Removing
`REQ-migrate-revert` from the summary set made the gate name exactly that requirement;
the unmodified control is empty. The empty result is therefore evidence.

Two extraction traps were hit and fixed before the set was trusted:

- `gsd-tools query summary-extract --pick` concatenates list values with **no
  separator**, so `REQ-[A-Za-z0-9_-]+` matched `REQ-aREQ-b` as a single token
  (18 apparent REQ-IDs instead of 27). The uppercase `REQ` prefix sits inside the
  character class, so the regex never sees a boundary. Narrowing the body class to
  `[a-z0-9-]` restores the split.
- Parsing REQ-IDs from the whole of REQUIREMENTS.md yields 30, surfacing three false
  "orphans" (`REQ-migration-resumability`, `REQ-version-dispatch-codec`,
  `REQ-consent-adversarial-proof`). These are **v2 / Out-of-Scope** entries at
  REQUIREMENTS.md:66–68, deliberately deferred and not milestone requirements. The
  orphan check is only meaningful when scoped to the v1 section.
